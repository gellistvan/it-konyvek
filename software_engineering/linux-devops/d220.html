44.5 Cloud API/identity diagnosztikai labor

44.5.1 Motiváció

A cloud API hibák első pillantásra hasonlítanak a C++ kivételekhez: kaptunk egy szöveget, egy hibakódot, és valamit javítani kell. A különbség az, hogy a cloud hibák mögött több, egymástól élesen eltérő réteg áll: a hitelesítés (authentication) kudarca, az engedélyezés (authorization) hiánya, a szolgáltatási kvóta (quota) kimerülése, vagy a rossz régió (region) megválasztása. A diagnosztikai labor célja, hogy ezt a négy okot API válaszokból, offline fixture-ökből és --dry-run hívásokból megbízhatóan elkülönítsük, még mielőtt egyetlen erőforrást is létrehoznánk. A korábbi Accountbaseline, audit, költség és cleanup fejezetben felépítettük a sandbox elszámolási és audit alapjait; most ezt a Működtetési szerződés, runbook és változtatás elvei szerint API-diagnosztikára használjuk.

44.5.2 Definíció és működés

A cloud API hívás legalább négy kérdést tesz fel:

  1. Authentication – ki vagy? A hívó identitását egy token vagy aláírt credential bizonyítja. Ha a token lejárt, hiányzik vagy érvénytelen, a hívás Unauthorized vagy ExpiredToken hibával tér vissza.
  2. Authorization – mit szabad? Az identitáshoz rendelt IAM-policy dönti el, hogy az adott művelet az adott erőforráson engedélyezett-e. Hiány esetén AccessDenied vagy Forbidden hibát kapunk.
  3. Quota – mennyi áll rendelkezésre? A szolgáltatási kvóta nem engedély, hanem erőforráslimit: hány futó instance, hány vCPU, hány API hívás másodpercenként. Túllépéskor QuotaExceeded, LimitExceeded vagy HTTP 429 válasz érkezik.
  4. Region – hol keresed? A legtöbb erőforrás regionális. Ha a hívás a eu-west-1 régióban keresi az us-east-1-ben létrehozott erőforrást, NotFound vagy InvalidParameterValue hibát kapunk – ez nem azt jelenti, hogy az erőforrás nem létezik.

A labor két üzemmódot használ: offline fixture esetén helyi JSON-fájl reprezentálja a várt API-válaszokat, így fizetős erőforrás nélkül gyakorolhatjuk az osztályozást; dedikált sandbox esetén pedig valós, de izolált CLI-hívásokat végzünk. A példákban lab-sandbox profilt és 111122223333 dummy account ID-t használunk; ezek nem valós credentials-ök.

44.5.3 Kidolgozott példa

A következő példa offline fixture-t és valós sandbox parancsokat kombinál. Feltételezzük, hogy a d219-ben beállított költségriasztás már működik.

Előkészítés: laborprofil és környezet

A parancs egy helyi környezeti fájlt hoz létre; nem módosít cloud erőforrást.

mkdir -p ~/lab-d220/fixtures
cat > ~/lab-d220/profile.env <<'EOF'
# Target: saját sandbox account, régió: eu-west-1
# Privilege: nincs szükség cloud jogra, helyi fájl
# Előfeltétel: d219 sandbox account létrehozva
# Ellenőrzés: tartalom megjelenik a cat paranccsal
# Rollback: a fájl törlésével
export AWS_PROFILE=lab-sandbox
export AWS_REGION=eu-west-1
export LAB_ACCOUNT_ID=111122223333
export LAB_COST_LIMIT_HYPOTHETICAL_USD=10.00
EOF
source ~/lab-d220/profile.env

Caller identity és régióellenőrzés

Első lépés mindig a hívó identitás és az aktuális régió azonosítása. A sts get-caller-identity olvasó hívás, nem módosít.

# Target: lab-sandbox account, UID: saját user
# Privilege: STS:GetCallerIdentity (alapjog)
# Előfeltétel: érvényes sandbox credential
# Ellenőrzés: a kimenetben a várt account ID
# Rollback: nem szükséges
aws sts get-caller-identity --profile lab-sandbox --region eu-west-1

Várt, illusztratív kimenet (dummy érték):

{
    "Account": "111122223333",
    "Arn": "arn:aws:iam::111122223333:user/lab-d220",
    "UserId": "AIDASAMPLELABD220"
}

A régióinventáriumot a describe-regions adja:

aws ec2 describe-regions --region eu-west-1 \
  --query 'Regions[0:3].{Name:RegionName,Endpoint:Endpoint}' --output table

Hibaosztályozó offline fixture

Hozzunk létre négy jellegzetes hibamintát a fixtures/api_errors.json fájlban. A hibakódok az EC2 API kódjai (a pontos lista a hivatalos EC2 error code oldalon ellenőrizendő); a HTTP-státuszt szándékosan nem rögzítjük, mert az AWS API-k az authn- és authz-hibát is jellemzően 403-mal adják, a réteget a kód mutatja:

cat > ~/lab-d220/fixtures/api_errors.json <<'EOF'
[
  {"case": "expired_token", "code": "ExpiredToken"},
  {"case": "denied_permission", "code": "UnauthorizedOperation"},
  {"case": "quota_exceeded", "code": "VcpuLimitExceeded"},
  {"case": "wrong_region", "code": "InvalidAMIID.NotFound"}
]
EOF

Az alábbi Python fixture-olvasó osztályozza a hibákat; ez a laborban magyarázó eszközként szolgál, és nem igényel cloud hívást. A fixture útvonalát a script saját helyéhez képest számolja, így bármely munkakönyvtárból futtatható.

cat > ~/lab-d220/classify_errors.py <<'EOF'
#!/usr/bin/env python3
"""Offline fixture: API hibaminták osztályozása."""
import json
from pathlib import Path

FIXTURE = Path(__file__).resolve().parent / "fixtures" / "api_errors.json"

CLASSES = {
    "ExpiredToken": "authentication",
    "UnauthorizedOperation": "authorization",
    "VcpuLimitExceeded": "quota",
    "InvalidAMIID.NotFound": "region",
}

with FIXTURE.open(encoding="utf-8") as f:
    for item in json.load(f):
        kind = CLASSES.get(item["code"], "unknown")
        print(f"{item['case']:20s} -> {kind}")
EOF
cd /tmp && python3 ~/lab-d220/classify_errors.py

Várt kimenet:

expired_token        -> authentication
denied_permission    -> authorization
quota_exceeded       -> quota
wrong_region         -> region

Quota smoke test

A következő hívás lekérdezi a futó on-demand instance kvótát. A quota kód és a név a provider aktuális API-jától függ; az itt használt név illusztratív, ezért a műveletet a sandboxban az aktuális lista alapján kell ellenőrizni. A parancs olvasó, nem módosít.

Q='Quotas[?contains(QuotaName, `Running On-Demand`)]'
Q+='.{Name:QuotaName,Value:Value,Code:QuotaCode}'
aws service-quotas list-service-quotas --service-code ec2 --region eu-west-1 \
  --query "$Q" --output table

Várt kimenet dummy értékkel:

----------------------------------------------------------------
|                    ListServiceQuotas                        |
+----------------------+---------------+----------------------+
|        Name          |    Value      |      Code            |
+----------------------+---------------+----------------------+
| Running On-Demand    |  5.0          |  L-DUMMY1234         |
| Standard instances   |               |                      |
+----------------------+---------------+----------------------+

Image és instance smoke test dry-runnal

A --dry-run dokumentált célja annak ellenőrzése, hogy a hívónak megvan-e a jogosultsága a műveletre; a paraméterek alapvető érvényessége (például a régióban létező kép azonosítója) is hibát adhat, de kvótát és kapacitást nem foglal és nem ellenőriz. Az AMI ID itt dummy; a tényleges labban a régióban elérhető, támogatott Ubuntu 24.04 AMI-t kell lekérdezni.

aws ec2 run-instances --dry-run --region eu-west-1 \
  --image-id ami-0dummy1234567890ab \
  --instance-type t3.micro \
  --subnet-id subnet-0dummy1234567890ab \
  --profile lab-sandbox

Ha az IAM-engedély és a hivatkozott erőforrások érvényesek, a várt hibaüzenet maga a dry-run megerősítése:

An error occurred (DryRunOperation) when calling the RunInstances operation:
Request would have succeeded, but DryRun flag is set.

Ez a hiba itt siker, mert azt jelenti, hogy a permission meglenne. Jogosultsághiánynál az EC2 UnauthorizedOperation hibát ad. A kvóta és a kapacitás csak valódi indításkor derül ki (VcpuLimitExceeded, illetve InsufficientInstanceCapacity); előre csak a fenti service-quotas lekérdezéssel becsülhető.

Audit trail és cleanup manifest

A hívások utáni auditnyomot a CloudTrail adja. A lookup-events olvasó hívás, és a 90 napos management-event historyt (Event history) trail nélkül is eléri; a d219-es trail a hosszú távú, S3-ba kézbesített naplóhoz kell. Az események listaelemeiben nincs hibamező: a hibakód (errorCode) a CloudTrailEvent JSON-sztringben van, ezért azt jq-val bontjuk ki:

aws cloudtrail lookup-events --region eu-west-1 \
  --lookup-attributes AttributeKey=Username,AttributeValue=lab-d220 \
  --max-results 3 \
  --query 'Events[].CloudTrailEvent' --output json \
  | jq -r '.[] | fromjson
      | [.eventTime, .eventName, (.errorCode // "OK")] | @tsv'

A cleanup manifest rögzíti az owner, az expiry, a cost limit és a ténylegesen létrehozott erőforrásokat. Mivel a laborban eddig csak dry-run volt, a lista üres.

# ~/lab-d220/cleanup-manifest.yaml
owner: lab-d220
account: "111122223333"
region: eu-west-1
cost_limit_hypothetical_usd: 10.00
expiry: "2025-12-31T23:59:59Z"
resources: []
cleanup_commands: []

44.5.4 Hibák és ellenpróbák

Jelenség Hipotézis Ellenőrzés Javítás
ExpiredToken, InvalidClientTokenId, AuthFailure A credential hiányzik, lejárt vagy rossz profilban van aws sts get-caller-identity Friss credentialt kérni, --profile ellenőrzése
UnauthorizedOperation (EC2), AccessDenied (más szolgáltatások) IAM policy hiányos a hívott műveletre aws iam simulate-principal-policy vagy dry-run hívás Minimális policy attach, nem admin jog
VcpuLimitExceeded A vCPU-kvóta elérte a felső határt (csak valódi indításkor jön) service-quotas list-service-quotas Kvótaemelés kérése, más régió vagy kisebb instance
RequestLimitExceeded API-throttling, nem kvóta a hívási gyakoriság a CloudTrailben Exponenciális backoff, kevesebb párhuzamos hívás
InvalidAMIID.NotFound A kép nem létezik ebben a régióban describe-images --owners a régióban A régióhoz tartozó AMI ID használata

A táblázat a hibakódokat adja meg, nem a HTTP-státuszt: az AWS API-k az authn- és az authz-hibát is jellemzően 403-mal jelzik; a kódok pontos listája a hivatalos EC2 error code oldalon ellenőrizendő. Gyakori csapda, hogy a jogosultsági hibát (UnauthorizedOperation/AccessDenied) credential-problémaként kezelik, pedig a token érvényes, csak a policy hiányzik. A másik félreértés, hogy a dry-run sikerét tényleges indításként értelmezik; a dry-run nem foglal kapacitást és nem ellenőrzi a kvótát, így később egy valódi VcpuLimitExceeded vagy InsufficientInstanceCapacity hiba még előfordulhat.

44.5.5 Feladatok

  1. Magyarázó feladat: Készítsen egy táblázatot, amely a következő hibakódokat osztályozza a négy kategóriába: InvalidClientTokenId, UnauthorizedOperation, VcpuLimitExceeded, InvalidAMIID.NotFound, ExpiredToken, RequestLimitExceeded. Mindegyikhez írjon egy mondatos indoklást, amely megkülönbözteti az authentikációt, engedélyt, kvótát és régiót.

  2. Adminisztrációs/konfigurációs feladat: Hozzon létre egy bővített offline fixture-t fixtures/api_errors.json néven legalább öt hibamintával, és írjon hozzá egy saját Python vagy bash osztályozót. A kimenet minden esethez a kategóriát adja meg. A postcondition: a script hiba nélkül fut, és a kategóriák helyesek.

  3. Diagnosztikai/failure/recovery feladat: Válasszon egy jogosultsági hibát a sandboxban: hajtsa végre a run-instances --dry-run hívást egy olyan sandbox userrel, akinek nincs ec2:RunInstances engedélye. Rögzítse a hibát (EC2-ben UnauthorizedOperation). Ezután csatolja hozzá a minimális policy-t, majd ismételje meg a dry-run hívást. A postcondition: a második hívás DryRunOperation hibát ad, nem UnauthorizedOperation. Ha nincs sandbox, szimulálja a folyamatot az offline fixture-ökben.

44.5.6 Megoldások

  1. Megoldás a magyarázó feladathoz: A táblázat:
Hibakód Kategória Indoklás
InvalidClientTokenId authentication A hívó access key azonosítója ismeretlen vagy érvénytelen
UnauthorizedOperation authorization A policy nem engedélyezi a műveletet (EC2)
VcpuLimitExceeded quota A vCPU-kvóta túllépve, nem engedélykérdés
InvalidAMIID.NotFound region A kép nem létezik az adott régióban
ExpiredToken authentication A token lejárt, meg kell újítani
RequestLimitExceeded quota API rate limit (throttling): a hívási gyakoriság korlátja, nem erőforráskvóta

  1. Megoldás az adminisztrációs feladathoz: A bővített JSON és a Python osztályozó a kidolgozott példa mintájára készül. A postcondition az, hogy a script minden mintát a várt kategóriába sorol, és nem hagy üresen unknown értéket. A script futtatása: python3 ~/lab-d220/classify_errors.py. A várt kimenet minden sorban case -> category.

  2. Megoldás a diagnosztikai feladathoz: A folyamat:

    • Hozza létre vagy válassza ki a lab-d220-deny user-t, akihez nem csatolt ec2:RunInstances engedély.
    • Futtassa a run-instances --dry-run hívást; várható UnauthorizedOperation hiba.
    • Csatoljon egy minimális inline policy-t, amely csak a labor saját AMI-jából, saját subnetjébe, t3.micro típussal engedi az ec2:RunInstances-t (lásd lent). Resource: "*" nem kell, és a ec2:DescribeImages sem szükséges a dry-runhoz. A módosító parancs target a sandbox IAM, privilege iam:PutUserPolicy, előfeltétel a deny user létezése, ellenőrzés a csatolás utáni dry-run, rollback a policy törlése.
    • Ismételje meg a dry-run hívást. A postcondition: DryRunOperation hiba, ami azt jelzi, hogy az engedély megvan, és a paraméterek érvényesek.

A labor egy hosszú életű IAM usert használ, mert a feladat egy konkrét principal jogosultsághiányát demonstrálja; a 44.2 szerint éles környezetben role/SSO a helyes út. A policy (lab-d220-run-dryrun.json; a pontos erőforrás-ARN-készlet a hivatalos EC2 Service Authorization Reference-ből ellenőrizendő):

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "ec2:RunInstances",
      "Resource": [
        "arn:aws:ec2:eu-west-1:111122223333:instance/*",
        "arn:aws:ec2:eu-west-1:111122223333:network-interface/*",
        "arn:aws:ec2:eu-west-1:111122223333:volume/*",
        "arn:aws:ec2:eu-west-1:111122223333:security-group/*",
        "arn:aws:ec2:eu-west-1:111122223333:subnet/subnet-0dummy1234567890ab",
        "arn:aws:ec2:eu-west-1::image/ami-0dummy1234567890ab"
      ],
      "Condition": {
        "StringEqualsIfExists": {"ec2:InstanceType": "t3.micro"}
      }
    }
  ]
}

Csatolás és rollback:

# target: sandbox IAM (account 111122223333), privilege: iam:PutUserPolicy
aws iam put-user-policy --profile lab-sandbox \
  --user-name lab-d220-deny \
  --policy-name lab-d220-run-dryrun \
  --policy-document file://lab-d220-run-dryrun.json
# rollback:
aws iam delete-user-policy --profile lab-sandbox \
  --user-name lab-d220-deny \
  --policy-name lab-d220-run-dryrun

A StringEqualsIfExists azért kell, mert az ec2:InstanceType kulcs csak az instance/* erőforrásnál létezik; sima StringEquals mellett a többi erőforrás-ARN-re a feltétel nem teljesülne.

44.5.7 Rövid összefoglaló

A cloud API-diagnosztika alapja a hibakódok rétegek szerinti elkülönítése: authentication, authorization, quota és region. A sts get-caller-identity mindig az első hívás, a --dry-run futtatás pedig erőforrás nélkül teszteli a permissiont és a paramétereket. Az offline fixture-ök lehetővé teszik a hibaminták gyakorlását fizetős erőforrás nélkül. A cleanup manifest rögzíti az owner, expiry és cost limit szerződést.

Továbbhasznált definíciók: authentication – az identitás bizonyítása; authorization – az identitásra vonatkozó engedélyek ellenőrzése; service quota – egy cloud szolgáltatás erőforrás- vagy API-limite.

44.5.8 Források és ellenőrzési hiányok

Állításonként (hivatkozott verzió: AWS CLI v2, a labor generálásakor aktuális dokumentáció; a CLI verzióját aws --version kimenettel kell rögzíteni):

  • sts get-caller-identity (a UserId formátuma), ec2 run-instances --dry-run, service-quotas list-service-quotas, cloudtrail lookup-events: az AWS CLI v2 Command Reference (https://awscli.amazonaws.com/v2/documentation/api/latest/index.html).
  • EC2 hibakódok (DryRunOperation, UnauthorizedOperation, VcpuLimitExceeded, InsufficientInstanceCapacity, RequestLimitExceeded, InvalidAMIID.NotFound): az Amazon EC2 API Reference „Error codes for the Amazon EC2 API” oldala a AWS Documentation alatt.
  • CloudTrail Event history (90 nap, trail nélkül) és a CloudTrailEvent mezői: AWS CloudTrail User Guide – „Working with CloudTrail Event history” és „CloudTrail record contents”.
  • ec2:RunInstances erőforrás-típusai és condition kulcsai: a Service Authorization Reference „Actions, resources, and condition keys for Amazon EC2” oldala; IAM user inline policy: AWS IAM User Guide.
  • GCP/Azure megfelelők: Google Cloud Docs – „Troubleshoot IAM”; Microsoft Azure Documentation – „Azure Resource Manager error codes”.

Ellenőrzési státusz: az offline fixture-osztályozó a fenti fixture-rel helyben ellenőrizhető; a sandbox-ág (dry-run siker és UnauthorizedOperation) laborban ellenőrizendő, dátumozott futtatási napló még nem készült.

Ellenőrzési hiányok: a fenti URL-ek nem ellenőrzött, aktuális verziójú források; a parancsok nem futtatottak, a várt kimenetek illusztratívak. A konkrét AMI ID, quota kód, hibakód és hipotetikus költség a provider aktuális dokumentációja és a sandbox tényleges állapota alapján ellenőrizendő. A CloudTrail, service-quotas és IAM simulate hívások pontos kimenete a generáláskor nem verifikált.
