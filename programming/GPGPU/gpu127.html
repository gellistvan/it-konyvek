33.2 Kernelimplementáció

Az előző alfejezetben (33.1) rögzített záróprojekt-követelményeket a kernelimplementáció szintjére fordítjuk le: ahelyett, hogy egyetlen monolitikus kernelt írnánk, a feladatot egy fő kernelre és több, jól körülhatárolt segédkernelre bontjuk. Az alábbiakban egy 2D hővezetési egyenletet megoldó explicit Euler-rendszert használunk példaként (a 33.1 charter Jacobi-stencilje ennek a speciális esete: αΔt/Δx2=1/4\alpha\Delta t/\Delta x^2 = 1/4), amely a korábbi fejezetekben már bevezetett stencil- és tilingfogalmakra épít, de nem ismétli meg azokat. A hangsúly a kernelimplementáció szerkezetén, a memória- és szinkronizációs döntéseken, valamint a hibakezelésen van.

33.2.1 A fő kernel és a segédkernelek szerepe

Egy GPGPU-alkalmazás ritkán áll egyetlen kernelből. A záróprojektben a következő logikai feladatokat érdemes elkülöníteni:

  • Fő kernel: a számítási mag, amely a legtöbb időt fogyasztja. Itt ez az időlépés-stencil, amely a hőmérsékletmezőt a következő időszintre lépteti.
  • Segédkernelek: inicializálás, peremfeltétel-beállítás, hibaszámítás és kiértékelés. Ezek futásideje gyakran elhanyagolható, de a helyes működéshez nélkülözhetetlenek.

A szétválasztás előnye, hogy a segédkernelek egyszerű, könnyen ellenőrizhető egységek, míg a fő kernel optimalizálását önállóan, a teljes rendszer újrafordítása nélkül végezhetjük. A következő alfejezetben (33.3) a fő kernel teljesítményét fogjuk tovább javítani, ezért itt a hangsúly a helyes, mérhető alapimplementáción van.

33.2.2 A példa: 2D hővezetési egyenlet

A 33.1 követelményei alapján a feladat a

∂u∂t=α(∂2u∂x2+∂2u∂y2) \frac{\partial u}{\partial t} = \alpha \left( \frac{\partial^2 u}{\partial x^2} + \frac{\partial^2 u}{\partial y^2} \right)

megoldása Dirichlet-peremfeltétellel. Az explicit Euler-diszkretizáció egyenlete:

ui,jn+1=ui,jn+αΔt(ui−1,jn−2ui,jn+ui+1,jnΔx2+ui,j−1n−2ui,jn+ui,j+1nΔy2) u^{n+1}_{i,j} = u^n_{i,j} + \alpha \Delta t \left( \frac{u^n_{i-1,j} - 2u^n_{i,j} + u^n_{i+1,j}}{\Delta x^2} + \frac{u^n_{i,j-1} - 2u^n_{i,j} + u^n_{i,j+1}}{\Delta y^2} \right)

ahol i=1,…,nx−2i=1,\dots,n_x-2, j=1,…,ny−2j=1,\dots,n_y-2, a perempontok pedig rögzítettek. A stabilitási feltétel 2D-ben αΔt≤14min⁡(Δx2,Δy2)\alpha \Delta t \leq \frac{1}{4} \min(\Delta x^2, \Delta y^2). A laborban ezt a feltételt szigorúan teljesítő paramétereket használunk (Δt=0,2\Delta t = 0{,}2); a charter Jacobi-esete Δt=0,25\Delta t = 0{,}25-nek felel meg, ami a stabilitás határán van.

33.2.3 A fő kernel implementációja: naiv verzió

A naiv kernel egyetlen szálat rendel minden belső rácsponthoz, és minden iterációban a globális memóriából olvassa a szomszédos értékeket. Ez a legegyszerűbb implementáció, és remek kiindulópont a helyesség ellenőrzéséhez.

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
// Blokk: 16x16, grid: ceil(nx/16) x ceil(ny/16) (az i, j indexek 0-tól indulnak)
__global__ void heat_step_naive(const float* __restrict__ u_old,
                                float* __restrict__ u_new,
                                int nx, int ny,
                                float alpha, float dt,
                                float dx, float dy) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;

    // Csak belső pontokat számolunk, a peremeket a segédkernel kezeli.
    if (i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        float u_center = u_old[j * nx + i];
        float u_left   = u_old[j * nx + (i - 1)];
        float u_right  = u_old[j * nx + (i + 1)];
        float u_down   = u_old[(j - 1) * nx + i];
        float u_up     = u_old[(j + 1) * nx + i];

        float d2x = (u_left - 2.0f * u_center + u_right) / (dx * dx);
        float d2y = (u_down - 2.0f * u_center + u_up) / (dy * dy);

        u_new[j * nx + i] = u_center + alpha * dt * (d2x + d2y);
    }
}

A naiv kernel minden időlépésben öt globális memóriaolvasást és egy írást végez belső pontonként. A hozzáférés koaleszkált: a gyors index i a threadIdx.x, így egy warp szálai szomszédos címeket olvasnak (a felső és alsó szomszéd is egy-egy összefüggő sor). A kernel azonban minden értéket logikailag ötször olvas; az ismételt olvasásokat az L1/L2 gyorsítótár nagyrészt elnyeli, így a DRAM-forgalom a naiv kernelnél is közelebb van a pontonkénti 8 bájthoz, mint a logikai 24 bájthoz (ezt ncu-val kell megmérni). A teljesítményt a 33.3 alfejezetben részletesen elemezzük; itt a kernel a helyesség referenciájaként szolgál.

33.2.4 A fő kernel implementációja: tiled verzió

A naiv kernel gyorsítótár- és load/store-terhelésének csökkentésére a shared memory tiling technikát alkalmazzuk (a DRAM-forgalom csökkenése nem automatikus, mert az L1/L2 már a naiv változatban is újrahasznosít). A blokk egy 16×1616\times16 belső pontból álló csempét számol, de a stencilhez szükséges halo (szegély) elemekkel együtt egy 18×1818\times18 méretű shared memory tömböt töltünk fel. A halo elemeket a szomszédos csempékből vagy a peremfeltételekből olvassuk be egyszer, így minden belső pont számításakor a szomszédok már a shared memoryban vannak.

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
// Blokk: 16x16, grid: ceil(nx/16) x ceil(ny/16)
constexpr int TILE_X = 16;
constexpr int TILE_Y = 16;

__global__ void heat_step_tiled(const float* __restrict__ u_old,
                                float* __restrict__ u_new,
                                int nx, int ny,
                                float alpha, float dt,
                                float dx, float dy) {
    // Shared memory csempe: blokkpontok + 1 halo mindkét irányban
    __shared__ float tile[TILE_Y + 2][TILE_X + 2];

    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;
    int tx = threadIdx.x;
    int ty = threadIdx.y;

    // A betöltés a TELJES rácsra (a peremre is) vonatkozik: i < nx, j < ny.
    // A perempontok (i=0, i=nx-1, j=0, j=ny-1) a belső pontok szomszédai.
    bool in_grid = (i < nx && j < ny);

    if (in_grid) {
        tile[ty + 1][tx + 1] = u_old[j * nx + i];
    }
    // Bal halo: a blokk bal szomszédja létezik, ha i > 0
    if (tx == 0 && i > 0 && j < ny) {
        tile[ty + 1][0] = u_old[j * nx + (i - 1)];
    }
    // Jobb halo: a jobb szomszéd létezik, ha i + 1 < nx
    if (tx == TILE_X - 1 && i + 1 < nx && j < ny) {
        tile[ty + 1][TILE_X + 1] = u_old[j * nx + (i + 1)];
    }
    // Alsó halo (j - 1)
    if (ty == 0 && j > 0 && i < nx) {
        tile[0][tx + 1] = u_old[(j - 1) * nx + i];
    }
    // Felső halo (j + 1)
    if (ty == TILE_Y - 1 && j + 1 < ny && i < nx) {
        tile[TILE_Y + 1][tx + 1] = u_old[(j + 1) * nx + i];
    }

    // Minden szál befejezte a betöltést, mielőtt bármelyik olvasná a csempét.
    // A __syncthreads()-t minden szál eléri (nincs szálfüggő elágazáson belül).
    __syncthreads();

    // Számítás csak a belső pontokra; a peremet az apply_boundary kernel kezeli
    if (i >= 1 && i < nx - 1 && j >= 1 && j < ny - 1) {
        float u_center = tile[ty + 1][tx + 1];
        float u_left   = tile[ty + 1][tx];
        float u_right  = tile[ty + 1][tx + 2];
        float u_down   = tile[ty][tx + 1];
        float u_up     = tile[ty + 2][tx + 1];

        float d2x = (u_left - 2.0f * u_center + u_right) / (dx * dx);
        float d2y = (u_down - 2.0f * u_center + u_up) / (dy * dy);

        u_new[j * nx + i] = u_center + alpha * dt * (d2x + d2y);
    }
}

Fontos különbség a kézenfekvő, de hibás változathoz képest: ha a betöltést is a belső-pont feltételhez (i >= 1 && i < nx-1 && ...) kötnénk, a perempontok szálai nem töltenének be semmit, és a peremmel szomszédos belső pontok inicializálatlan shared memóriát olvasnának (hibás, nemdeterminisztikus értékek a perem mentén). A betöltés ezért a teljes rácsra (i < nx && j < ny) vonatkozik, a számítás pedig csak a belső pontokra. Ellenőrzés: a tiled eredményt a naiv kernel eredményével kell összevetni (a két kernel azonos műveleti sorrendű, ezért az eltérés várhatóan 0), és a compute-sanitizer --tool initcheck futtatását is érdemes rögzíteni; ezeket a könyv nem futtatta.

A shared memory tömb mérete 18×1818\times18 elem, FP32 esetén 18⋅18⋅4=129618\cdot18\cdot4 = 1296 bájt, ami messze a limit alatt van. A __syncthreads() kulcsfontosságú: biztosítja, hogy a csempe minden eleme látható legyen a blokk minden szála számára, mielőtt a számítás elkezdődik. Enélkül versenyhelyzet alakulna ki: egyes szálak olvashatnák a még be nem töltött csempeelemeket.

33.2.5 Segédkernelek implementációja

33.2.6 Inicializálás

Az inicializáló kernel egy kezdeti hőmérsékleti eloszlást állít elő. A példában egy Gauss-csomagot helyezünk a tartomány közepére. A szélesség a tartományhoz igazodik: σ=0,05nxΔx\sigma = 0{,}05\, n_x \Delta x (4096 × 4096 rácson σ=204,8\sigma = 204{,}8 rácstávolság), így a csomag sok rácsponton át simán változik, és a perem környékén exp⁡(−50)≈2⋅10−22\exp(-50)\approx 2\cdot 10^{-22}, azaz gyakorlatilag 0, összhangban a nulla Dirichlet-peremmel. (Egy σ=0,1\sigma = 0{,}1 rácstávolságú csomag a rácson Dirac-deltává fajulna, és az L2L^2-teszt nem lenne informatív.) A csomag középpontja pontosan egy rácspontra esik.

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
// Blokk: 16x16, grid: ceil(nx/16) x ceil(ny/16)
// sigma: a Gauss-szélesség hosszegységben (a tartomány arányában, pl. 0,05 * nx * dx)
__global__ void init_field(float* __restrict__ u,
                           int nx, int ny,
                           float dx, float dy, float sigma) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    int j = blockIdx.y * blockDim.y + threadIdx.y;
    if (i < nx && j < ny) {
        float x = i * dx;
        float y = j * dy;
        float cx = nx * dx * 0.5f;
        float cy = ny * dy * 0.5f;
        float r2 = (x - cx) * (x - cx) + (y - cy) * (y - cy);
        u[j * nx + i] = expf(-r2 / (2.0f * sigma * sigma));
    }
}

33.2.7 Peremfeltétel

A Dirichlet-peremfeltétel rögzített értéket ír a mező széleire. A kernel az alsó/felső sort és a bal/jobb oszlopot kezeli.

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
// Blokk: 256 szál, grid: ceil(max(nx,ny)/256)
__global__ void apply_boundary(float* __restrict__ u,
                               int nx, int ny,
                               float bc_value) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < nx) {
        u[idx] = bc_value;                  // alsó sor (j=0)
        u[(ny - 1) * nx + idx] = bc_value;  // felső sor (j=ny-1)
    }
    if (idx < ny) {
        u[idx * nx] = bc_value;             // bal oszlop (i=0)
        u[idx * nx + nx - 1] = bc_value;    // jobb oszlop (i=nx-1)
    }
}

A sarokpontokat több szál is írja ugyanabban a kernelben, de ugyanazzal az értékkel, ezért az eredmény determinisztikus és ártalmatlan (azonos értékű párhuzamos írás), függetlenül a streamek számától.

33.2.8 Hibaszámítás

A validációhoz szükség van a numerikus megoldás és egy referencia közötti eltérés normájára. A redukciót shared memoryban végezzük blokkszinten, majd a parciális összegeket a host számolja össze. Ez a segédkernel is a fő kernel helyességét ellenőrzi.

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
// Blokk: 256 szál, grid: ceil(n/256), dinamikus shared memory: 256 * sizeof(float)
__global__ void compute_l2_diff(const float* __restrict__ u,
                                const float* __restrict__ u_ref,
                                int n,
                                float* __restrict__ partial) {
    extern __shared__ float sdata[];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;

    float diff = 0.0f;
    if (idx < n) {
        float d = u[idx] - u_ref[idx];
        diff = d * d;
    }

    sdata[tid] = diff;
    __syncthreads();

    for (unsigned int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            sdata[tid] += sdata[tid + s];
        }
        __syncthreads();
    }

    if (tid == 0) {
        partial[blockIdx.x] = sdata[0];
    }
}

A host oldalon a parciális összegeket összeadjuk és gyököt vonunk, így megkapjuk a két mező közötti L2L^2-hibát.

33.2.9 Memória és szinkronizáció a kernelben

A fő kernel implementációjának központi kérdése a memóriaterek helyes megválasztása és a szinkronizáció.

  • Global memory: a hőmérsékletmezők (u_old, u_new) nagy méretűek, ezért csak global memoryban tárolhatók. A naiv kernel minden pontnál öt globális olvasást és egy írást végez, ami nagy memóriaforgalmat generál.
  • Shared memory: a tiled kernel a csempéhez szükséges pontokat egyszer tölti be shared memoryba, majd a számítás során onnan olvassa őket. A shared memory sávszélessége nagyságrendekkel nagyobb, mint a global memoryé, ezért a memóriaforgalom csökken.
  • Regiszterek: a belső számítások során a skalár értékeket (u_center, u_left, stb.) a fordító regiszterekben tartja, ami a leggyorsabb memóriatér.
  • Szinkronizáció: a __syncthreads() blokkszintű barrier, amely garantálja, hogy a shared memoryba írt összes érték láthatóvá válik a blokk minden szála számára, mielőtt a számítás elkezdődik. A hiánya versenyhelyzetet okoz, ami nemdeterminisztikus eredményekhez vezethet.

Fontos megjegyezni, hogy a __syncthreads() csak a blokkon belüli szálakat szinkronizálja. A blokkok közötti szinkronizációt a kernelhatárok oldják meg: minden időlépés külön kernelindítás, így a következő időlépés csak akkor kezdődik, ha az előző befejeződött (stream-szintű sorosítás esetén). A grid-szintű szinkronizációra itt nincs szükség.

33.2.10 Hibakezelés a kernelimplementációban

A CUDA-alkalmazásokban a hibakezelés nem opcionális. A kernelindítás aszinkron, ezért a hibák gyakran csak a cudaDeviceSynchronize() vagy a következő API-hívás során derülnek ki. A laborban kötelezően használt hibamakró a következő:

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
#include <cstdio>
#include <cstdlib>
#include <cuda_runtime.h>

#define CUDA_CHECK(call) do {                                       \
    cudaError_t err = (call);                                       \
    if (err != cudaSuccess) {                                       \
        fprintf(stderr, "CUDA hiba: %s:%d: %s\n",                   \
                __FILE__, __LINE__, cudaGetErrorString(err));       \
        exit(EXIT_FAILURE);                                         \
    }                                                               \
} while (0)

// Kernel indítás után közvetlenül:
// CUDA_CHECK(cudaGetLastError());
// A szinkronizáció után:
// CUDA_CHECK(cudaDeviceSynchronize());

A cudaGetLastError() a kernelindítási hibákat (pl. érvénytelen launch konfiguráció, nem létező függvény) fogja el, míg a cudaDeviceSynchronize() a kernel végrehajtása közben fellépő aszinkron hibákat (pl. illegális memória-hozzáférés) jelenti. A hibamakró használata kötelező minden CUDA API-hívás körül.

A fejlesztés során a compute-sanitizer --tool memcheck a tartományon kívüli hozzáféréseket, a --tool racecheck a shared memory versenyhelyzeteit, a --tool initcheck az inicializálatlan olvasásokat tárja fel. A laborban ezeket is le kell futtatni (parancsok a Build és futtatási parancs szakaszban), és az eredményt a mérési naplóba kell rögzíteni.

33.2.11 Labor: naiv és optimalizált kernel

Az alábbi labor a 33.1 követelményein alapul, és a fenti kerneleket futtatja. A heat_impl.cu teljes forrása a fenti kernelek (heat_step_naive, heat_step_tiled, init_field, apply_boundary, compute_l2_diff) és a CUDA_CHECK makró, valamint az alábbi host program (main) egymás után fűzve. A kódot a könyv szerzői nem fordították és nem futtatták hardveren; a mérési napló mezői az olvasó saját mérésével töltendők ki.

// CUDA C++ (C++17), nvcc 12.x, Linux x86_64
// heat_impl.cu host része (a kernelek és a CUDA_CHECK után); nem fordított, nem futtatott
#include <algorithm>
#include <cmath>
#include <cstdio>
#include <cstdlib>
#include <cstring>
#include <vector>

// Egy futás: inicializálás + `steps` időlépés ping-pong pufferekkel; a lépések ideje ms-ban
static float run_steps(bool tiled, float* d_a, float* d_b, int nx, int ny,
                       int steps, float alpha, float dt, float dx, float dy,
                       float sigma, float** d_final) {
    dim3 blk(16, 16), grd((nx + 15) / 16, (ny + 15) / 16);
    int bt = 256, bb = (std::max(nx, ny) + bt - 1) / bt;
    for (float* p : {d_a, d_b}) {            // mindkét puffer peremét be kell állítani
        init_field<<<grd, blk>>>(p, nx, ny, dx, dy, sigma);
        apply_boundary<<<bb, bt>>>(p, nx, ny, 0.0f);
    }
    CUDA_CHECK(cudaGetLastError());
    cudaEvent_t t0, t1;
    CUDA_CHECK(cudaEventCreate(&t0));
    CUDA_CHECK(cudaEventCreate(&t1));
    CUDA_CHECK(cudaDeviceSynchronize());
    CUDA_CHECK(cudaEventRecord(t0));
    float *cur = d_a, *nxt = d_b;
    for (int s = 0; s < steps; ++s) {
        if (tiled)
            heat_step_tiled<<<grd, blk>>>(cur, nxt, nx, ny, alpha, dt, dx, dy);
        else
            heat_step_naive<<<grd, blk>>>(cur, nxt, nx, ny, alpha, dt, dx, dy);
        std::swap(cur, nxt);
    }
    CUDA_CHECK(cudaGetLastError());
    CUDA_CHECK(cudaEventRecord(t1));
    CUDA_CHECK(cudaEventSynchronize(t1));
    float ms = 0.0f;
    CUDA_CHECK(cudaEventElapsedTime(&ms, t0, t1));
    CUDA_CHECK(cudaEventDestroy(t0));
    CUDA_CHECK(cudaEventDestroy(t1));
    *d_final = cur;
    return ms;
}

// FP64 CPU-referencia (csak kis rácsra; --check)
static void cpu_reference(std::vector<double>& u, int nx, int ny, int steps,
                          double alpha, double dt, double dx, double dy,
                          double sigma) {
    std::vector<double> a((size_t)nx * ny), b;
    for (int j = 0; j < ny; ++j)
        for (int i = 0; i < nx; ++i) {
            double x = i * dx - nx * dx * 0.5, y = j * dy - ny * dy * 0.5;
            a[(size_t)j * nx + i] = std::exp(-(x * x + y * y) / (2.0 * sigma * sigma));
        }
    for (int i = 0; i < nx; ++i) { a[i] = 0.0; a[(size_t)(ny - 1) * nx + i] = 0.0; }
    for (int j = 0; j < ny; ++j) {
        a[(size_t)j * nx] = 0.0;
        a[(size_t)j * nx + nx - 1] = 0.0;
    }
    b = a;
    for (int s = 0; s < steps; ++s) {
        for (int j = 1; j < ny - 1; ++j)
            for (int i = 1; i < nx - 1; ++i) {
                size_t k = (size_t)j * nx + i;
                double d2x = (a[k - 1] - 2.0 * a[k] + a[k + 1]) / (dx * dx);
                double d2y = (a[k - nx] - 2.0 * a[k] + a[k + nx]) / (dy * dy);
                b[k] = a[k] + alpha * dt * (d2x + d2y);
            }
        std::swap(a, b);
    }
    u = a;
}

int main(int argc, char** argv) {
    int nx = 4096, ny = 4096, steps = 1000, warmup = 5, reps = 20;
    float dt = 0.2f;
    bool check = false;
    for (int a = 1; a < argc; ++a) {
        if (!std::strcmp(argv[a], "--nx") && a + 1 < argc) nx = std::atoi(argv[++a]);
        else if (!std::strcmp(argv[a], "--ny") && a + 1 < argc)
            ny = std::atoi(argv[++a]);
        else if (!std::strcmp(argv[a], "--steps") && a + 1 < argc)
            steps = std::atoi(argv[++a]);
        else if (!std::strcmp(argv[a], "--dt") && a + 1 < argc)
            dt = (float)std::atof(argv[++a]);
        else if (!std::strcmp(argv[a], "--reps") && a + 1 < argc)
            reps = std::atoi(argv[++a]);
        else if (!std::strcmp(argv[a], "--check")) check = true;
        else {
            std::fprintf(stderr, "ismeretlen argumentum: %s\n", argv[a]);
            return EXIT_FAILURE;
        }
    }
    const float alpha = 1.0f, dx = 1.0f, dy = 1.0f, sigma = 0.05f * nx * dx;
    const size_t n = (size_t)nx * ny, bytes = n * sizeof(float);
    float *d_a = nullptr, *d_b = nullptr;
    CUDA_CHECK(cudaMalloc(&d_a, bytes));
    CUDA_CHECK(cudaMalloc(&d_b, bytes));

    std::vector<float> h[2];
    for (int v = 0; v < 2; ++v) {            // v = 0: naiv, v = 1: tiled
        std::vector<double> ms;
        float* d_final = nullptr;
        for (int r = 0; r < warmup + reps; ++r) {
            float t = run_steps(v == 1, d_a, d_b, nx, ny, steps, alpha, dt,
                                dx, dy, sigma, &d_final);
            if (r >= warmup) ms.push_back(t);
        }
        double avg = 0.0, var = 0.0;
        for (double t : ms) avg += t;
        avg /= ms.size();
        for (double t : ms) var += (t - avg) * (t - avg);
        double sd = ms.size() > 1 ? std::sqrt(var / (ms.size() - 1)) : 0.0;
        std::sort(ms.begin(), ms.end());
        size_t m = ms.size();
        double med = (m % 2) ? ms[m / 2] : 0.5 * (ms[m / 2 - 1] + ms[m / 2]);
        // algoritmikus (minimális) forgalom: 8 bájt/pont/lépés (4 B olvasás + 4 B írás)
        double bw = 8.0 * (double)n * steps / (med * 1e-3) / 1e9;
        std::printf("%s: medián %.3f ms +- %.3f ms (%d lepes), "
                    "effektiv savszelesseg (8 B/pont): %.1f GB/s\n",
                    v ? "tiled" : "naiv", med, sd, steps, bw);
        h[v].resize(n);
        CUDA_CHECK(cudaMemcpy(h[v].data(), d_final, bytes, cudaMemcpyDeviceToHost));
    }
    double maxdiff = 0.0;                    // naiv vs tiled: várhatóan 0
    for (size_t k = 0; k < n; ++k)
        maxdiff = std::max(maxdiff, (double)std::fabs(h[0][k] - h[1][k]));
    std::printf("max |naiv - tiled| = %.3e\n", maxdiff);
    if (check) {
        std::vector<double> ref;
        cpu_reference(ref, nx, ny, steps, alpha, dt, dx, dy, sigma);
        for (int v = 0; v < 2; ++v) {
            double e = 0.0, emax = 0.0;
            for (size_t k = 0; k < n; ++k) {
                double d = h[v][k] - ref[k];
                e += d * d;
                emax = std::max(emax, std::fabs(d));
            }
            std::printf("%s: L2-hiba az FP64 CPU-referenciához: %.3e, "
                        "max abs hiba: %.3e\n", v ? "tiled" : "naiv", std::sqrt(e), emax);
        }
    }
    CUDA_CHECK(cudaFree(d_a));
    CUDA_CHECK(cudaFree(d_b));
    return 0;
}

33.2.15 Mérési módszertan

  • Warm-up: 5 iteráció
  • Mérés: 20 ismétlés, medián és szórás számítása
  • Időmérés: CUDA events, a teljes időlépés-sorozatra
  • Effektív sávszélesség mindkét kernelre azonos, algoritmikus alapon: 4 bájt olvasás + 4 bájt írás pontonként = 8 bájt/pont/lépés (a halo redundancia elhanyagolható). Így a két kernel értéke összehasonlítható. A logikai load/store-forgalom (naiv: 5 olvasás + 1 írás = 24 bájt/pont) nem azonos a DRAM-forgalommal, mert az L1/L2 az ismételt olvasásokat elnyeli; a valódi DRAM-forgalmat ncu-val (dram__bytes_read.sum, dram__bytes_write.sum) kell megmérni.
  • A hiba számítása a végső mező és egy CPU referencia (FP64) közötti L2L^2-normával történik (kis rácson, --check).
  • Várt alsó korlát (analitikus, nem mért): 1000 lépés ×\times 128 MiB ≈134,2\approx 134{,}2 GB ideális forgalom; 448 GB/s-on legalább kb. 300 ms.

33.2.17 Mért és várt eredmények

A várt érték a modellből származik, a mért érték a futtatásból: az FP64 CPU-referencia nem „várt”, hanem külön számított összehasonlítási alap. A naiv és a tiled kernel L2L^2-hibáját a referenciához képest a --check kapcsoló írja ki; a --check a maximális abszolút hibát is kiírja; ennek megengedett értéke a charter hibakorlátja (FP32: legfeljebb 10−310^{-3} maximális abszolút hiba), az L2L^2-norma kiegészítő adat. A 4096²-es futás ellenőrzéséhez a 33.4 validációja (GPU-s FP64 referenciakernel vagy ritkított mintavétel) szolgál; a labor host-programja egyszerűség kedvéért a hibát a hoston számolja, a compute_l2_diff a nagy rácsos validációban használható. A futásidő-arány (tiled / naiv) mért érték, amelyet a roofline-modellből nem lehet előre ígérni: ha a gyorsítótár már a naiv változatban elnyeli az újraolvasást, a tiling nyeresége kicsi vagy akár negatív is lehet.

33.2.18 Önellenőrző kérdések

  1. Miért van szükség __syncthreads()-re a tiled kernelben a halo betöltés után, és mi történne, ha elhagynánk?
  2. Mi a különbség a naiv és a tiled kernel memória-hozzáférése között? Mindkettő koaleszkált-e, és hol (L1/L2 vagy shared memory) keletkezik az újrafelhasználás?
  3. Hogyan ellenőrizzük a kernelindítás hibáját közvetlenül a launch után, és miért nem elég a cudaGetLastError() a kernel végrehajtása közbeni hibákhoz?
  4. Miért választottuk szét a fő kernelt a segédkernelektől? Milyen előnyei vannak ennek a tesztelés és a karbantartás szempontjából?

Rövid válaszok. (1) A halo és a belső elemek betöltése után a szomszéd szálak által írt csempe-elemeket csak barrier után szabad olvasni; nélküle versenyhelyzet és hibás stencil-érték keletkezik (33.2.4). (2) A naiv kernel öt globális olvasást végez pontonként, a tiled egyet a csempébe, onnan a shared memory-ból olvas; a naivban az újrafelhasználást az L1/L2 adja, a tiledben a shared memory (33.2.3). (3) Az indítás után cudaGetLastError() az indítási hibát (konfiguráció) adja; a végrehajtás közbeni hibák (például memóriahozzáférés) csak a következő szinkronizáló híváson (cudaDeviceSynchronize vagy az eseményre várás) derülnek ki, ezért a mérési ciklus után is ellenőrizni kell, és compute-sanitizer-rel futtatni (33.2.10). (4) A segédkernelek külön tesztelhetők és cserélhetők, a fő kernel kódja rövidebb és a hiba lokalizálható; a karbantartás egyszerűbb (33.2.1).

33.2.19 Összegzés

Ebben az egységben a záróprojekt kernelimplementációját építettük fel: a fő stencil-kernelt naiv és tiled változatban, valamint az inicializáló, peremfeltételt beállító és hibaszámító segédkerneleket. A memória- és szinkronizációs döntések középpontjában a shared memory tiling és a blokkszintű barrier állt. A hibakezelést kötelező makróval és compute-sanitizer-rel biztosítottuk. A labor mérési naplója (kitöltendő) mutatja majd meg, hogy a tiled kernel a saját GPU-n mennyivel tér el a naivtól, és hogy a numerikus hiba a megengedett tartományon belül marad. A következő alfejezet (33.3) ezt az alapot mérésvezérelt hangolásra használja: tiling, bankkonfliktus, occupancy és launch-paraméterek, streamek és átfedés, valamint Nsight-alapú elemzés következik.
