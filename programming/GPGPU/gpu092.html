24.3 Attention kernelek

A scaled dot-product attention a transformer modellek központi építőköve: a bemeneti szekvencia minden tokenjéhez kiszámítja, hogy a többi token mennyire releváns a reprezentációjában. GPU-n a művelet három nagy mátrixszorzásra és egy softmaxra bontható, ezért elsőre egyszerűnek tűnik, de a gyakorlatban a memóriaelérési minta és a softmax numerikus stabilitása határozza meg a teljesítményt. Ebben az alfejezetben a scaled dot-product attention CUDA C++ implementációját építjük fel a naiv kerneltől a tiled, online softmaxot használó változatig, és bemutatjuk a FlashAttention alapelvét.

24.3.1 A scaled dot-product attention matematikai alakja

Adott egy Q∈ℝN×dQ \in \mathbb{R}^{N \times d} query, egy K∈ℝN×dK \in \mathbb{R}^{N \times d} key és egy V∈ℝN×dV \in \mathbb{R}^{N \times d} value mátrix, ahol NN a szekvencia hossza, dd a fej dimenziója. Az attention kimenet:

O=softmax(QKTd)V O = \text{softmax}\left(\frac{QK^T}{\sqrt{d}}\right)V

A softmax soronként normalizál:

pij=esij−mi∑k=1Nesik−mi,sij=(QKT)ijd,mi=maxjsij p_{ij} = \frac{e^{s_{ij} - m_i}}{\sum_{k=1}^{N} e^{s_{ik} - m_i}}, \quad s_{ij} = \frac{(QK^T)_{ij}}{\sqrt{d}}, \quad m_i = \max_j s_{ij}

A mim_i kivonása numerikusan stabilizálja a kitevőt: a legnagyobb logit nulla lesz, így a kitevő értéke nem csordul túl FP32 esetén sem. A 1/d1/\sqrt{d} skálázás a nagy dd esetén fellépő variancia-növekedést kompenzálja.

A kimenet O∈ℝN×dO \in \mathbb{R}^{N \times d}, minden sora a value vektorok súlyozott összege:

Oi=∑j=1NpijVj O_i = \sum_{j=1}^{N} p_{ij} V_j

A művelet számítási komplexitása O(N2d)O(N^2 d); a naiv (tankönyvi) implementáció kiegészítő memóriaigénye O(N2)O(N^2), mert a köztes S=QKT/dS = QK^T/\sqrt{d} mátrixot ki kell számítani és eltárolni, HBM-forgalma Θ(Nd+N2)\Theta(Nd + N^2). A FlashAttention tiling és online softmax alkalmazásával a kiegészítő memóriaigényt O(N)O(N)-re, a HBM-forgalmat Θ(N2d2/M)\Theta(N^2 d^2 / M)-re csökkenti (MM a SRAM mérete).

24.3.2 Naiv CUDA implementáció

Az első implementációban minden kimeneti sorhoz egy CUDA thread tartozik. A thread kiszámolja a query sor és az összes key sor skaláris szorzatát, elvégzi a softmaxot, majd a value sorok súlyozott összegét írja az outputba. A kernel a következő:

// attention_naive.cu  (CUDA C++17; nem lett lefordítva vagy futtatva)
#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cmath>
#include <vector>
#include <algorithm>

#define CUDA_CHECK(call) do {                                  \
    cudaError_t err = (call);                                  \
    if (err != cudaSuccess) {                                  \
        std::fprintf(stderr, "CUDA error at %s:%d: %s\n",      \
                     __FILE__, __LINE__, cudaGetErrorString(err)); \
        std::exit(EXIT_FAILURE);                                \
    }                                                          \
} while (0)

__global__ void attention_naive_kernel(const float* __restrict__ Q,
                                       const float* __restrict__ K,
                                       const float* __restrict__ V,
                                       float* __restrict__ O,
                                       int N, int D) {
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row >= N) return;

    const float inv_sqrt_d = 1.0f / sqrtf((float)D);
    float max_s = -INFINITY;
    // Először a maximumot keressük a stabil softmaxhoz.
    for (int j = 0; j < N; ++j) {
        float dot = 0.0f;
        for (int d = 0; d < D; ++d) {
            dot += Q[row * D + d] * K[j * D + d];
        }
        float s = dot * inv_sqrt_d;
        max_s = fmaxf(max_s, s);
    }

    float sum = 0.0f;
    for (int j = 0; j < N; ++j) {
        float dot = 0.0f;
        for (int d = 0; d < D; ++d) {
            dot += Q[row * D + d] * K[j * D + d];
        }
        float s = dot * inv_sqrt_d;
        float p = expf(s - max_s);
        sum += p;
    }

    float* O_row = O + row * D;
    for (int d = 0; d < D; ++d) {
        O_row[d] = 0.0f;
    }

    for (int j = 0; j < N; ++j) {
        float dot = 0.0f;
        for (int d = 0; d < D; ++d) {
            dot += Q[row * D + d] * K[j * D + d];
        }
        float s = dot * inv_sqrt_d;
        float p = expf(s - max_s) / sum;
        for (int d = 0; d < D; ++d) {
            O_row[d] += p * V[j * D + d];
        }
    }
}

// CPU referencia: a definíció double pontossággal
void attention_cpu(const float* Q, const float* K, const float* V, float* O, int N, int D) {
    std::vector<double> s(N);
    for (int i = 0; i < N; ++i) {
        double m = -INFINITY;
        for (int j = 0; j < N; ++j) {
            double dot = 0.0;
            for (int d = 0; d < D; ++d) dot += (double)Q[i * D + d] * K[j * D + d];
            s[j] = dot / std::sqrt((double)D);
            m = std::max(m, s[j]);
        }
        double sum = 0.0;
        for (int j = 0; j < N; ++j) { s[j] = std::exp(s[j] - m); sum += s[j]; }
        for (int d = 0; d < D; ++d) {
            double o = 0.0;
            for (int j = 0; j < N; ++j) o += s[j] / sum * V[j * D + d];
            O[i * D + d] = (float)o;
        }
    }
}

int main(int argc, char** argv) {
    int N = (argc > 1) ? std::atoi(argv[1]) : 1024;
    int D = (argc > 2) ? std::atoi(argv[2]) : 64;
    size_t bytes = (size_t)N * D * sizeof(float);
    std::vector<float> h_Q(N * D), h_K(N * D), h_V(N * D), h_O(N * D), h_ref(N * D);
    std::srand(1234);                                  // determinisztikus bemenet
    for (int i = 0; i < N * D; ++i) {
        h_Q[i] = (float)std::rand() / RAND_MAX;
        h_K[i] = (float)std::rand() / RAND_MAX;
        h_V[i] = (float)std::rand() / RAND_MAX;
    }
    float *d_Q, *d_K, *d_V, *d_O;
    CUDA_CHECK(cudaMalloc(&d_Q, bytes));
    CUDA_CHECK(cudaMalloc(&d_K, bytes));
    CUDA_CHECK(cudaMalloc(&d_V, bytes));
    CUDA_CHECK(cudaMalloc(&d_O, bytes));
    CUDA_CHECK(cudaMemcpy(d_Q, h_Q.data(), bytes, cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(d_K, h_K.data(), bytes, cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(d_V, h_V.data(), bytes, cudaMemcpyHostToDevice));

    int block = 256;
    int grid = (N + block - 1) / block;
    // Warm-up (10 futás), majd iterációnként külön mért idő (CUDA events)
    for (int i = 0; i < 10; ++i)
        attention_naive_kernel<<<grid, block>>>(d_Q, d_K, d_V, d_O, N, D);
    CUDA_CHECK(cudaGetLastError());
    CUDA_CHECK(cudaDeviceSynchronize());
    const int iters = 20;
    cudaEvent_t t0, t1;
    CUDA_CHECK(cudaEventCreate(&t0)); CUDA_CHECK(cudaEventCreate(&t1));
    std::vector<float> ts(iters);
    for (int i = 0; i < iters; ++i) {
        CUDA_CHECK(cudaEventRecord(t0));
        attention_naive_kernel<<<grid, block>>>(d_Q, d_K, d_V, d_O, N, D);
        CUDA_CHECK(cudaGetLastError());
        CUDA_CHECK(cudaEventRecord(t1));
        CUDA_CHECK(cudaEventSynchronize(t1));
        CUDA_CHECK(cudaEventElapsedTime(&ts[i], t0, t1));
    }
    std::sort(ts.begin(), ts.end());
    float med = 0.5f * (ts[iters / 2 - 1] + ts[iters / 2]);
    float iqr = ts[3 * iters / 4] - ts[iters / 4];
    std::printf("Naiv kernel: medián %.3f ms, IQR %.3f ms (%d iteráció)\n", med, iqr, iters);

    // Helyesség: CPU referencia és max abszolút hiba
    CUDA_CHECK(cudaMemcpy(h_O.data(), d_O, bytes, cudaMemcpyDeviceToHost));
    attention_cpu(h_Q.data(), h_K.data(), h_V.data(), h_ref.data(), N, D);
    float max_err = 0.0f;
    for (int i = 0; i < N * D; ++i) max_err = std::max(max_err, std::fabs(h_O[i] - h_ref[i]));
    std::printf("Naiv kernel: max abszolút hiba a CPU referenciához képest = %g\n", max_err);

    CUDA_CHECK(cudaFree(d_Q)); CUDA_CHECK(cudaFree(d_K));
    CUDA_CHECK(cudaFree(d_V)); CUDA_CHECK(cudaFree(d_O));
    return 0;
}

A naiv kernel háromszor járja be a KK mátrixot: egyszer a maximumhoz, egyszer az összeghez, egyszer a súlyozott összeghez; a VV mátrixot csak a harmadik menet olvassa (egyszer). A QQ-sor és a KK-val vett skaláris szorzat háromszor számolódik, mert a softmax köztes ss értékeit a kernel nem tárolja. Ez a „naiv” kernel ezért nem a tankönyvi háromkernelés változat (ott SS-t a globális memóriába írnák), hanem egy újraszámoló kernel. A KK és VV olvasása a warpon belül broadcast (minden szál ugyanazt a jj-edik sort olvassa), a QQ-sor olvasása viszont D lépésközű; a globális tranzakciók száma ezért kisebb, mint a szálankénti O(Nd)O(Nd) olvasásból adódó felső becslés. A kernel regiszterhasználata alacsony, de a memóriaforgalom és a redundáns számítás nagy; ez a teljesítmény fő korlátja.

24.3.3 Softmax és tiling

A naiv kernel a softmaxot a teljes sorra számítja ki, amihez ismerni kell az összes sijs_{ij} értéket. Ha a KK és VV mátrixokat blokkokra osztjuk, a softmaxot inkrementálisan is kiszámíthatjuk. Az online softmax algoritmus a következő állapotot tartja karban:

  • mm: az eddig látott maximális logit,
  • ℓ\ell: az eddig látott exponenciális összeg,
  • OO: az eddigi súlyozott value összeg.

Amikor egy új sjs_j logit érkezik, a frissítés:

mnew=max⁡(m,sj) m_{\text{new}} = \max(m, s_j) ℓnew=ℓ⋅em−mnew+esj−mnew \ell_{\text{new}} = \ell \cdot e^{m - m_{\text{new}}} + e^{s_j - m_{\text{new}}} Onew=O⋅em−mnew+Vj⋅esj−mnew O_{\text{new}} = O \cdot e^{m - m_{\text{new}}} + V_j \cdot e^{s_j - m_{\text{new}}}

Az algoritmus lényege, hogy a korábbi exponenciális összeget és a korábbi kimenetet átskálázzuk, amikor új maximumot találunk. Így soha nem kell az összes sijs_{ij} értéket egyszerre tárolni, és a kimenet a blokkok feldolgozása közben folyamatosan frissül.

A tiling lényege, hogy a KK és VV mátrixokat BcB_c méretű blokkokra osztjuk, a QQ mátrixot BrB_r méretű blokkokra. Egy CUDA blokk egy QQ-blokkhoz tartozó kimeneti blokkot számol ki, és a K,VK,V-blokkokat shared memoryba tölti be. A kernel pszeudokódja:

for each Q block (B_r x d) in Q:
    load Q block into shared memory
    initialize m = -inf, l = 0, acc = 0
    for each K,V block (B_c x d) in K,V:
        load K block and V block into shared memory
        compute S block = Q_block * K_block^T / sqrt(d)
        for each row i in Q block:
            for each column j in K block:
                s = S[i][j]
                m_new = max(m[i], s)
                l_new = l[i] * exp(m[i] - m_new) + exp(s - m_new)
                acc[i] = acc[i] * exp(m[i] - m_new) + V_block[j] * exp(s - m_new)
                m[i] = m_new
                l[i] = l_new
    write O block = acc[i] / l[i]

A tiled kernel a következő CUDA C++ implementációban valósul meg (jelölés: BLOCK_M = BrB_r, BLOCK_N = BcB_c, D = dd, l_i = ℓ\ell). A blokk dimenziója BLOCK_M, minden thread egy QQ-sort dolgoz fel, amelyet a regiszterekbe tölt; a K,VK,V-blokkokat a blokk közösen tölti be a shared memoryba és iterálja.

// attention_tiled.cu  (CUDA C++17; nem lett lefordítva vagy futtatva)
#include <cuda_runtime.h>
#include <cstdio>
#include <cstdlib>
#include <cmath>
#include <vector>
#include <algorithm>

#define CUDA_CHECK(call) do {                                  \
    cudaError_t err = (call);                                  \
    if (err != cudaSuccess) {                                  \
        std::fprintf(stderr, "CUDA error at %s:%d: %s\n",      \
                     __FILE__, __LINE__, cudaGetErrorString(err)); \
        std::exit(EXIT_FAILURE);                                \
    }                                                          \
} while (0)

#define BLOCK_M 128
#define BLOCK_N 64
constexpr int D = 64;   // fordításkor rögzített fej-dimenzió

__global__ void attention_tiled_kernel(const float* __restrict__ Q,
                                       const float* __restrict__ K,
                                       const float* __restrict__ V,
                                       float* __restrict__ O,
                                       int N) {
    extern __shared__ float smem[];
    float* K_shared = smem;                     // BLOCK_N * D
    float* V_shared = smem + BLOCK_N * D;       // BLOCK_N * D

    int row = blockIdx.x * BLOCK_M + threadIdx.x;
    float inv_sqrt_d = 1.0f / sqrtf((float)D);

    // A szál saját Q-sora regiszterekbe kerül (a shared memory D-s lépésköze
    // 32-utas bank conflictot okozna).
    float q[D];
    for (int d = 0; d < D; ++d) q[d] = (row < N) ? Q[row * D + d] : 0.0f;

    // Online softmax állapot regiszterekben.
    float m_i = -INFINITY;
    float l_i = 0.0f;
    float acc[D];
    for (int d = 0; d < D; ++d) acc[d] = 0.0f;

    // K,V blokkok iterálása.
    for (int block_start = 0; block_start < N; block_start += BLOCK_N) {
        // K és V blokk betöltése (a szomszédos szálak szomszédos elemeket olvasnak).
        for (int idx = threadIdx.x; idx < BLOCK_N * D; idx += blockDim.x) {
            int r = idx / D;
            int c = idx % D;
            int global_r = block_start + r;
            K_shared[idx] = (global_r < N) ? K[global_r * D + c] : 0.0f;
            V_shared[idx] = (global_r < N) ? V[global_r * D + c] : 0.0f;
        }
        __syncthreads();

        // Skaláris szorzat és online softmax frissítés (K_shared olvasás: broadcast).
        if (row < N) {
            for (int j = 0; j < BLOCK_N; ++j) {
                int global_j = block_start + j;
                if (global_j >= N) break;
                float dot = 0.0f;
                for (int d = 0; d < D; ++d) {
                    dot += q[d] * K_shared[j * D + d];
                }
                float s = dot * inv_sqrt_d;

                float m_new = fmaxf(m_i, s);
                float exp_m_old = expf(m_i - m_new);   // az első lépésben exp(-inf) = 0
                float exp_s = expf(s - m_new);
                l_i = l_i * exp_m_old + exp_s;
                for (int d = 0; d < D; ++d) {
                    acc[d] = acc[d] * exp_m_old + V_shared[j * D + d] * exp_s;
                }
                m_i = m_new;
            }
        }
        __syncthreads();
    }

    // Kimenet írása.
    if (row < N) {
        for (int d = 0; d < D; ++d) {
            O[row * D + d] = acc[d] / l_i;
        }
    }
}


// CPU referencia: a definíció double pontossággal (azonos a naiv programéval)
void attention_cpu(const float* Q, const float* K, const float* V, float* O,
                   int N, int dim) {
    std::vector<double> s(N);
    for (int i = 0; i < N; ++i) {
        double m = -INFINITY;
        for (int j = 0; j < N; ++j) {
            double dot = 0.0;
            for (int d = 0; d < dim; ++d) dot += (double)Q[i * dim + d] * K[j * dim + d];
            s[j] = dot / std::sqrt((double)dim);
            m = std::max(m, s[j]);
        }
        double sum = 0.0;
        for (int j = 0; j < N; ++j) { s[j] = std::exp(s[j] - m); sum += s[j]; }
        for (int d = 0; d < dim; ++d) {
            double o = 0.0;
            for (int j = 0; j < N; ++j) o += s[j] / sum * V[j * dim + d];
            O[i * dim + d] = (float)o;
        }
    }
}

A tiled kernel shared memory igénye 2⋅64⋅64⋅4=327682 \cdot 64 \cdot 64 \cdot 4 = 32\,768 bájt (32 KiB): a KK és VV blokk; a QQ sor regiszterben van. Ez az alapértelmezett 48 KiB/blokk korlát alatt marad, ezért nincs szükség opt-inre (a main mégis tartalmaz feltételes cudaFuncSetAttribute hívást a nagyobb konfigurációkhoz). A kernelben a DD dimenzió ciklusban van: egy szál minden K,VK,V elempárhoz 2 FMA-t végez (skaláris szorzat és az acc frissítés) és 2 shared memory olvasást (egy K_shared és egy V_shared elem), azaz shared olvasásonként egyetlen FMA-t, ezért az aritmetikai intenzitás a shared memory olvasásokra vetítve alacsony; ez az oka annak, hogy a valódi FlashAttention warp-szintű mátrixszorzást (Tensor Core) használ. A KsharedK_\text{shared} és a VsharedV_\text{shared} olvasása is broadcast (a warp minden szála ugyanazt az elemet olvassa), így bank conflict nem keletkezik.

A naiv kernelhez képest a tiled kernel a KK és VV mátrixokat blokkonként csak egyszer olvassa be a globális memóriából (blokkonként; a blokkok száma N/N/BLOCK_M), utána a shared memoryból dolgozik. A QQ sor csak egyszer kerül beolvasásra. A softmax online frissítése pedig elkerüli, hogy a teljes SS sort tárolni kelljen. Ez a két tulajdonság a FlashAttention alapelve.

24.3.4 FlashAttention elve

A FlashAttention (Dao et al., 2022) a fenti tiling és online softmax ötletét viszi tovább. A tankönyvi (három lépéses) attention implementáció a teljes S=QKT/dS = QK^T/\sqrt{d} mátrixot kiírja a globális memóriába, majd beolvassa a softmaxhoz, és végül a VV-vel való szorzáshoz (ez O(N2)O(N^2) kiegészítő memóriát és Θ(Nd+N2)\Theta(Nd + N^2) HBM-forgalmat jelent; nagy NN esetén ez a HBM sávszélességét telíti). A fent bemutatott „naiv” kernel ettől eltér: SS-t nem materializálja, hanem háromszor újraszámolja; ez a referencia a tiled kernelhez, míg a tankönyvi változat a FlashAttention elméleti viszonyítási alapja. A FlashAttention az SS mátrixot soha nem materializálja a globális memóriában; helyette a K,VK,V blokkokat tölti be, az online softmaxot a regiszterekben és a shared memoryban végzi, és a kimenetet folyamatosan frissíti.

A FlashAttention főbb technikai elemei:

  1. Tiling: a Q,K,VQ,K,V mátrixokat olyan blokkokra osztja, amelyek beférnek a shared memoryba. A QQ blokk Br×dB_r \times d, a K,VK,V blokk Bc×dB_c \times d méretű. A kernel egy QQ-blokkhoz tartozó kimeneti blokkot számol ki, és a K,VK,V-blokkokat sorban tölti be.

  2. Online softmax: a softmax normalizáló összeget és a kimeneti accumulatorokat inkrementálisan frissíti a fent bemutatott képletekkel. Így nincs szükség arra, hogy a teljes SS sort egyszerre lássa.

  3. Regiszteres tiling: a QQ blokk egyes sorait a regiszterekben tartja, a K,VK,V blokkokat a shared memoryban. A Q,K,VQ, K, V blokkok teljes dd szélességgel töltődnek be (Br×dB_r \times d, Bc×dB_c \times d); a fej-dimenziót az algoritmus nem blokkolja.

  4. Egzakt számítás és numerikus stabilitás: a FlashAttention nem közelítő, hanem egzakt attention (a szabványos softmax-attention eredményét adja, más összegzési sorrenddel). Az online softmax miatt a numerikus hiba kicsi marad, mert minden lépésben a futó maximum kerül kivonásra; FP16/BF16 esetén is stabil, ha a skálázást és a kitevőt megfelelően kezelik.

A FlashAttention gyakorlati előnye, hogy a kiegészítő memóriaigény O(N2)O(N^2)-ről O(N)O(N)-re csökken (csak a soronkénti statisztikákat kell tárolni), a HBM-forgalom pedig Θ(Nd+N2)\Theta(Nd + N^2)-ről (standard attention) Θ(N2d2/M)\Theta(N^2 d^2 / M)-re (MM a SRAM mérete; Dao et al., 2022). Az O(N2d)O(N^2 d) a számítási komplexitás, ez nem változik. A kernel így a HBM sávszélesség helyett inkább a számítási egységek kihasználtságát növeli. A CUDA implementációban a shared memory és a regiszterek közötti adatáramlás optimalizálása a fő feladat.

A fenti tiled kernel a FlashAttention egy leegyszerűsített változata: egy szál egy QQ-sort dolgoz fel (a sor regiszterben van), a K,VK,V blokkokat a shared memoryból olvassa, és a mátrixszorzást skalár FMA-kkal végzi. A valódi FlashAttention is a teljes dd szélességű Q,K,VQ, K, V blokkokkal dolgozik (nem blokkolja a fej-dimenziót), de a mátrixszorzást warp-szintű primitívekkel, például a mma utasításokkal (Tensor Core) gyorsítja, és a blokkokat a SRAM méretéhez hangolja. A laborban az egyszerűsített változatot mérjük, hogy az alapelvek érthetők legyenek.

24.3.8 Ellenőrzés

Az implementáció helyességét CPU referencia implementációval kell összehasonlítani (lásd a fenti attention_cpu függvényt): a CPU referencia a matematikai definíciót double pontossággal számítja ki, és a kimeneti mátrix elemeit összehasonlítja a GPU eredménnyel. A GPU kernelek más összegzési sorrendet használnak (a naiv három menetben, a tiled online softmaxszal, átskálázva), ezért bitazonos eredmény nem várható; FP32 esetén N=1024N=1024, d=64d=64 és egyenletes [0,1)[0,1) bemenet mellett az abszolút eltérés jellemzően 10−610^{-6} nagyságrendű (a kimenet értéke ≈0,5\approx 0{,}5); 10−510^{-5} feletti eltérés már hibagyanús (a lektor saját futtatása alapján; nálunk nem futtatva). A küszöböt a saját mérés alapján kell megerősíteni (a küszöb nem azon alapul, hogy a két implementáció ugyanazt a sorrendet követné).

JAX ellenőrző példa (csak dokumentáció, nem futtatott):

import jax
import jax.numpy as jnp

def attention(q, k, v):
    d = q.shape[-1]
    scores = (q @ k.T) / jnp.sqrt(d)
    weights = jax.nn.softmax(scores, axis=-1)
    return weights @ v

# Egyfejes példa, mint a CUDA kernelek; véletlen bemenet, rögzített maggal.
kq, kk, kv = jax.random.split(jax.random.PRNGKey(0), 3)
q = jax.random.uniform(kq, (1024, 64), dtype=jnp.float32)
k = jax.random.uniform(kk, (1024, 64), dtype=jnp.float32)
v = jax.random.uniform(kv, (1024, 64), dtype=jnp.float32)
out = attention(q, k, v)
# A CUDA-kernel kimenetét (ugyanezzel a bemenettel, fájlba mentve) betöltve:
# jnp.allclose(out, o_cuda, rtol=1e-4, atol=1e-5)
print(out.shape)

A JAX példa a TPU-n való futtatásra is alkalmas, de a laborban csak a CPU/GPU ellenőrzéshez használjuk.

24.3.9 Gyakori hibák és megoldások

  1. Softmax túlcsordulás: ha a sijs_{ij} értékek nagyok, a expf túlcsordulhat, és inf értéket ad. A megoldás a maximum kivonása minden sorban. A naiv kernel ezt a max_s kiszámításával, a tiled kernel az online softmax frissítéssel oldja meg.

  2. Skálázás elfelejtése: a 1/d1/\sqrt{d} tényező kihagyása nagy dd esetén a softmax bemenet varianciáját növeli, ami numerikus instabilitáshoz és rossz tanulási dinamikához vezet. A kernelben mindig alkalmazni kell az inv_sqrt_d szorzót.

  3. Race condition az output írásakor: ha több thread írja ugyanazt a kimeneti elemet, atomi művelet vagy redukció szükséges. A naiv kernelben minden thread egy sort ír, ezért nincs ütközés. A tiled kernelben a kimeneti sorokat a blokk threadjei írják, de minden thread egy sort, így szintén nincs ütközés. Ha a DD dimenziót párhuzamosítanánk, akkor atomi add vagy külön redukciós lépés kellene.

  4. Túl nagy shared memory foglalás: ha a BLOCK_M és BLOCK_N értékeket nagyra választjuk, a shared memory igény túl nagy lesz. A blokkonkénti dinamikus shared memory alapértelmezett korlátja 48 KiB; efölött a kernelre cudaFuncSetAttribute(kernel, cudaFuncAttributeMaxDynamicSharedMemorySize, bytes) opt-in kell, különben a launch „invalid argument” hibával elbukik. Az itt bemutatott kernel (Q regiszterben) 2⋅64⋅64⋅4=327682 \cdot 64 \cdot 64 \cdot 4 = 32\,768 bájtot (32 KiB) használ. Ha a QQ-blokkot is a shared memoryban tartanánk, BLOCK_M=128 esetén (128+2⋅64)⋅64⋅4=65536(128+2 \cdot 64) \cdot 64 \cdot 4 = 65\,536 bájt (64 KiB), BLOCK_M=256 esetén (256+2⋅64)⋅64⋅4=98304(256+2 \cdot 64) \cdot 64 \cdot 4 = 98\,304 bájt (96 KiB) kellene; az sm_86 (RTX 3090) blokkonként legfeljebb 99 KiB-ot enged opt-in, az SM-enként 100 KiB miatt 1 blokk/SM fér el, az sm_80 (A100) blokkonként legfeljebb 163 KiB-ot enged.

  5. A naiv kernel regiszter spill: ha a naiv kernelben a teljes SS sort lokális tömbben tároljuk, a regiszterekből a lokális memóriába kerül, ami lassú. A tiled kernel ezt elkerüli, mert nem tárolja a teljes sort.

  6. Nem megfelelő blokkméret: a naiv kernel blokkmérete 256, ami jó occupancyt ad. A tiled kernel blokkmérete BLOCK_M=128, ami alacsonyabb, de a shared memory igény miatt elfogadható. A blokkméretet a kernel erőforrás-igényéhez kell igazítani.

24.3.10 Önellenőrző kérdés

Miért kerüli el a FlashAttention a teljes S=QKT/dS = QK^T/\sqrt{d} mátrix globális memóriába írását, és hogyan befolyásolja ez a teljesítményt?

Válasz: A teljes SS mátrix mérete N×NN \times N, ami nagy NN esetén hatalmas memóriaforgalmat jelent. A FlashAttention a K,VK,V blokkokat tölti be, az online softmaxot a regiszterekben és a shared memoryban végzi, és a kimenetet folyamatosan frissíti. Ezáltal a kiegészítő memóriaigény O(N2)O(N^2)-ről O(N)O(N)-re csökken (csak a soronkénti statisztikákat kell tárolni), a HBM-forgalom pedig Θ(Nd+N2)\Theta(Nd + N^2)-ről Θ(N2d2/M)\Theta(N^2 d^2 / M)-re (MM a SRAM mérete; Dao et al., 2022). A teljesítményt így kevésbé a HBM sávszélesség, inkább a számítási átbocsátóképesség határozza meg. Az eredmény egzakt, nem közelítő.
