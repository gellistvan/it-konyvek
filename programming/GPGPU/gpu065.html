17.4 Selection és order statistics

Amikor egy rendezetlen sorozatból nem a teljes rendezést, hanem csak egy kitüntetett elemet – például a mediánt, a felső kvartilist vagy az adott percentilishez tartozó értéket – kell kinyernünk, a kiválasztási (selection) feladatot oldjuk meg. A GPU-n ez a feladat sokszor hatékonyabban megoldható, mint a teljes rendezés, mert a párhuzamos hisztogramok és a prefix összegek segítségével a keresési teret iteratívan szűkíthetjük. Ebben az alfejezetben a kk-adik elem és a medián GPU-s kiszámítását vizsgáljuk meg, különös tekintettel a pivot alapú particionálásra, a radix selectre, valamint a pontossági és teljesítménybeli kérdésekre.

17.4.1 A kk-adik elem és a medián GPU-n

A sorrendi statisztika (order statistics) fogalma egy nn elemű X={x0,x1,…,xn−1}X = \{x_0, x_1, \ldots, x_{n-1}\} sorozat kk-adik legkisebb elemét jelöli: azt az értéket, amely a nem csökkenő sorrendbe rendezett sorozat kk-adik pozícióján áll. A k=0k = 0 a minimum, k=n−1k = n-1 a maximum, k=⌊n/2⌋k = \lfloor n/2 \rfloor pedig a (páros nn-nél felső) medián; páros nn-nél az alsó medián a ⌊(n−1)/2⌋\lfloor (n-1)/2 \rfloor indexű elem. A kvantilisek – például a felső kvartilis vagy a 95. percentilis – ugyanezt a definíciót követik, csak más kk értékkel.

A CPU-n a probléma klasszikus megoldása a std::nth_element függvény, amely átlagosan O(n)O(n) időben kiválasztja a kk-adik elemet anélkül, hogy a teljes tömböt rendezné. A GPU-n azonban a helyzet bonyolultabb, mert a párhuzamos végrehajtás és a memóriahierarchia miatt a triviális CPU-algoritmusok nem vihetők át közvetlenül. A teljes rendezés GPU-n is hatékony lehet (például radix sort), de ha csak egyetlen elemre van szükségünk, a teljes rendezés (összehasonlító rendezésnél O(nlog⁡n)O(n \log n), radix sortnál 4 teljes olvasó-író menet) felesleges munka. Célunk olyan párhuzamos algoritmus, amely átlagosan O(n)O(n) munkát végez, és jól illeszkedik a SIMT-végrehajtáshoz.

A GPU-s kiválasztási algoritmusok két fő családba sorolhatók:

  1. Pivot alapú (quickselect): egy pivot elem köré particionáljuk a tömböt, majd a kk index alapján eldöntjük, hogy a bal vagy a jobb oldali részben folytassuk a keresést. Ez az algoritmus átlagosan O(n)O(n) munkát végez, de az iterációk száma a pivot minőségétől függ, ami GPU-n szinkronizációs többletköltséget okozhat.
  2. Radix alapú (radix select): a kulcsok bináris vagy bájtonkénti reprezentációját használva minden iterációban a hisztogram és a prefix összeg segítségével egyre szűkebb bucketbe szorítjuk a keresést. A lépések száma korlátos (32 bites kulcsoknál legfeljebb 4 darab 8 bites lépés, azaz legfeljebb 4 hisztogram-menet), nincs pivotválasztási kockázat, és jól párhuzamosítható; a lépésenkénti munka azonban az adateloszlástól függ (lásd alább).

A következőkben mindkét megközelítést részletesen megvizsgáljuk.

17.4.2 Pivot és particionálás

A quickselect alapötlete a quicksort partíciós lépésén nyugszik: válasszunk egy pivot elemet, és a tömböt a pivothoz viszonyítva osszuk három részre: a pivotnál kisebb elemek, a pivottal egyenlők, a nagyobbak. Jelölje n<n_< a kisebb, n=n_= az egyenlő elemek számát. Ha a keresett (0 alapú) rang kk, akkor:

  • ha k<n<k < n_<, a keresést a pivotnál kisebb elemek között folytatjuk, kk változatlan;
  • ha n<≤k<n<+n=n_< \le k < n_< + n_=, a keresett elem a pivot értéke, kész vagyunk;
  • különben a pivotnál nagyobb elemek között folytatjuk, és kk-t k−n<−n=k - n_< - n_=-ra módosítjuk.

(Ha a tömb elemei mind különbözők, az n==1n_= = 1 eset a klasszikus „pivot pozíciója p=n<p = n_<; ha k>pk > p, akkor k−p−1k - p - 1” szabályt adja. Ismétlődő kulcsoknál a háromutas változat a helyes.)

A GPU-n a particionálás párhuzamos megvalósítása a kulcsfontosságú lépés. Elegendő két számlálót meghatározni (n<n_<, n=n_=), majd csak a kiválasztott oldal elemeit egy új tömbbe tömöríteni; a másik két oldalt nem kell kiírni. A számlálás blokkonként shared memory-ban történik, a tömörítés a kiválasztott elemek számára egy globális számláló atomicAdd-jával (az elemek sorrendje a kiválasztáshoz nem számít). Ez az iteráció két kernel (nem fordított, nem futtatott vázlat):

// CUDA C++ (C++17, sm_80) – nem fordított, nem futtatott vázlat
// d_cnt[0] = n_less, d_cnt[1] = n_eq (a hívás előtt nullázva)
__global__ void countKernel(const unsigned int* d_keys, unsigned int pivot,
                            unsigned int* d_cnt, int n) {
    __shared__ unsigned int s_less, s_eq;
    if (threadIdx.x == 0) { s_less = 0; s_eq = 0; }
    __syncthreads();
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        unsigned int key = d_keys[idx];
        if (key < pivot) atomicAdd(&s_less, 1u);
        else if (key == pivot) atomicAdd(&s_eq, 1u);
    }
    __syncthreads();
    if (threadIdx.x == 0) {
        atomicAdd(&d_cnt[0], s_less);
        atomicAdd(&d_cnt[1], s_eq);
    }
}

// side: 0 -> a pivotnál kisebbeket, 2 -> a nagyobbakat tömöríti d_out-ba;
// d_counter a hívás előtt nullázva; d_out legalább a kiválasztott oldal méretű.
__global__ void compactKernel(const unsigned int* d_keys, unsigned int* d_out,
                              unsigned int* d_counter, unsigned int pivot,
                              int side, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        unsigned int key = d_keys[idx];
        bool take = (side == 0) ? (key < pivot) : (key > pivot);
        if (take) d_out[atomicAdd(d_counter, 1u)] = key;
    }
}

A host-oldali quickselect ciklus pszeudokódja: (1) pivot választása; (2) countKernel, a két számláló visszamásolása; (3) a fenti háromutas szabály szerinti ág kiválasztása: ha a pivot a válasz, vége, különben compactKernel a kiválasztott oldalra, az új szegmens mérete n<n_< vagy n−n<−n=n - n_< - n_=, és kk frissítése; (4) ismétlés. A pivot kiválasztása döntő fontosságú. A legegyszerűbb megoldás a tömb első eleme, de ez rendezett vagy részben rendezett bemenet esetén O(n2)O(n^2)-es viselkedéshez vezethet (helyben particionáló, sorrendtartó változatnál; az itt vázolt atomikus tömörítés a sorrendet futásonként keveri, így ez a laborban nem feltétlenül jelentkezik). A GPU-n a host és a device közötti adatmozgatás költsége miatt a véletlen pivot kiválasztása sem triviális. A gyakorlatban két megoldás terjedt el:

  • Minta mediánja: a device-on kiválasztunk egy kis mintát (pl. 32 elemet), és annak mediánját használjuk pivotként. A minta egyetlen kernelhívással kiválasztható, a medián kiszámítható például egy kis rendezéssel a shared memory-ban.
  • Determinisztikus pivot: ha a bemenetről tudjuk, hogy közel egyenletes eloszlású, használhatunk konstans pivotot, de ez nem általános.

A quickselect GPU-s verziója tehát egy host-oldali ciklusból áll, amely minden iterációban meghívja a számláló és tömörítő kerneleket, majd kk alapján eldönti a következő lépést. Az algoritmus átlagos munkaigénye O(n)O(n), de a gyakorlatban a szinkronizáció (a számlálók visszamásolása) és a kernelindítási késleltetés miatt gyakran lassabb, mint a radix select.

17.4.3 Radix select

A radix alapú kiválasztás elkerüli a pivot minőségétől való függést. Az algoritmus a kulcsok bináris reprezentációját dolgozza fel a legmagasabb bittől (MSD – Most Significant Digit) kezdve. Minden iterációban a jelenlegi szegmens elemeire hisztogramot készítünk a következő 8 bitre (256 bucket), majd a kk rang alapján kiválasztjuk azt a bucketet, amelybe a keresett elem tartozik. A következő iterációban csak az ebbe a bucketbe eső elemekkel dolgozunk tovább.

Egy iteráció lépései:

  1. Hisztogram készítése: a szegmens minden elemére kiszámítjuk a következő 8 bit értékét (biteltolással és maszkkal). A hisztogramot standard módon blokkonként shared memory-ban (256 bin) építjük, majd a blokk a saját 256 számlálóját egyetlen menetben, blokkonként 256 globális atomicAdd-del adja hozzá a globális hisztogramhoz. A szegmens mérete (több blokk) ezt nem zárja ki; a globális atomi műveletek száma így csak a blokkok számától függ, nem az elemek számától. Erősen torz eloszlásnál (sok azonos bucket) a shared memory-s atomok azonos címre sorosítódnak; ez warp-aggregációval enyhíthető.

  2. Prefix összeg (exkluzív scan): a hisztogramon végzett exkluzív scan megadja az egyes bucketek kezdő indexeit a szegmensen belül. 256 elemnél ez a hoston is elvégezhető (a hisztogramot úgyis vissza kell másolni a célbucket kiválasztásához), nagyobb bucketszámnál device-oldali scan (például cub::DeviceScan::ExclusiveSum) indokolt.

  3. Bucket kiválasztása: a kk rangot összehasonlítjuk a kumulált számlálókkal. Ha a kk-adik elem az ii-edik bucketbe esik (azaz a prefix[ii] ≤k<\le k < prefix[ii] + hist[ii]), a következő iterációban a célbucket ii, az új szegmens mérete hist[ii], és a kk rangot prefix[ii]-vel csökkentjük.

  4. Szűkítés (tömörítés): az aktuális szegmensből a célbucket elemeit egy új, hist[ii] méretű tömbbe másoljuk úgy, hogy azok összefüggően helyezkedjenek el. Minden szál a saját elemét megvizsgálja, és csak ha a bucketindexe megegyezik a célbucket indexével, a globális számláló atomicAdd-jával kapott pozícióba írja. A kiválasztáshoz az elemek sorrendje nem számít, ezért a stabilitás nem követelmény. A legutolsó (legalacsonyabb helyiértékű) bájt után szűkítésre nincs szükség.

A folyamat 32 bites kulcsoknál legfeljebb 4 iterációt (hisztogram-menetet) tartalmaz; a keresett érték a kiválasztott bucketindexekből áll össze (a bucketindexek maguk a kulcs bájtjai), nem kell a szegmensből kiolvasni. Az alábbi ábra egy teljes lefutást mutat 16 bites kulcsokon (két menet).

Az MSD radix select GPU-s megvalósításának kernelei 32 bites, előjel nélküli egész kulcsokra (nem fordított, nem futtatott vázlat):

// CUDA C++ (C++17, sm_80) – nem fordított, nem futtatott vázlat
// Radix select hisztogram kernel: 8 bites bucketek, blokkonkénti shared memory hisztogram.
// d_keys: a jelenlegi szegmens elemei; d_hist: 256 elemű globális hisztogram (nullázva);
// bit_offset: 24, 16, 8, 0; n: a jelenlegi szegmens mérete.
// A szegmensbe már csak az előző bájtok célbucketjeibe eső elemek kerülnek.
__global__ void radixHistogramKernel(const unsigned int* d_keys,
                                     unsigned int* d_hist,
                                     int bit_offset, int n) {
    __shared__ unsigned int s_hist[256];
    for (int i = threadIdx.x; i < 256; i += blockDim.x) s_hist[i] = 0;
    __syncthreads();

    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        unsigned int bucket = (d_keys[idx] >> bit_offset) & 0xFF;
        atomicAdd(&s_hist[bucket], 1u);
    }
    __syncthreads();

    for (int i = threadIdx.x; i < 256; i += blockDim.x) {
        if (s_hist[i] != 0) atomicAdd(&d_hist[i], s_hist[i]);   // blokkonként legfeljebb 256 globális atomi
    }
}

// Szűkítő kernel: csak a célbucket elemeit írja a d_out[0 .. bucket_size-1] tartományba.
// d_counter: egyetlen unsigned int, a hívás előtt 0-ra nullázva.
__global__ void radixFilterKernel(const unsigned int* d_keys, unsigned int* d_out,
                                  unsigned int* d_counter,
                                  int bit_offset, unsigned int target_bucket, int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        unsigned int key = d_keys[idx];
        if (((key >> bit_offset) & 0xFF) == target_bucket) {
            unsigned int pos = atomicAdd(d_counter, 1u);   // pos < bucket_size
            d_out[pos] = key;
        }
    }
}

A host-oldali ciklus:

// CUDA C++ (C++17, sm_80) – nem fordított, nem futtatott vázlat
// Előfeltétel: 0 <= k < n; a CUDA_CHECK makró a laborforrás 1. részében (lásd lent) van definiálva.
unsigned int radixSelectGPU(const unsigned int* d_input, unsigned int k,
                            int n, cudaStream_t stream) {
    const unsigned int* d_current = d_input;      // az aktuális szegmens
    int current_n = n;
    unsigned int current_k = k;
    unsigned int result = 0;

    unsigned int* d_hist = nullptr;
    unsigned int* d_counter = nullptr;
    CUDA_CHECK(cudaMalloc(&d_hist, 256 * sizeof(unsigned int)));
    CUDA_CHECK(cudaMalloc(&d_counter, sizeof(unsigned int)));

    for (int byte_idx = 3; byte_idx >= 0; --byte_idx) {
        const int bit_offset = byte_idx * 8;
        const int block = 256;
        const int grid = (current_n + block - 1) / block;

        // 1. Hisztogram.
        CUDA_CHECK(cudaMemsetAsync(d_hist, 0, 256 * sizeof(unsigned int), stream));
        radixHistogramKernel<<<grid, block, 0, stream>>>(d_current, d_hist, bit_offset, current_n);
        CUDA_CHECK(cudaGetLastError());

        // 2-3. A 256 elemű hisztogram a hostra kerül; a prefix összeg és a célbucket ott számolható.
        unsigned int h_hist[256];
        CUDA_CHECK(cudaMemcpyAsync(h_hist, d_hist, sizeof(h_hist),
                                   cudaMemcpyDeviceToHost, stream));
        CUDA_CHECK(cudaStreamSynchronize(stream));

        int target_bucket = -1;
        unsigned int prefix = 0;                  // az aktuális bucket kezdő indexe
        for (int b = 0; b < 256; ++b) {
            if (current_k < prefix + h_hist[b]) { target_bucket = b; break; }
            prefix += h_hist[b];
        }
        if (target_bucket < 0) {                  // csak hibás k vagy n esetén fordulhat elő
            fprintf(stderr, "radixSelectGPU: ervenytelen k\n");
            exit(EXIT_FAILURE);
        }
        current_k -= prefix;
        const int bucket_size = static_cast<int>(h_hist[target_bucket]);
        result |= static_cast<unsigned int>(target_bucket) << bit_offset;

        if (byte_idx == 0) break;                 // a kulcs minden bájtja ismert

        // 4. Szűkítés: a célbucket elemeinek tömörítése új szegmensbe.
        unsigned int* d_next = nullptr;
        CUDA_CHECK(cudaMalloc(&d_next, bucket_size * sizeof(unsigned int)));
        CUDA_CHECK(cudaMemsetAsync(d_counter, 0, sizeof(unsigned int), stream));
        radixFilterKernel<<<grid, block, 0, stream>>>(
            d_current, d_next, d_counter, bit_offset,
            static_cast<unsigned int>(target_bucket), current_n);
        CUDA_CHECK(cudaGetLastError());
        CUDA_CHECK(cudaStreamSynchronize(stream));  // d_current felszabadítása előtt

        if (d_current != d_input) CUDA_CHECK(cudaFree(const_cast<unsigned int*>(d_current)));
        d_current = d_next;
        current_n = bucket_size;
    }

    if (d_current != d_input) CUDA_CHECK(cudaFree(const_cast<unsigned int*>(d_current)));
    CUDA_CHECK(cudaFree(d_hist));
    CUDA_CHECK(cudaFree(d_counter));
    return result;
}

A kód egyszerűsített, de a fő gondolatot mutatja: a host ciklusban irányítjuk az iterációkat, minden lépésben hisztogramot és prefix összeget számolunk, kiválasztjuk a célbucketet és szűkítjük a szegmenst. Ismétlődő kulcsoknál a szegmens nem feltétlenül szűkül jelentősen (az utolsó bájt után az összes megmaradó elem azonos kulcsú), de az eredmény így is helyes. A valós implementációban a hisztogramot warp-aggregációval és a pufferek előzetes foglalásával (ping-pong) érdemes gyorsítani; a cudaMalloc iterációnkénti hívása itt az egyszerűség kedvéért szerepel. Könyvtári alternatíva: cub::DeviceRadixSort::SortKeys után a kk-adik elem kiolvasása.

17.4.4 Pontosság és teljesítmény

A kiválasztási feladat pontossága a kulcsok összehasonlításának helyességétől függ. Mivel az algoritmus nem végez lebegőpontos aritmetikát a kulcsokon, a pontossági modell egyszerű: ha a bemeneti kulcsok egész számok vagy IEEE-754 lebegőpontos számok, a végeredmény az értéket tekintve megegyezik a CPU referencia std::nth_element által adott értékkel, feltéve, hogy a kulcsok rendezése ekvivalens. Lebegőpontos kulcsoknál ügyelni kell a speciális értékekre. A radix select a kulcsokat unsigned bitmintaként kezeli, ezért a float értékeket előbb monoton, rendezhető unsigned kulccsá kell alakítani, ugyanazzal a transzformációval, mint a radix sortnál:

// u = __float_as_uint(f); key = u ^ ((u >> 31) ? 0xFFFFFFFFu : 0x80000000u);
// Visszaalakítás: u = key ^ ((key >> 31) ? 0x80000000u : 0xFFFFFFFFu); f = __uint_as_float(u);

(a pozitív számoknál az előjelbit átbillentése, a negatívaknál minden bit negálása adja azt, hogy a kulcsok egész-rendezése a float rendezését követi). A különleges értékek:

  • NaN: nem rendezhető, ezért a bemenetből ki kell zárni, vagy előre kanonizálni kell (például egyetlen pozitív NaN bitminta), és definiálni kell, hogy a NaN a rendezési sorrend végén áll (a transzformáció után a pozitív NaN a +inf fölé kerül).
  • ±0: a transzformáció után a -0.0 és a +0.0 különböző kulcsot kap (a -0.0 kisebb). A két érték számértékként egyenlő, ezért a kiválasztott érték numerikusan ugyanaz lehet, de a rang szerinti határon a bitminta (előjel) eltérhet a std::nth_element eredményétől. Ha a nullákat egyenlőként kell kezelni, a transzformáció előtt kanonizálni kell őket (if (f == 0.0f) f = 0.0f;). Teszteljük ±0, ±Inf és NaN elemeket tartalmazó bemenettel is.

A determinizmus szempontjából: ha a hisztogramot atomi műveletekkel készítjük, az összeg nem függ az atomok sorrendjétől, így a hisztogram értékei determinisztikusak; a radix select eredménye (az érték) ezért determinisztikus. A szűkített szegmensben az elemek sorrendje az atomi számláló miatt futásonként eltérhet, de ez az eredményt nem befolyásolja. A quickselect eredménye érték szerint szintén egyértelmű (a háromutas szabály miatt ismétlődő kulcsoknál is); a futás menete (az iterációk száma) a pivotválasztástól és – atomikus tömörítésnél – az ütemezéstől függ, ezért azonos bemeneten is futásonként változhat.

A teljesítmény elemzéséhez a roofline-modell használható. A radix select minden iterációban a teljes aktuális szegmensen dolgozik: olvassa a szegmenst a hisztogramhoz, majd újra a szűkítéshez, és a célbucket elemeit írja. A munka iterációnként O(szegmensméret)O(\text{szegmensméret}). Véletlen, egyenletes eloszlású kulcsoknál a szegmens iterációnként nagyjából 256-od részére szűkül, így az összes munka körülbelül n+n/256+n/2562+…≈nn + n/256 + n/256^2 + \dots \approx n elemhozzáférés-nagyságrend; a legrosszabb esetben (például ha minden kulcs felső bájtja azonos) a szegmens nem szűkül, és az összes munka akár 4n4n. A futásidő tehát az adateloszlástól függ, ezért a méréseket torz eloszlású (azonos felső bájtú, sok duplikátumot tartalmazó) bemenettel is el kell végezni. A quickselect átlagosan O(n)O(n) munkát végez, de az iterációk száma a bemenettől függ, és iterációnként számlálásra, visszamásolásra és szinkronizációra van szükség; a GPU-s verzió a kernelindítási késleltetés és a szinkronizáció miatt gyakran lassabb, mint a radix select. Ez azonban mérendő, nem általánosítható állítás.

A mérési szempontok: rögzíteni kell a bemeneti méretet, a kulcsok eloszlását, a kk értékét, a GPU konfigurációját. A teljesítményt befolyásolja a hisztogram készítésének módja, a szűkítő kernel memória-hozzáférési mintája (a célbucket elemei szórtan, a számláló atomi növelése miatt sorosítva íródnak) és a host–device szinkronizációk száma. A gyakorlatban a cub::DeviceRadixSort::SortKeys után a kk-adik elem kiolvasása sokszor versenyképes a saját radix selecttel, de a cél itt az algoritmus megértése.

17.4.5 Labor: quickselect és radix select

A labor célja, hogy a fenti kernelekre és a radix select host-ciklusra építve elkészítsük a selection_lab.cu programot (három részből áll: fejléc és hibamakró, a fent bemutatott kernelek és radixSelectGPU, majd a quickselect host-ciklusa és a main; lásd lent), és összehasonlítsuk a két GPU-s algoritmust a CPU std::nth_element referenciával. A könyv nem közöl futtatott mérést; az alábbi környezeti és mérési adatok kitöltendő sablonok.

17.4.5.1 Környezet és build

// CUDA C++ (C++17) – selection_lab.cu, 3. rész: quickselect host-ciklus és main
// Háromutas quickselect; pivot: a szegmens első eleme (egyszerű, de mérendő választás).
unsigned int quickSelectGPU(const unsigned int* d_input, unsigned int k,
                            int n, cudaStream_t stream) {
    const unsigned int* d_current = d_input;
    int current_n = n;
    unsigned int current_k = k;
    unsigned int result = 0;

    unsigned int* d_cnt = nullptr;        // [0] = n_less, [1] = n_eq
    unsigned int* d_counter = nullptr;
    CUDA_CHECK(cudaMalloc(&d_cnt, 2 * sizeof(unsigned int)));
    CUDA_CHECK(cudaMalloc(&d_counter, sizeof(unsigned int)));
    const int block = 256;

    while (true) {
        unsigned int pivot = 0;
        CUDA_CHECK(cudaMemcpyAsync(&pivot, d_current, sizeof(pivot),
                                   cudaMemcpyDeviceToHost, stream));
        CUDA_CHECK(cudaStreamSynchronize(stream));

        const int grid = (current_n + block - 1) / block;
        CUDA_CHECK(cudaMemsetAsync(d_cnt, 0, 2 * sizeof(unsigned int), stream));
        countKernel<<<grid, block, 0, stream>>>(d_current, pivot, d_cnt, current_n);
        CUDA_CHECK(cudaGetLastError());
        unsigned int h_cnt[2];
        CUDA_CHECK(cudaMemcpyAsync(h_cnt, d_cnt, sizeof(h_cnt),
                                   cudaMemcpyDeviceToHost, stream));
        CUDA_CHECK(cudaStreamSynchronize(stream));
        const unsigned int n_less = h_cnt[0], n_eq = h_cnt[1];

        if (current_k >= n_less && current_k < n_less + n_eq) {   // a pivot a válasz
            result = pivot;
            break;
        }
        int side, next_n;
        if (current_k < n_less) {
            side = 0;  next_n = static_cast<int>(n_less);
        } else {
            side = 2;  next_n = current_n - static_cast<int>(n_less + n_eq);
            current_k -= n_less + n_eq;
        }

        unsigned int* d_next = nullptr;
        CUDA_CHECK(cudaMalloc(&d_next, next_n * sizeof(unsigned int)));
        CUDA_CHECK(cudaMemsetAsync(d_counter, 0, sizeof(unsigned int), stream));
        compactKernel<<<grid, block, 0, stream>>>(d_current, d_next, d_counter,
                                                  pivot, side, current_n);
        CUDA_CHECK(cudaGetLastError());
        CUDA_CHECK(cudaStreamSynchronize(stream));   // d_current felszabadítása előtt

        if (d_current != d_input) CUDA_CHECK(cudaFree(const_cast<unsigned int*>(d_current)));
        d_current = d_next;
        current_n = next_n;
    }
    if (d_current != d_input) CUDA_CHECK(cudaFree(const_cast<unsigned int*>(d_current)));
    CUDA_CHECK(cudaFree(d_cnt));
    CUDA_CHECK(cudaFree(d_counter));
    return result;
}

using SelectFn = unsigned int (*)(const unsigned int*, unsigned int, int, cudaStream_t);

// 5 warm-up + 20 mért futás, ismétlésenként saját eseménypár; medián és IQR (ms)
static bool bench(const char* name, SelectFn fn, const unsigned int* d_in,
                  unsigned int k, int n, unsigned int ref, cudaStream_t stream) {
    const int WARMUP = 5, REPS = 20;
    cudaEvent_t start, stop;
    CUDA_CHECK(cudaEventCreate(&start));
    CUDA_CHECK(cudaEventCreate(&stop));
    bool ok = true;
    unsigned int got = 0;
    for (int i = 0; i < WARMUP; ++i) got = fn(d_in, k, n, stream);
    std::vector<float> t(REPS);
    for (int i = 0; i < REPS; ++i) {
        CUDA_CHECK(cudaEventRecord(start, stream));
        got = fn(d_in, k, n, stream);
        CUDA_CHECK(cudaEventRecord(stop, stream));
        CUDA_CHECK(cudaEventSynchronize(stop));
        CUDA_CHECK(cudaEventElapsedTime(&t[i], start, stop));
        ok = ok && (got == ref);
    }
    std::sort(t.begin(), t.end());
    const float med = 0.5f * (t[REPS / 2 - 1] + t[REPS / 2]);
    const float iqr = t[3 * REPS / 4] - t[REPS / 4];
    std::printf("%-14s median=%.3f ms IQR=%.3f ms GPU=%u CPU=%u egyezes=%s\n",
                name, med, iqr, got, ref, ok ? "igen" : "NEM");
    CUDA_CHECK(cudaEventDestroy(start));
    CUDA_CHECK(cudaEventDestroy(stop));
    return ok;
}

int main(int argc, char** argv) {
    unsigned long long n_arg = 1ull << 24, k_arg = 0;
    bool k_set = false;
    for (int i = 1; i + 1 < argc; i += 2) {
        if (!std::strcmp(argv[i], "--n")) n_arg = std::strtoull(argv[i + 1], nullptr, 10);
        else if (!std::strcmp(argv[i], "--k")) { k_arg = std::strtoull(argv[i + 1], nullptr, 10); k_set = true; }
    }
    const int n = static_cast<int>(n_arg);
    const unsigned int k = k_set ? static_cast<unsigned int>(k_arg) : static_cast<unsigned int>(n / 2);
    if (n <= 0 || k >= static_cast<unsigned int>(n)) {
        std::fprintf(stderr, "hasznalat: %s [--n N] [--k K], 0 <= K < N\n", argv[0]);
        return EXIT_FAILURE;
    }

    std::mt19937 gen(42);                                   // rögzített seed
    std::vector<unsigned int> h(n);
    for (auto& v : h) v = gen();

    std::vector<unsigned int> tmp(h);                       // CPU referencia
    auto c0 = std::chrono::steady_clock::now();
    std::nth_element(tmp.begin(), tmp.begin() + k, tmp.end());
    auto c1 = std::chrono::steady_clock::now();
    const unsigned int ref = tmp[k];
    std::printf("n=%d k=%u CPU nth_element: %u (egyetlen futas: %.3f ms, nem protokoll szerinti mérés)\n",
                n, k, ref, std::chrono::duration<double, std::milli>(c1 - c0).count());

    unsigned int* d_in = nullptr;
    CUDA_CHECK(cudaMalloc(&d_in, n * sizeof(unsigned int)));
    CUDA_CHECK(cudaMemcpy(d_in, h.data(), n * sizeof(unsigned int), cudaMemcpyHostToDevice));
    cudaStream_t stream;
    CUDA_CHECK(cudaStreamCreate(&stream));

    bool ok = bench("radix select", radixSelectGPU, d_in, k, n, ref, stream);
    ok = bench("quickselect", quickSelectGPU, d_in, k, n, ref, stream) && ok;

    CUDA_CHECK(cudaStreamDestroy(stream));
    CUDA_CHECK(cudaFree(d_in));
    return ok ? 0 : 1;
}

Az 5. lépéshez torz bemenetet (sok duplikátum, azonos felső bájt, rendezett) a gen() értékeinek átalakításával lehet kipróbálni, például v = 0xAB000000u | (gen() & 0xFFu) (azonos felső bájt) vagy v = gen() % 10 (sok duplikátum).

17.4.5.3 A program felépítése

  1. Véletlenszerű 32 bites egész kulcsok generálása a hoston, rögzített seeddel.
  2. A CPU referencia kiszámítása std::nth_element-tel.
  3. A GPU-s radix select futtatása a fent bemutatott MSD algoritmussal.
  4. A GPU-s quickselect futtatása a háromutas particionálással (pivot: a szegmens első eleme az egyszerűség kedvéért; mivel a compactKernel atomikus pozíciókra ír, a szűkített szegmens sorrendje futásonként változik, így az első elem a második iterációtól gyakorlatilag véletlen pivot – a rendezett bemenet ezért itt nem okoz O(n2)O(n^2)-es viselkedést, az iterációszám viszont futásonként eltérhet; ezt a mérési naplóban rögzítsük).
  5. Az eredmények összehasonlítása és a futási idők mérése. Az egyezést mindkét GPU-s eredményre ellenőrizni kell, beleértve a sok duplikátumot tartalmazó, a rendezett és a torz eloszlású bemenetet is.

A mérési protokoll a könyv szerinti: 5 warm-up, majd 20 mért futás cudaEvent-ekkel; a mediánt és az IQR-t rögzítjük. A hibakezelés CUDA_CHECK makróval történik.

17.4.5.4 Mérési napló (sablon)

17.4.6 Összegzés

A kk-adik elem és a medián GPU-s kiválasztása két fő úton valósítható meg: a pivot alapú quickselect és a radix select. A quickselect rugalmas, de a szinkronizáció és a pivot minősége miatt GPU-n gyakran kevésbé hatékony, míg a radix select korlátos lépésszámmal (32 bites kulcsnál legfeljebb 4 menet) és jól párhuzamosítható lépésekkel rendelkezik; a futásidő az eloszlástól függ. A radix select a hisztogramok determinizmusa miatt az eredményt tekintve determinisztikus; lebegőpontos kulcsoknál a bitminta átalakítására, a ±0 és a NaN kezelésére ügyelni kell. A következő alfejezetek a stencil-alapú műveleteket tárgyalják, ahol a térbeli lokalitás és a halo-csere lesz a hangsúly.

17.4.7 Önellenőrző kérdés

Miért lehet a radix select gyakran gyorsabb a GPU-n, mint a quickselect, annak ellenére, hogy a quickselect átlagosan kevesebb munkát végez? Válaszában térjen ki a szinkronizáció, a determinizmus és a memória-hozzáférés szerepére.

Válaszvázlat: a radix select korlátos számú (legfeljebb 4) hisztogram-menettel jár, kevés host–device szinkronizációval, a quickselect iterációszáma és szinkronizációja a pivottól függ; a hisztogram összege atomok mellett is determinisztikus; a szűkítő kernel szórtan ír, ezért memóriaforgalma nagyobb, mint a tiszta olvasásé, és ezt mérni kell.
