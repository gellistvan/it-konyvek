28.1 JAX alapok és a funkcionális modell

A JAX programozási modell egyik legfontosabb ígérete, hogy a numerikus kódot függvénytranszformációkkal tehetjük gyorsabbá és differenciálhatóvá anélkül, hogy a magas szintű, NumPy-szerű kifejezésmódot feladnánk. Ebben az alfejezetben a JAX két alapfogalmát, a JAX array-t és a tiszta függvényt használjuk arra, hogy bevezessük a jit (just-in-time fordítás) és a grad (automatikus differenciálás) transzformációkat. A cél nem csupán a szintaxis bemutatása, hanem annak megértése, hogy a funkcionális modell miért teszi lehetővé, hogy ugyanazt a forráskódot különböző hardvereken futtathassuk; az eredmények tűréshatáron belül egyeznek, de a JAX nem garantál bitazonos eredményt eltérő hardveren (kerekítési és algoritmus-választási különbségek).

28.1.1 A JAX array: eszközfüggetlen tömb, XLA háttérrel

A JAX központi adatszerkezete a jax.Array. Első ránézésre nagyon hasonlít a NumPy ndarray-hoz: többdimenziós, elemenkénti műveleteket támogat, és a legtöbb NumPy-függvény elérhető a jax.numpy modulon keresztül. Egy lényeges különbség azonban azonnal szembetűnik: a jax.Array immutábilis. Nem módosítható helyben, mint egy NumPy tömb; minden művelet új tömböt ad vissza. Ez a funkcionális tisztaság alapja.

# Python / JAX 0.4.x minta (nem futtatott; a típus- és eszközkiírás verziófüggő)
import jax
import jax.numpy as jnp

x = jnp.arange(10, dtype=jnp.float32)
print(isinstance(x, jax.Array))  # True (a konkrét osztály, pl. ArrayImpl, verziófüggő)
print(x.devices())      # pl. {CudaDevice(id=0)}; a régi x.device() elavult

# Az alábbi sor hibát dob, mert a JAX array immutable:
# x[0] = 5.0

# Helyette:
y = x.at[0].set(5.0)    # új tömböt ad vissza
print(y[0])             # 5.0
print(x[0])             # 0.0, az eredeti változatlan

A jax.Array mögött az XLA (Accelerated Linear Algebra) fordító áll. A JAX a Python-függvényt trace-eléssel először jaxpr közbülső reprezentációra, majd StableHLO/HLO gráfra képezi le; az XLA ezt optimalizálja és gépi kódra fordítja a céleszközre (lánc: Python → jaxpr → StableHLO/HLO → XLA gépi kód). Ez a céleszköz lehet CPU, GPU vagy TPU. Az eszközt a tömb létrehozásakor vagy a jax.device_put függvénnyel választhatjuk meg:

cpu_x = jax.device_put(x, jax.devices("cpu")[0])
gpu_x = jax.device_put(x, jax.devices("gpu")[0])

A JAX nem lusta: jit nélkül az egyes műveletek azonnal elindulnak, de aszinkron dispatch-csel azonnal vissza is térnek (a NumPy szinkron), így az eredmény a block_until_ready()-ig vagy az adat tényleges eléréséig (pl. kiírás, np.asarray) nem biztos, hogy kész. Ez a trace-eléstől független fogalom: a számítási gráf a jit trace-elése során épül fel, és az XLA ezt az egész függvényt optimalizálja.

28.1.2 Tiszta függvények: a transzformációk előfeltétele

A JAX funkcionális modelljének sarokköve a tiszta függvény fogalma. Egy függvény akkor tiszta, ha:

  1. Ugyanarra a bemenetre mindig ugyanazt a kimenetet adja (determinisztikus).
  2. Nincsenek mellékhatásai: nem módosít globális állapotot, nem ír fájlba, nem végez I/O-t, nem változtatja meg a bemeneti objektumokat.

A JAX transzformációi, mint a jit, a grad, a vmap vagy a pmap, csak tiszta függvényeken értelmezhetők. Ennek oka, hogy a transzformáció során a JAX nyomkövetést (tracing) végez: a függvényt szimbolikus bemenetekkel hívja meg, hogy felépítse a számítási gráfot. Ha a függvény mellékhatásoktól függ, a nyomkövetés eredménye nem lesz egyértelmű, és a lefordított kód hibásan viselkedhet.

Tekintsünk egy egyszerű példát:

# Nem tiszta függvény – mellékhatás: globális lista módosítása
log = []
def impure_square(x):
    log.append(x)
    return x * x

# Tiszta függvény – nincs mellékhatás, csak a bemenetből számol
def pure_square(x):
    return x * x

A JAX dokumentációja és a gyakorlat azt javasolja, hogy minden JAX-szal transzformált függvény tiszta legyen. Ha mellékhatásra van szükség, azt a transzformált függvényen kívül kell kezelni, például a Python-vezérlésben.

28.1.3 A jit transzformáció: XLA-fordítás és gyorsítás

A jax.jit egy függvénytranszformáció: bemenete egy tiszta függvény, kimenete egy olyan függvény, amely ugyanazt számolja, de a híváskor az XLA segítségével lefordítja és optimalizálja a kódot. Az első hívás fordítási költséggel jár, a további hívások a gyorsított verziót használják.

import jax
import jax.numpy as jnp

def slow_f(x):
    return jnp.sum(jnp.sin(x) * jnp.cos(x))

fast_f = jax.jit(slow_f)

x = jnp.arange(1_000_000, dtype=jnp.float32)

import time

def timed(f, *args):
    t0 = time.perf_counter()
    f(*args).block_until_ready()   # aszinkron dispatch miatt kötelező
    return time.perf_counter() - t0

print("eager     :", timed(slow_f, x))  # jit nélküli út
print("jit, 1.   :", timed(fast_f, x))  # fordítási idő + futás
print("jit, 2.   :", timed(fast_f, x))  # már a lefordított kód futása
# (nem futtatott példa; a kiírt idők gépfüggők, a jit 1. hívása tartalmazza a fordítást)

A jit a Python-függvényt trace-eli. A nyomkövetés során a JAX a bemeneti jax.Array-eket absztrakt helyőrzőkkel helyettesíti, és minden NumPy-szerű műveletet rögzít a HLO gráfba. A Python-vezérlési szerkezetek (pl. if, for, while) a nyomkövetés idején kiértékelődnek, tehát a bemeneti értékektől függő (trace-elt) feltételek nem használhatók közvetlenül a jit-elt függvényben. Statikus feltétel (pl. shape-függő, vagy static_argnums/static_argnames argumentum) esetén a Python for/if jól működik (a ciklus kibomlik). Egyébként a JAX saját vezérlési primitívjeit kell használni:

def f(x, flag):
    if flag:                      # Python if – nem trace-elhető
        return x * 2
    else:
        return x * 3

# Helyes megoldás 1: a flag legyen statikus (új érték újrafordítást okoz)
f_static = jax.jit(f, static_argnames=("flag",))

# Helyes megoldás 2: trace-elt flag esetén lax.cond
def f_jit(x, flag):
    return jax.lax.cond(flag, lambda y: y * 2, lambda y: y * 3, x)

A jit hatékonysága abban rejlik, hogy az XLA a teljes függvényt egyetlen optimalizált kernelként vagy kernelcsoportként futtatja, elkerülve a Python-értelmező és a memória-allokációk overheadjét. Emiatt a jit különösen akkor előnyös, ha a függvény sok kis műveletet végez, vagy ha a számítási gráf hosszú.

28.1.4 Pytree és funkcionális transzformációk

A JAX a pytree fogalmát használja a be- és kimeneti adatok strukturálására. A pytree egy Python-adatszerkezet (például lista, tuple, dict, namedtuple, illetve regisztrált dataclass vagy saját osztály – utóbbiak csak jax.tree_util.register_pytree_node / register_dataclass után), amelynek levelei tetszőleges tömb vagy skalár típusúak (jax.Array, NumPy-tömb, Python-skalár). A JAX minden transzformációja – beleértve a jit-et és a grad-et is – képes pytree-kkel dolgozni, így nem kell a paramétereket lapos vektorba rendezni.

Például egy egyszerű lineáris modell paramétereit tárolhatjuk dictben:

params = {
    'W': jnp.array([[1.0, 2.0], [3.0, 4.0]], dtype=jnp.float32),
    'b': jnp.array([0.5, -0.5], dtype=jnp.float32)
}

def predict(params, x):
    return jnp.dot(x, params['W']) + params['b']

x = jnp.array([2.0, 3.0], dtype=jnp.float32)
y = predict(params, x)
print(y)   # [11.5 15.5]  (x·W = [2·1+3·3, 2·2+3·4] = [11, 16], majd + b)

# jit pytree-vel is működik:
jit_predict = jax.jit(predict)
print(jit_predict(params, x))

A jax.tree_util modul segítségével a pytree-ket lapos listává alakíthatjuk, vagy visszaállíthatjuk őket. Ez hasznos a paraméterek frissítésénél, például gradiens-ereszkedés közben.

A funkcionális transzformációk általános tulajdonsága, hogy komponálhatók: például jax.jit(jax.grad(f)) először kiszámítja a gradiensfüggvényt, majd lefordítja azt. A JAX lehetővé teszi további transzformációk használatát is, mint a vmap (vektorizálás) és a pmap (több eszközre párhuzamosítás), amelyekkel a következő alfejezet foglalkozik részletesen.

28.1.5 Gradiens és a grad transzformáció

A jax.grad egy másik alapvető funkcionális transzformáció, amely egy skalár kimenetű függvényből számol gradiensfüggvényt. A grad az automatikus differenciálás (autodiff) egy változatát, a reverse-mode-ot használja, amely hatékonyan számítja ki a bemenetek szerinti parciális deriváltakat.

Példa egy egyszerű skalárfüggvényre:

import jax
import jax.numpy as jnp

def f(x):
    return x**3 + 2*x**2 + x

df = jax.grad(f)
x_val = 3.0
print(f(x_val))   # 48.0
print(df(x_val))  # 40.0  (f'(x) = 3x² + 4x + 1 → 3·9 + 4·3 + 1 = 40)

A grad többváltozós függvényekkel is működik, és a kimenet ugyanolyan pytree szerkezetű lesz, mint az argnums által kijelölt (alapértelmezésben az első) argumentum:

def loss(params, x, y_true):
    return jnp.mean((predict(params, x) - y_true) ** 2)

y_true = jnp.array([11.0, 16.0], dtype=jnp.float32)  # példacímke a fenti x-hez

grad_loss = jax.grad(loss)
grads = grad_loss(params, x, y_true)
print(grads['W'])   # kézi számolás: [[1. -1.], [1.5 -1.5]]
print(grads['b'])   # kézi számolás: [0.5 -0.5]

A JAX a jacrev, jacfwd, hessian stb. függvényekkel magasabb rendű deriváltakat is támogat, de ezekre ebben az alfejezetben nincs szükség.

A grad és a jit együttes használata különösen erőteljes: a gradiensszámítás gráfja is lefordítható XLA-ra, így a tanulási lépések nagy sebességgel futnak.

28.1.6 Állapot és véletlenszámok a funkcionális modellben

A tiszta függvények modellje megköveteli, hogy a véletlenszám-generálás is determinisztikus és mellékhatásmentes legyen. A NumPy globális random állapota helyett a JAX explicit kulcsokkal dolgozik. A jax.random.PRNGKey(seed) egy kulcsot hoz létre, amelyet minden véletlenszám-generáló művelet bemenetként kap. A kulcs nem módosul; ha újabb véletlen számokra van szükség, a kulcsot szét kell osztani (split), hogy független alkulcsokat kapjunk.

import jax
import jax.random as jr

key = jr.PRNGKey(42)          # kezdeti kulcs
subkey1, subkey2 = jr.split(key)

x = jr.normal(subkey1, (1000,))
y = jr.normal(subkey2, (1000,))

A kulcsok explicit kezelése biztosítja a reprodukálhatóságot, és lehetővé teszi, hogy a véletlenszám-generáló függvények is tiszták legyenek, így jit-telhetők és grad-elhetők (bár a gradiens a véletlen műveleteken általában nem értelmes).

A következő példa egy tipikus minta, amelyben a paraméterek frissítése is funkcionálisan történik:

def train_step(params, x, y, lr):
    grads = jax.grad(loss)(params, x, y)
    new_params = jax.tree_util.tree_map(
        lambda p, g: p - lr * g, params, grads)
    return new_params

Itt nincs globális állapot: minden lépés új paraméter-pytree-t ad vissza.

28.1.7 Gyakori hibák és helyes megoldások

A JAX funkcionális modelljének megértése során a kezdők több tipikus hibába ütközhetnek. Ezeket érdemes előre ismerni.

28.1.7.1 In-place mutáció

A JAX array immutable, ezért bármilyen közvetlen elem-hozzárendelés hibát dob. A helyes megoldás a .at[...].set(...) használata, amely új tömböt ad vissza.

# Hibás:
x = jnp.zeros(10)
# x[0] = 1.0   # TypeError: JAX arrays are immutable ... (az üzenet verziófüggő)

# Helyes:
x = x.at[0].set(1.0)

28.1.7.2 Python-vezérlési szerkezetek adatfüggő feltételekkel a jit-ben

Ahogy korábban említettük, a jit-elt függvényben a Python if nem láthatja a bemeneti adat értékét, mert a nyomkövetés során az absztrakt. A megoldás a jax.lax.cond, jax.lax.select, jax.numpy.where vagy ciklusok esetén jax.lax.scan használata.

def f(x):
    if x > 0:          # hibás jit alatt
        return x
    else:
        return 0.0

# Helyes:
def f_jit(x):
    return jax.lax.cond(x > 0, lambda y: y, lambda y: 0.0, x)

28.1.7.3 Globális random állapot

A numpy.random globális, rejtett állapotot használ (mellékhatás), és jit alatt csak a trace idején fut le: az eredmény konstansként beég a lefordított függvénybe, így minden hívás ugyanazt a „véletlen” számot kapja. Mindig jax.random.PRNGKey-t (vagy jax.random.key-t) és explicit kulcsmenedzsmentet használjunk.

28.1.7.4 A fordítási idő figyelmen kívül hagyása

Az első jit-hívás fordítási költsége jelentős lehet. A méréseknél mindig végezzünk bemelegítő hívást (warm-up), és a mérési időt a második hívástól számoljuk. Ez analóg a CUDA-kernelek mérésénél alkalmazott warm-up gyakorlattal.

28.1.7.5 A tiszta függvény megsértése mellékhatásokkal

Ha a jit-elt függvény Python-szintű mellékhatást végez (például nyomtat, listát módosít, fájlba ír), a mellékhatás csak trace-időben, egyszer fut le; a lefordított függvény a további hívásokon már nem ismétli, ezért a viselkedés félrevezető, a hibakeresés nehézkes.

@jax.jit
def noisy(x):
    print("trace:", x)               # csak az első híváskor (trace-kor) ír ki
    jax.debug.print("érték: {}", x)  # minden híváskor kiír (futásidejű)
    return x * 2

noisy(1.0); noisy(2.0)   # a `trace:` sor csak egyszer jelenik meg

A mellékhatásokat tartsuk a transzformált függvényen kívül, vagy használjunk jax.debug.print-et.

A következő labor célja, hogy a fenti fogalmakat egy ellenőrizhető, mérhető példán keresztül gyakoroljuk. 28.1.8.2 Forráskód

A következő kódblokk JAX/Python, és a laborban izolált környezetben fut.

# JAX 0.4.x, Python 3.10
import jax
import jax.numpy as jnp
import time

# Modell: logisztikus regresszió
def predict(params, x):
    return jax.nn.sigmoid(jnp.dot(x, params['w']) + params['b'])

def loss(params, x, y):
    p = predict(params, x)
    return -jnp.mean(y * jnp.log(p + 1e-8) + (1 - y) * jnp.log(1 - p + 1e-8))

# Bemeneti adatok: 4 dimenziós jellemzők, 100 minta
key = jax.random.PRNGKey(42)
key_w, key_x, key_y = jax.random.split(key, 3)

w_true = jax.random.normal(key_w, (4,))
b_true = jnp.array(0.1, dtype=jnp.float32)

x_data = jax.random.normal(key_x, (100, 4))
logits = jnp.dot(x_data, w_true) + b_true
y_data = (logits > 0.0).astype(jnp.float32)

params = {
    'w': jnp.zeros(4, dtype=jnp.float32),
    'b': jnp.array(0.0, dtype=jnp.float32)
}

# Gradiens és jit
grad_loss = jax.grad(loss)
jit_grad_loss = jax.jit(grad_loss)

# Analitikus várt gradiens (w=0, b=0 → p = 0,5)
p0 = jax.nn.sigmoid(jnp.dot(x_data, params['w']) + params['b'])
grad_w_ref = ((p0 - y_data)[:, None] * x_data).mean(axis=0)
grad_b_ref = (p0 - y_data).mean()

import statistics

# Warm-up: 5 hívás
for _ in range(5):
    jax.block_until_ready(jit_grad_loss(params, x_data, y_data))

# Mérés: 20 ismétlés
times = []
grads = None
for _ in range(20):
    start = time.perf_counter()
    grads = jit_grad_loss(params, x_data, y_data)
    jax.block_until_ready(grads)
    end = time.perf_counter()
    times.append(end - start)

# Eager (jit nélküli) összehasonlító mérés ugyanazokkal a bemenetekkel
for _ in range(5):  # warm-up
    jax.block_until_ready(grad_loss(params, x_data, y_data))
times_eager = []
for _ in range(20):
    start = time.perf_counter()
    g_e = grad_loss(params, x_data, y_data)
    jax.block_until_ready(g_e)
    times_eager.append(time.perf_counter() - start)
med_eager = statistics.median(times_eager)

q1, _, q3 = statistics.quantiles(times, n=4)
med_time = statistics.median(times)
iqr_time = q3 - q1

print(f"Medián futásidő: {med_time:.6f} s")
print(f"IQR: {iqr_time:.6f} s")
print(f"Gradiens w: {grads['w']}")
print(f"Gradiens b: {grads['b']}")
print(f"Eager medián: {med_eager:.6f} s, "
      f"eager/jit arány (mediánokból): {med_eager / med_time:.2f}")
print(f"max |eltérés| w: {jnp.max(jnp.abs(grads['w'] - grad_w_ref)):.3e}")
print(f"|eltérés| b:     {jnp.abs(grads['b'] - grad_b_ref):.3e}")

28.1.8.3 Várt eredmény (analitikus gradiens)

A logisztikus regresszió veszteségfüggvényének gradiense a paramétervektor szerint:

∇𝐰L=1N∑i=1N(pi−yi)𝐱i \nabla_{\mathbf{w}} L = \frac{1}{N} \sum_{i=1}^{N} (p_i - y_i) \mathbf{x}_i ∇bL=1N∑i=1N(pi−yi) \nabla_{b} L = \frac{1}{N} \sum_{i=1}^{N} (p_i - y_i)

ahol pi=σ(𝐰⊤𝐱i+b)p_i = \sigma(\mathbf{w}^\top \mathbf{x}_i + b).

A JAX által számított gradiensnek közelítenie kell ezt az értéket. A várt gradiens a kezdeti paraméterekkel (w=0, b=0) számolva:

pi=σ(0)=0,5 p_i = \sigma(0) = 0{,}5 Így pi−yi=0,5−yip_i - y_i = 0{,}5 - y_i. A gradiens tehát a jellemzők és a címkék lineáris kombinációja. Pontos értéke függ a generált véletlen adatoktól, de a laborban a mért és a várt (analitikus) értéket össze kell hasonlítani, például relatív hibával.

28.1.8.4 Mért eredmény (nincs futtatva, kitöltendő)

Nem futtatott mérés – helyőrző. A fenti kódot ebben a könyvben nem futtattuk, ezért nincs mért érték; a kimenet formátuma:

Medián futásidő: <mért – kitöltendő> s
IQR: <mért – kitöltendő> s
Gradiens w: <mért – kitöltendő>
Gradiens b: <mért – kitöltendő>
Eager medián: <mért – kitöltendő> s, eager/jit arány (mediánokból): <mért – kitöltendő>
max |eltérés| w: <mért – kitöltendő>
|eltérés| b:     <mért – kitöltendő>

A mért és az analitikus gradiens eltérését a kód kiírja. Várakozás (nem mért): a float32 kerekítés és a log-ban szereplő 10−810^{-8} epszilon miatt az eltérés legfeljebb 10−710^{-7} nagyságrendű (a relatív gépi epszilon float32-ben ≈1,2⋅10−7\approx 1{,}2 \cdot 10^{-7}), gyakran kisebb; elfogadási küszöbnek például atol = 1e-6 megfelelő.

28.1.8.5 Értelmezés

A jit hatására a függvény futásideje a Python-eager verzióhoz képest sok elemi műveletet végző függvénynél csökkenhet. A kód az eager és a jit-elt időt is méri, és kiírja az arányukat. Ilyen kis feladatnál (100×4 adat) a különbség nem feltétlenül jelentős, és a mért érték hiányában gyorsulást nem állítunk; nagyobb méreteknél a nyereség méréssel igazolandó.

28.1.9 Összefoglalás és továbbvezetés

Ebben az alfejezetben bevezettük a JAX funkcionális modelljének alapelemeit:

  • A JAX array immutábilis, eszközfüggetlen tömb, amelyet az XLA fordít.
  • A tiszta függvények determinisztikusak és mellékhatásmentesek, ami a transzformációk előfeltétele.
  • A jit a függvényt XLA-gráffá fordítja, és sok elemi műveletet végző függvénynél csökkentheti a futásidőt (méréssel igazolandó).
  • A pytree lehetővé teszi, hogy a függvények összetett Python-adatszerkezetekkel dolgozzanak, és a transzformációk is kezeljék ezeket.
  • A grad automatikus differenciálással számolja a gradiensfüggvényt.
  • Az állapot és véletlenszámok explicit kulcsokkal kezelhetők, megőrizve a tisztaságot.

A következő alfejezetben (28.2) a vmap, a pmap és a sharding (több eszközre osztás) fogalmait építjük erre az alapra, hogy a JAX kódot több GPU-ra vagy TPU-ra skálázzuk. Az itt megismert funkcionális szemlélet és a pytree-kezelés elengedhetetlen lesz a haladó témákhoz.

Önellenőrző kérdés: Miért nem módosítható a JAX array helyben, és hogyan oldanád meg egy tömb első elemének megváltoztatását funkcionálisan? Válasz: az immutábilitás biztosítja a tiszta függvényeket és a transzformációk konzisztenciáját; a .at[0].set(érték) egy új tömböt ad vissza.
