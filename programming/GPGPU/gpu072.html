19.3 SpMV és sparse optimalizálás

A sparse mátrix-vektor szorzás (SpMV) a ritka lineáris algebra sarokköve: iteratív megoldók, PageRank, spektrális klaszterezés, végeselem-módszerek és számos tudományos kód minden iterációja legalább egy SpMV-t végez. A dense GEMM-mel ellentétben az SpMV memória-kötött, szabálytalan hozzáférési mintájú, és a teljesítménye erősen függ a mátrix nemnulla szerkezetétől. Ebben az alfejezetben a CSR-reprezentáció feletti alapvető kernelektől a terheléskiegyensúlyozatlanság kezelésén át a cuSPARSE könyvtári megoldásig jutunk el, és egy teljes mérési labort építünk fel.

19.3.1 Az SpMV definíciója és költségmodellje

Az SpMV az y=Axy = A x műveletet számítja, ahol A∈ℝn×nA \in \mathbb{R}^{n \times n} ritka, x,y∈ℝnx,y \in \mathbb{R}^n. A ritkaságot a nemnulla elemek számával, nnz\mathrm{nnz}-vel jellemezzük. A művelet aritmetikai költsége 2nnz2\, \mathrm{nnz} lebegőpontos művelet (FLOP), de a tényleges futásidőt a memóriaforgalom dominálja: minden nemnulla elemhez be kell olvasni az értékét és az oszlopindexét, minden sorhoz a sorhatárokat, valamint az xx vektorból a megfelelő elemeket, és ki kell írni az yy vektort. A memóriaforgalom tipikusan 8nnz+4nnz+4(n+1)+8n+8n8\,\mathrm{nnz} + 4\,\mathrm{nnz} + 4(n+1) + 8n + 8n bájt double precízió esetén, ami általában egy nagyságrenddel nagyobb, mint a hasznos aritmetika – ezért az SpMV a memória-sávszélesség-korlátos tartományban van.

Az előző alfejezetben (19.2, ritka mátrixreprezentációk) bevezetett CSR-formátum a legelterjedtebb reprezentáció. Itt a row_ptr tömb hossza n+1n+1, a col_idx és values tömbök hossza nnz\mathrm{nnz}. A soronkénti feldolgozás természetes párhuzamosságot ad, de a sorhosszak szóródása – a ritka mátrixok jellegzetessége – egyenetlen munkamennyiséget okoz a szálak között.

19.3.2 A naiv scalar kernel

A legegyszerűbb CUDA-megvalósítás minden sorhoz egy szálat rendel. A kernel a globális indexszámítást követően a row_ptr határokon belül iterál, és felhalmozza a részletösszeget:

// CUDA C++ (C++17)
__global__ void spmv_csr_scalar(const int* row_ptr,
                                 const int* col_idx,
                                 const double* values,
                                 const double* x,
                                 double* y,
                                 int n)
{
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row < n) {
        double sum = 0.0;
        int start = row_ptr[row];
        int end   = row_ptr[row + 1];
        for (int j = start; j < end; ++j) {
            sum += values[j] * x[col_idx[j]];
        }
        y[row] = sum;
    }
}

A launch konfiguráció: dim3 block(256); dim3 grid((n + block.x - 1) / block.x);, a kernel indítása pedig spmv_csr_scalar<<<grid, block>>>(...). Minden szál pontosan egy sort dolgoz fel, így nincs versenyhelyzet az y írásakor. A memória-hozzáférés a col_idx[j] indirekción keresztül történik, ami az xx vektor véletlenszerű, nem koaleszkált olvasását eredményezi. A values[j] és col_idx[j] tömbök soron belül folytonosak, de a warp szomszédos szálai különböző sorokat dolgoznak fel, tehát egyidejűleg egymástól körülbelül egy sorhossznyi távolságra lévő elemeket olvasnak: ez a hozzáférés nem koaleszkált, függetlenül attól, hogy a szálak milyen ütemben haladnak. Ez a scalar CSR-kernel – a terheléskiegyensúlyozatlanság mellett – fő hátránya; a warp-per-row kernel azért gyorsabb hosszú soroknál, mert ott a warp szálai a sor folytonos elemeit olvassák (a hatás Nsight Compute-ban a gld_efficiency/sector-kihasználtság mutatóval ellenőrizhető).

A kernel fő problémája a terheléskiegyensúlyozatlanság (load imbalance). Ha a sorhosszak eloszlása széles – például egy skálafüggetlen gráf mátrixában néhány sor több ezer nemnulla elemet tartalmaz, míg a legtöbb sor csak néhányat –, akkor a hosszú sorokat feldolgozó szálak sokáig dolgoznak, míg a rövid sorokhoz rendelt szálak befejezik a munkájukat és várakoznak. A GPU ütemezője a warpokat csak akkor vonja ki, ha a warp mind a 32 szála befejezte a kernelét, ezért a leghosszabb sor hossza határozza meg a teljes warp futásidejét. A divergencia mellett a kihasználatlan szálak csökkentik az effektív sávszélességet.

A scalar kernel előnye az egyszerűsége és az alacsony regiszterigénye, ami magas occupancy-t tesz lehetővé. Rövid, egyenletes sorhosszúságú mátrixokon – például sávos mátrixokon, ahol minden sorban 5–7 nemnulla elem van – a kernel elfogadhatóan teljesít, mert a warp minden szála közel azonos munkát végez; a hozzáférés itt sem koaleszkált (a szálak 5–7 elemnyi távolságra olvasnak), de a rövid sorok miatt a szomszédos szálak ugyanazokat a cache-sorokat használják, így az L1 részben kompenzálhat – ennek mértéke mérendő.

19.3.3 A warp-per-row kernel

A hosszú sorok hatékony feldolgozásához egy sort több szálra kell bontani. A warp-per-row stratégia minden sorhoz egy 32 szálból álló warp-ot rendel, a sor nemnulla elemeit pedig a warp szálai ciklikusan osztják el. A részletösszegeket ezután egy warp-szintű redukcióval kombináljuk:

// CUDA C++ (C++17)
__global__ void spmv_csr_warp(const int* row_ptr,
                               const int* col_idx,
                               const double* values,
                               const double* x,
                               double* y,
                               int n)
{
    int warps_per_block = blockDim.x / warpSize;   // warpSize == 32
    int row = blockIdx.x * warps_per_block + (threadIdx.x / warpSize);
    if (row >= n) return;

    int lane = threadIdx.x % warpSize;
    int start = row_ptr[row];
    int end   = row_ptr[row + 1];

    double sum = 0.0;
    for (int j = start + lane; j < end; j += warpSize) {
        sum += values[j] * x[col_idx[j]];
    }

    // Warp-szintű redukció shuffle-lel
    for (int offset = warpSize / 2; offset > 0; offset >>= 1) {
        sum += __shfl_down_sync(0xffffffffu, sum, offset);
    }

    if (lane == 0) {
        y[row] = sum;
    }
}

A launch konfiguráció: dim3 block(256); int rows_per_block = block.x / warpSize; dim3 grid((n + rows_per_block - 1) / rows_per_block);. A kernelben a __shfl_down_sync a warp szálai közötti adatcserét valósítja meg regisztereken keresztül, ami elkerüli a shared memory használatát és a barrier szinkronizációt. A redukció után csak a 0. lane írja az y[row] értéket, így nincs versenyhelyzet.

A warp-per-row kernel lényegesen jobb a hosszú sorokra, mert a nemnulla elemek feldolgozását 32 szál párhuzamosítja, és a values/col_idx tömbök olvasása – a scalar kernellel ellentétben – koaleszkált, mert a warp szálai szomszédos elemeket érnek el. A shuffle-redukció logaritmikus költsége elhanyagolható a soron belüli iterációhoz képest. A kernel hátránya, hogy rövid sorok esetén a warp nagy része tétlen: ha egy sorban csak 3 nemnulla elem van, a 32 szálból 29 nem végez hasznos munkát a ciklusban, és a redukció is pazarló. Ezért a warp-per-row kernel a hosszú sorok dominálta mátrixoknál előnyös, míg a scalar kernel a rövid soroknál.

Az alábbi ábra egy kis, 8 soros mátrixon (sorhosszak 3, 5, 2, 40, 4, 3, 6, 1; nnz = 64) iterációnként mutatja, mely values-elemeket olvassa a két kernel, hány lane tétlen, és hány 32 bájtos szektort érint egy-egy kérés.

19.3.4 Load imbalance és irregularitás

A ritka mátrixok sorhossz-eloszlása gyakran erősen ferde. A valós alkalmazásokban – például szociális hálózatok, webgráfok, vagy adaptív végeselem-hálók – előfordul, hogy a sorok 90%-a kevesebb mint 10 nemnulla elemet tartalmaz, míg a maradék 10% több száz vagy több ezer elemet. A naiv scalar kernel ilyenkor a leghosszabb sor hosszával arányos időt tölt, miközben a legtöbb szál már régen végzett. A warp-per-row kernel ezt részben orvosolja, de a rövid soroknál a warp pazarlása miatt a teljesítmény még mindig messze van a memória-sávszélesség-korláttól.

A terheléskiegyensúlyozatlanság mérésére a sorhossz-szóródás (coefficient of variation) használható: σ/μ\sigma / \mu, ahol μ\mu az átlagos sorhossz, σ\sigma pedig a szórása. Ha ez az érték nagy, akkor a soronkénti párhuzamosítás rosszul teljesít. A megoldás az, hogy a hosszú sorokat több szálra bontjuk, a rövid sorokat pedig soronként egy szállal dolgozzuk fel. Ezt a hibrid megközelítést két külön kernellel valósíthatjuk meg: a host egy előfeldolgozási lépésben szétválogatja a sorokat egy threshold hosszúság szerint, a rövid sorokat a scalar kernel, a hosszú sorokat a warp-per-row kernel dolgozza fel (nem fordított, nem futtatott vázlat):

// CUDA C++ (C++17) – hibrid SpMV két kernellel; a host a hosszú sorok indexlistáját előre
// elkészíti
// (long_rows: azon sorok indexei, amelyekre nnz_row > threshold)

// 1. kernel: rövid sorok, soronként egy szál; a hosszú sorokat kihagyja
__global__ void spmv_csr_short(const int* row_ptr, const int* col_idx,
                               const double* values, const double* x,
                               double* y, int n, int threshold)
{
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row >= n) return;
    int start = row_ptr[row], end = row_ptr[row + 1];
    if (end - start > threshold) return;           // ezt a sort a 2. kernel számolja
    double sum = 0.0;
    for (int j = start; j < end; ++j) sum += values[j] * x[col_idx[j]];
    y[row] = sum;
}

// 2. kernel: hosszú sorok, soronként egy warp
__global__ void spmv_csr_long(const int* row_ptr, const int* col_idx,
                              const double* values, const double* x,
                              double* y, const int* long_rows, int num_long)
{
    int warp = (blockIdx.x * blockDim.x + threadIdx.x) / warpSize;
    if (warp >= num_long) return;                  // a teljes warp egyszerre lép ki
    int lane = threadIdx.x % warpSize;
    int row = long_rows[warp];
    int start = row_ptr[row], end = row_ptr[row + 1];
    double sum = 0.0;
    for (int j = start + lane; j < end; j += warpSize) sum += values[j] * x[col_idx[j]];
    for (int offset = warpSize / 2; offset > 0; offset >>= 1)
        sum += __shfl_down_sync(0xffffffffu, sum, offset);
    if (lane == 0) y[row] = sum;
}
// Indítás: spmv_csr_short<<<(n + 255) / 256, 256>>>(...);
//          spmv_csr_long <<<(num_long * 32 + 255) / 256, 256>>>(...);

Minden sort pontosan egy kernel ír, ezért nincs versenyhelyzet, és kernelen belüli blokk-szintű szinkronizációra sincs szükség. A threshold értékét nem lehet elméletileg rögzíteni: kiindulásként a warpméret nagyságrendje (32) szokásos, de a helyes érték a mátrixtól és a GPU-tól függ, ezért különböző sorhossz-eloszlású mátrixokon cudaEvent-es méréssel kell megállapítani. A fejezet laborja a hibrid kernelt nem méri.

A SELL-C-σ formátum egy másik megoldás: a mátrixot sorblokkokra osztja, és minden blokkban a sorokat a blokk maximális sorhosszára egészíti ki üres helyekkel, majd a blokk sorait oszlopfolytonosan tárolja. Ez a formátum a koaleszkált hozzáférést és a terheléskiegyensúlyozást egyszerre javítja, de a feltöltés miatt extra memóriát igényel. A SELL-C-σ tipikusan a rövid, közel egyenletes sorokat tartalmazó mátrixokon előnyös, míg a CSR hosszú sorokra rugalmasabb; a választást mérés dönti el.

19.3.5 A cuSPARSE könyvtár SpMV API-ja

A CUDA ökoszisztéma a ritka mátrixműveletekhez a cuSPARSE könyvtárat biztosítja. A cuSPARSE a CUDA 11-től kezdve egy generikus API-t kínál, amely a mátrix- és vektorleírók segítségével egységes felületet ad a különböző formátumokhoz. Az SpMV-hez a cusparseSpMV függvény tartozik, amely puffert igényel az előfeldolgozási adatokhoz. Az API használata:

// CUDA C++ (C++17) – cuSPARSE generikus API (CUDA 11+)
#include <cusparse.h>

// CUDA_CHECK: lásd 1.2; CUSPARSE_CHECK: ugyanilyen alakú, `cusparseStatus_t` és
// `cusparseGetErrorString` kiírással
void cusparse_spmv_example(int n, int nnz,
                           int* d_row_ptr, int* d_col_idx, double* d_values,
                           double* d_x, double* d_y)
{
    cusparseHandle_t handle;
    CUSPARSE_CHECK(cusparseCreate(&handle));

    cusparseSpMatDescr_t matA;
    cusparseDnVecDescr_t vecX, vecY;

    // Mátrixleíró: CSR formátum, 32 bites indexek, 0 bázisú indexelés, double
    CUSPARSE_CHECK(cusparseCreateCsr(&matA, n, n, nnz,
                      d_row_ptr, d_col_idx, d_values,
                      CUSPARSE_INDEX_32I, CUSPARSE_INDEX_32I,
                      CUSPARSE_INDEX_BASE_ZERO, CUDA_R_64F));

    // Vektorleírók
    CUSPARSE_CHECK(cusparseCreateDnVec(&vecX, n, d_x, CUDA_R_64F));
    CUSPARSE_CHECK(cusparseCreateDnVec(&vecY, n, d_y, CUDA_R_64F));

    double alpha = 1.0, beta = 0.0;
    size_t bufferSize = 0;
    void* d_buffer = nullptr;

    // Pufferméret lekérdezése
    CUSPARSE_CHECK(cusparseSpMV_bufferSize(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                            &alpha, matA, vecX, &beta, vecY,
                            CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT,
                            &bufferSize));
    CUDA_CHECK(cudaMalloc(&d_buffer, bufferSize));

    // SpMV végrehajtása: y = alpha * A * x + beta * y
    CUSPARSE_CHECK(cusparseSpMV(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                 &alpha, matA, vecX, &beta, vecY,
                 CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT,
                 d_buffer));

    // Takarítás
    CUSPARSE_CHECK(cusparseDestroySpMat(matA));
    CUSPARSE_CHECK(cusparseDestroyDnVec(vecX));
    CUSPARSE_CHECK(cusparseDestroyDnVec(vecY));
    CUSPARSE_CHECK(cusparseDestroy(handle));
    CUDA_CHECK(cudaFree(d_buffer));
}

A cusparseSpMV_bufferSize hívás nélkülözhetetlen: a cuSPARSE a megadott algoritmushoz szükséges munkaterület méretét adja vissza; a puffert a hívó foglalja le, és a cusparseSpMV munkaterületként használja. A CUSPARSE_SPMV_ALG_DEFAULT az alapértelmezett algoritmus; a formátumspecifikus alternatívák (a lektor CUDA 13.0 fejléc-ellenőrzése szerint: CUSPARSE_SPMV_CSR_ALG1/ALG2, CUSPARSE_SPMV_COO_ALG1/ALG2, CUSPARSE_SPMV_SELL_ALG1, CUSPARSE_SPMV_BSR_ALG1) a mindenkori verzióban változhatnak; a nevek a telepített cuSPARSE-dokumentációban ellenőrizendők. A mátrixleírót a formátumnak megfelelően kell létrehozni; CSR-hez a cusparseCreateCsr, COO-hoz a cusparseCreateCoo, BSR-hez a cusparseCreateBsr szolgál. A vektorleírók a sűrű vektorokat reprezentálják.

A cuSPARSE belsőleg több optimalizálást alkalmaz, beleértve a soronkénti feldolgozás adaptív kiválasztását, a memória-hozzáférési minták javítását és a hosszú sorok párhuzamosítását. A gyakorlatban a cuSPARSE SpMV-ja általában jelentősen gyorsabb, mint a naiv kernel, de a teljesítménye erősen függ a mátrix szerkezetétől és a választott formátumtól. A CUDA 12.3-tól elérhető cusparseSpMV_preprocess az előfeldolgozási fázis különválasztását teszi lehetővé (csak bizonyos algoritmusokra), ami ismételt SpMV-knél hasznos lehet; a pontos feltételek a dokumentációban ellenőrizendők.

Fontos verziómegjegyzés: A régi, formátum- és típusspecifikus cuSPARSE API (pl. cusparseDcsrmv) a CUDA 11-ben megszűnt, helyét a generikus API vette át. A fenti példa a CUDA 11+ generikus API-t használja, amely a jelenlegi (CUDA 12.x) verziókban az ajánlott. A pontos függvényszignatúrák és konstansok a cuSPARSE dokumentációban ellenőrizendők, mivel azok verzióról verzióra változhatnak.

// --- Kernelek a korábbi definíciókból ---
__global__ void spmv_csr_scalar(const int* row_ptr, const int* col_idx,
                                 const double* values, const double* x,
                                 double* y, int n)
{
    int row = blockIdx.x * blockDim.x + threadIdx.x;
    if (row < n) {
        double sum = 0.0;
        int start = row_ptr[row];
        int end   = row_ptr[row + 1];
        for (int j = start; j < end; ++j) {
            sum += values[j] * x[col_idx[j]];
        }
        y[row] = sum;
    }
}

__global__ void spmv_csr_warp(const int* row_ptr, const int* col_idx,
                               const double* values, const double* x,
                               double* y, int n)
{
    int warps_per_block = blockDim.x / warpSize;
    int row = blockIdx.x * warps_per_block + (threadIdx.x / warpSize);
    if (row >= n) return;
    int lane = threadIdx.x % warpSize;
    int start = row_ptr[row];
    int end   = row_ptr[row + 1];
    double sum = 0.0;
    for (int j = start + lane; j < end; j += warpSize) {
        sum += values[j] * x[col_idx[j]];
    }
    for (int offset = warpSize / 2; offset > 0; offset >>= 1) {
        sum += __shfl_down_sync(0xffffffffu, sum, offset);
    }
    if (lane == 0) y[row] = sum;
}

// --- CPU referencia ---
void spmv_cpu(const int* row_ptr, const int* col_idx, const double* values,
              const double* x, double* y, int n)
{
    for (int i = 0; i < n; ++i) {
        double sum = 0.0;
        for (int j = row_ptr[i]; j < row_ptr[i + 1]; ++j) {
            sum += values[j] * x[col_idx[j]];
        }
        y[i] = sum;
    }
}

// --- Mátrixgenerátor ---
// imbalance > 0: log-normális sorhosszak. A lognormal(0, s) várható értéke exp(s^2/2),
//   ezért a skálát target / exp(s^2/2)-nek választjuk, hogy az ELVÁRT átlagos sorhossz target
// legyen
//   (a max(1, .) és a kerekítés miatt a tényleges átlag kissé eltérhet; a program kiírja).
// imbalance == 0: sávos mátrix, minden sorban pontosan target elem az átló körül.
void generate_sparse_matrix(int n, int target, double imbalance,
                            std::vector<int>& row_ptr, std::vector<int>& col_idx,
                            std::vector<double>& values, int& nnz)
{
    row_ptr.resize(n + 1);
    std::mt19937 rng(42);
    std::lognormal_distribution<double> dist(0.0, imbalance > 0 ? imbalance : 1.0);
    const double scale = target / std::exp(0.5 * imbalance * imbalance);
    row_ptr[0] = 0;
    for (int i = 0; i < n; ++i) {
        int len = (imbalance > 0) ? std::max(1, (int)std::round(dist(rng) * scale)) : target;
        len = std::min(len, n);
        row_ptr[i + 1] = row_ptr[i] + len;
    }
    nnz = row_ptr[n];
    col_idx.resize(nnz);
    values.resize(nnz);
    std::uniform_int_distribution<int> col_dist(0, n - 1);
    std::uniform_real_distribution<double> val_dist(-1.0, 1.0);
    for (int i = 0; i < n; ++i) {
        int b = row_ptr[i], e = row_ptr[i + 1], len = e - b;
        if (imbalance > 0) {
            // ismétlődés elvileg lehetséges
            for (int j = b; j < e; ++j) col_idx[j] = col_dist(rng);
        } else {
            int c0 = std::min(std::max(i - len / 2, 0), n - len);
            for (int j = b; j < e; ++j) col_idx[j] = c0 + (j - b);
        }
        // soronként rendezett oszlopindexek
        std::sort(col_idx.begin() + b, col_idx.begin() + e);
        for (int j = b; j < e; ++j) values[j] = val_dist(rng);
    }
}

// --- Mérési segédfüggvény: tetszőleges hívható objektummal (lambda), warm-up + reps x iters
// ---
template <typename Launch>
double measure_time(Launch launch, int warmup, int iters, int reps, double* sd_out)
{
    for (int i = 0; i < warmup; ++i) launch();
    CUDA_CHECK(cudaGetLastError());
    CUDA_CHECK(cudaDeviceSynchronize());
    cudaEvent_t start, stop;
    CUDA_CHECK(cudaEventCreate(&start));
    CUDA_CHECK(cudaEventCreate(&stop));
    std::vector<double> t;
    t.reserve(reps);
    for (int r = 0; r < reps; ++r) {
        CUDA_CHECK(cudaEventRecord(start));
        for (int i = 0; i < iters; ++i) launch();
        CUDA_CHECK(cudaEventRecord(stop));
        CUDA_CHECK(cudaEventSynchronize(stop));
        CUDA_CHECK(cudaGetLastError());
        float ms = 0.0f;
        CUDA_CHECK(cudaEventElapsedTime(&ms, start, stop));
        t.push_back(ms / iters);
    }
    CUDA_CHECK(cudaEventDestroy(start));
    CUDA_CHECK(cudaEventDestroy(stop));
    double mean = 0.0, ss = 0.0;                       // mintaszórás két menetben
    for (double x : t) mean += x;
    mean /= reps;
    for (double x : t) ss += (x - mean) * (x - mean);
    *sd_out = std::sqrt(ss / (reps - 1));
    std::sort(t.begin(), t.end());
    return 0.5 * (t[reps / 2 - 1] + t[reps / 2]);     // medián (reps páros)
}

// --- cuSPARSE: a leírók és a puffer a mérési cikluson KÍVÜL jönnek létre, a mérés csak az
// SpMV hívást ismétli ---
struct CusparseSpmv {
    cusparseHandle_t handle{};
    cusparseSpMatDescr_t matA{};
    cusparseDnVecDescr_t vecX{}, vecY{};
    void* d_buffer = nullptr;
    double alpha = 1.0, beta = 0.0;

    void setup(int n, int nnz, int* d_row_ptr, int* d_col_idx, double* d_values,
               double* d_x, double* d_y)
    {
        CUSPARSE_CHECK(cusparseCreate(&handle));
        CUSPARSE_CHECK(cusparseCreateCsr(&matA, n, n, nnz, d_row_ptr, d_col_idx, d_values,
                                         CUSPARSE_INDEX_32I, CUSPARSE_INDEX_32I,
                                         CUSPARSE_INDEX_BASE_ZERO, CUDA_R_64F));
        CUSPARSE_CHECK(cusparseCreateDnVec(&vecX, n, d_x, CUDA_R_64F));
        CUSPARSE_CHECK(cusparseCreateDnVec(&vecY, n, d_y, CUDA_R_64F));
        size_t bufferSize = 0;
        CUSPARSE_CHECK(cusparseSpMV_bufferSize(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                                               &alpha, matA, vecX, &beta, vecY,
                                               CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT,
                                               &bufferSize));
        CUDA_CHECK(cudaMalloc(&d_buffer, bufferSize));
    }
    void run()
    {
        CUSPARSE_CHECK(cusparseSpMV(handle, CUSPARSE_OPERATION_NON_TRANSPOSE,
                                    &alpha, matA, vecX, &beta, vecY,
                                    CUDA_R_64F, CUSPARSE_SPMV_ALG_DEFAULT, d_buffer));
    }
    void teardown()
    {
        CUDA_CHECK(cudaFree(d_buffer));
        CUSPARSE_CHECK(cusparseDestroySpMat(matA));
        CUSPARSE_CHECK(cusparseDestroyDnVec(vecX));
        CUSPARSE_CHECK(cusparseDestroyDnVec(vecY));
        CUSPARSE_CHECK(cusparseDestroy(handle));
    }
};

// Egy mátrixeset teljes mérése: minden megvalósítás eredményét a CPU referenciával
// ellenőrizzük, MIELŐTT időt mérnénk.
void run_case(const char* name, int n, int target, double imbalance)
{
    const int block_size = 256, warmup = 5, iters = 20, reps = 20;
    std::vector<int> h_row_ptr, h_col_idx;
    std::vector<double> h_values;
    int nnz;
    generate_sparse_matrix(n, target, imbalance, h_row_ptr, h_col_idx, h_values, nnz);
    printf("\n[%s] n = %d, nnz = %d, átlagos sorhossz = %.2f\n", name, n, nnz,
        (double)nnz / n);

    std::vector<double> h_x(n), h_y_ref(n), h_y(n);
    std::mt19937 rng(123);
    std::uniform_real_distribution<double> dist(-1.0, 1.0);
    for (auto& v : h_x) v = dist(rng);
    spmv_cpu(h_row_ptr.data(), h_col_idx.data(), h_values.data(), h_x.data(), h_y_ref.data(),
        n);

    int *d_row_ptr, *d_col_idx;
    double *d_values, *d_x, *d_y;
    CUDA_CHECK(cudaMalloc(&d_row_ptr, (n + 1) * sizeof(int)));
    CUDA_CHECK(cudaMalloc(&d_col_idx, nnz * sizeof(int)));
    CUDA_CHECK(cudaMalloc(&d_values, nnz * sizeof(double)));
    CUDA_CHECK(cudaMalloc(&d_x, n * sizeof(double)));
    CUDA_CHECK(cudaMalloc(&d_y, n * sizeof(double)));
    CUDA_CHECK(cudaMemcpy(d_row_ptr, h_row_ptr.data(), (n + 1) * sizeof(int),
        cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(d_col_idx, h_col_idx.data(), nnz * sizeof(int),
        cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(d_values, h_values.data(), nnz * sizeof(double),
        cudaMemcpyHostToDevice));
    CUDA_CHECK(cudaMemcpy(d_x, h_x.data(), n * sizeof(double), cudaMemcpyHostToDevice));

    CusparseSpmv sp;
    sp.setup(n, nnz, d_row_ptr, d_col_idx, d_values, d_x, d_y);

    const int grid_scalar = (n + block_size - 1) / block_size;
    const int warps_per_block = block_size / 32;
    const int grid_warp = (n + warps_per_block - 1) / warps_per_block;
    auto run_scalar = [&] {
        spmv_csr_scalar<<<grid_scalar, block_size>>>(d_row_ptr, d_col_idx, d_values, d_x, d_y,
            n);
    };
    auto run_warp = [&] {
        spmv_csr_warp<<<grid_warp, block_size>>>(d_row_ptr, d_col_idx, d_values, d_x, d_y, n);
    };
    auto run_cusparse = [&] { sp.run(); };

    // Közös bytes-becslés (alsó becslés: az x-et egyszer olvassuk)
    const double mem_bytes = (double)nnz * (sizeof(double) + sizeof(int))
                           + (double)(n + 1) * sizeof(int) + 2.0 * n * sizeof(double);

    printf("%-9s %10s %10s %14s %14s\n", "Kernel", "Idő (ms)", "Szórás", "GB/s (becsült)",
        "Max rel. hiba");
    auto evaluate = [&](const char* kname, auto&& fn) {
        CUDA_CHECK(cudaMemset(d_y, 0, n * sizeof(double)));
        fn();
        CUDA_CHECK(cudaGetLastError());
        CUDA_CHECK(cudaDeviceSynchronize());
        CUDA_CHECK(cudaMemcpy(h_y.data(), d_y, n * sizeof(double), cudaMemcpyDeviceToHost));
        double max_rel = 0.0;
        for (int i = 0; i < n; ++i)
            max_rel = std::max(max_rel, std::abs(h_y[i] - h_y_ref[i]) / std::max(1.0,
                std::abs(h_y_ref[i])));
        double sd;
        double t = measure_time(fn, warmup, iters, reps, &sd);
        printf("%-9s %10.4f %10.4f %14.1f %14.2e\n", kname, t, sd,
            mem_bytes / (t * 1e-3) / 1e9, max_rel);
    };
    evaluate("scalar", run_scalar);
    evaluate("warp", run_warp);
    evaluate("cusparse", run_cusparse);

    sp.teardown();
    CUDA_CHECK(cudaFree(d_row_ptr));
    CUDA_CHECK(cudaFree(d_col_idx));
    CUDA_CHECK(cudaFree(d_values));
    CUDA_CHECK(cudaFree(d_x));
    CUDA_CHECK(cudaFree(d_y));
}

int main()
{
    const int n = 1'000'000;
    run_case("log-normális, imbalance=1.5", n, 10, 1.5);   // várt átlagos sorhossz ~10
    run_case("sávos, 5 nemnulla/sor", n, 5, 0.0);          // pontosan 5 elem soronként
    return 0;
}

Megjegyzés a kódhoz: A cusparse mérésben a leírók és a puffer a mérési cikluson kívül jönnek létre (CusparseSpmv::setup), így a mért idő csak az cusparseSpMV hívásokat tartalmazza; az allokáció és a leíróépítés költsége (amely a kernelnél nagyságrendekkel nagyobb is lehet) a mérésből kimarad. Minden megvalósítás eredményét a CPU referenciával vetjük össze a mérés előtt (relatív hiba, FP64: a felhalmozás sorrendje miatt kb. 1e-12 nagyságrendű eltérés várható, hibaküszöbnek 1e-9 javasolt). A cusparseSpMV_preprocess hívás (CUDA 12.3+) opcionális, a kód nem használja. A kód nem volt lefordítva és futtatva; minden szám a laborban mérendő.

A labor során a következő táblázatot kell kitölteni. A várt eredmény oszlopban a tendencia szerepel – ezt a mérés előtt kell megadni, a mért oszlopot pedig a futtatás után.

Fontos: A fenti táblázatban a „várt tendencia” előrejelzés, amelyet a mérés előtt kell megfogalmazni. A „mért” oszlopok a tényleges futtatás eredményei, amelyeket a labor során kell rögzíteni. A laborjelentésnek tartalmaznia kell a teljes környezetet (GPU modell, driver, CUDA verzió, órajel, power limit, ECC állapot) és a mérés statisztikáját (medián, szórás vagy IQR, ismétlésszám). A mérési naplóban a tényleges és a várt eredményeket egyértelműen el kell különíteni, és ha eltérés van, azt elemezni kell.

A sávszélesség számításánál a tényleges adatforgalmat kell használni: bytes=nnz⋅(8+4)+(n+1)⋅4+2n⋅8\mathrm{bytes} = \mathrm{nnz} \cdot (8 + 4) + (n+1) \cdot 4 + 2 n \cdot 8 double precízió esetén. A névleges GPU sávszélesség (pl. A100 40 GB: kb. 1555 GB/s, HBM2) csak felső korlát; a tényleges SpMV-sávszélesség a mátrix szerkezetétől függ (szabályos szerkezetnél a csúcs jelentős részét is elérheti), ezért az arányt a mérésből kell megadni, előre nem állítjuk. A kódban szereplő bájtszám alsó becslés (az xx vektort egyszer számolja).

19.3.7 Gyakori hibák és megelőzésük

  1. Out-of-bounds indexelés a CSR tömbökben. Ha a row_ptr[n] nem egyezik a values hosszával, vagy a col_idx elemei kívül esnek a [0,n−1][0, n-1] tartományon, a kernel nem definiált viselkedést okoz. Megelőzés: a mátrixgenerátor után ellenőrizni kell a tömbök konzisztenciáját, és a kernelben a col_idx[j] értékét a beolvasás előtt validálni (debug módban).

  2. Nem lefedett vagy többszörösen írt y elemek. Ha a grid nem fedi le az összes sort, a ki nem számolt y[row] elemek tartalma határozatlan (nincs versenyhelyzet, csak hiányzó eredmény). Versenyhelyzet akkor keletkezik, ha két szál ugyanazt az y[row] elemet írja – ez a hibrid vagy a nonzero-onkénti megoldásoknál lehetséges. Megelőzés: minden sort pontosan egy szál vagy warp írjon (a hibrid vázlatban a két kernel sorhalmaza diszjunkt), és a y teljes lefedettségét teszteljük (pl. az y előzetes feltöltésével jelzőértékkel).

  3. Hibás szinkronizációs maszk a warp-redukciónál. A __shfl_down_sync a mask-ban megadott szálakat szinkronizálja és regiszteren keresztül cserél adatot, külön __syncwarp() nem kell hozzá. A hiba ott van, ha a maszkban szereplő szálak közül nem mind hívja meg az utasítást (pl. egy korai return után csak a warp egy része éri el): ez határozatlan viselkedés. Megelőzés: a teljes maszkot (0xffffffff) csak akkor használjuk, ha a warp minden szála eljut a hívásig; korai kilépésnél a kilépési feltételnek a teljes warpra egységesnek kell lennie (mint a fenti kerneleknél), vagy a maszkot a még aktív szálakra kell szűkíteni.

  4. A cuSPARSE puffer elhagyása vagy helytelen méretezése. A cusparseSpMV a bufferSize által meghatározott puffert igényli; ha a puffer túl kicsi, a hívás hibát ad vagy nem definiált viselkedést okoz. Megelőzés: mindig hívjuk meg a cusparseSpMV_bufferSize-t, és ellenőrizzük a visszatérési értékeket.

  5. A mérési idő nem tartalmazza a teljes adatmozgatást. Ha a mérés csak a kernel futásidejét rögzíti, de a mátrix feltöltését nem, akkor a valós alkalmazás teljesítménye rosszabb lesz. Megelőzés: a mérés során a teljes adatutat mérjük, vagy legalább külön jelöljük a kernel- és a transzferidőt.

  6. A numerikus pontosság elhanyagolása. Az SpMV-nál a felhalmozás sorrendje befolyásolja a kerekítési hibát, különösen ha a mátrix értékei nagy dinamikatartományúak. A warp-per-row kernel redukciós sorrendje eltér a CPU-tól, ami kis eltéréseket okozhat. Megelőzés: a hibahatárt a feladat numerikus igényeihez kell igazítani, és a mérési naplóban rögzíteni kell a használt precíziót (FP64/FP32).

19.3.8 Összefoglalás

Az SpMV a GPU-számítás egyik legnehezebb memória-kötött feladata. A naiv scalar kernel egyszerű, de a terheléskiegyensúlyozatlanság miatt a valós mátrixokon gyakran nagyon lassú. A warp-per-row kernel a hosszú sorokat párhuzamosítja, de a rövid soroknál pazarló. Hatékony megoldás lehet a sorhossz-eloszláshoz igazodó hibrid stratégia vagy a SELL-C-σ formátum; ezek előnyét a fejezet laborja nem méri, ezért mérendő hipotézisként kezeljük. A cuSPARSE generikus API-ja kényelmes és erősen optimalizált SpMV-t kínál, de a teljesítmény még így is a mátrix szerkezetétől függ. A labor során a hallgató a három megközelítést méri össze, és a mért eredményeket a várt tendenciákkal veti össze.

Önellenőrző kérdés: Miért nem elegendő a soronként egy szálat indító scalar kernel a nagy sorhossz-szóródású mátrixokhoz? Hogyan oldja meg a warp-per-row kernel a problémát, és mi a hátránya rövid sorok esetén?

Megoldás. Nagy szóródásnál egy warp futásideje a benne lévő leghosszabb sor hosszával arányos, a rövid sorú szálak tétlenek, és a szálak egy sorhossznyi távolságra olvasnak (nem koaleszkált). A warp-per-row kernel a sor elemeit a 32 lane között osztja szét (koaleszkált values/col_idx olvasás), majd shuffle-redukcióval összegez; rövid sornál (pl. 3 elem) viszont 29 lane tétlen, és a redukció 5 lépése is többletköltség.
