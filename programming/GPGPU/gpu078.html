21.1 Adatpárhuzamos minták

Az adatpárhuzamos minták a GPGPU-programozás közös szókincsét alkotják. Amikor egy feladatot GPU-ra viszünk, az első kérdés általában az, hogy a párhuzamosság az adatelemek, a feladatok vagy az adatfolyam szintjén jelenik-e meg. A map, a reduce és a scan az adatelemek szintjén párhuzamosítható minták, amelyekből a legtöbb numerikus kernel felépíthető. A map független elemenkénti transzformációt, a reduce aggregációt, a scan pedig prefix műveletet valósít meg. Mindhárom közös tulajdonsága, hogy a párhuzamosság az adatelemek között jön létre, nem pedig az utasítások között; ez közvetlenül illeszkedik a SIMT-végrehajtáshoz.

21.1.1 A három alapminta

Legyen x0,…,xN−1x_0,\ldots,x_{N-1} egy NN elemű bemeneti vektor, ff egy elemenként alkalmazható függvény, ⊕\oplus pedig egy asszociatív művelet (például összeadás, maximum, minimum vagy logikai ÉS). A három minta formálisan:

  • Map: yi=f(xi)y_i = f(x_i), minden ii-re. Az elemek függetlenek, ezért a párhuzamosítás triviális.
  • Reduce: s=x0⊕x1⊕⋯⊕xN−1s = x_0 \oplus x_1 \oplus \cdots \oplus x_{N-1}. A művelet asszociativitása miatt a részeredmények tetszőleges fába rendezhetők.
  • Scan (prefix): yi=x0⊕x1⊕⋯⊕xiy_i = x_0 \oplus x_1 \oplus \cdots \oplus x_i (inclusive), vagy yi=x0⊕⋯⊕xi−1y_i = x_0 \oplus \cdots \oplus x_{i-1} és y0=ey_0 = e (exclusive, ahol ee a semleges elem). A scan minden kimeneti eleme az összes korábbi bemenettől függ, ezért a párhuzamosítás már gondosabb szervezést igényel.

A három minta kompozíciója rendkívül gyakori: egy map előkészíti az adatot, egy reduce összegzi vagy normalizálja, egy scan pedig kumulatív mennyiséget állít elő. A következőkben mindegyik mintát külön-külön, majd láncolt formában vizsgáljuk.

21.1.2 Map: független elemek transzformációja

A map a legegyszerűbb adatpárhuzamos minta, mivel a kimeneti elemek között nincs adatfüggőség. Minden szál egy vagy több elemet dolgoz fel, és a szálak közötti kommunikációra nincs szükség. A CUDA-ban a legjobb gyakorlat a grid-stride loop: a szálak a saját indexüktől indulva, a teljes szálrács lépésközével haladva dolgozzák fel az elemeket. Ez lehetővé teszi, hogy a kernel akkor is helyesen működjön, ha a rács mérete kisebb, mint az elemszám, és csökkenti a launch overheadet.

// CUDA C++ (C++17, nvcc)
__global__ void map_sqrt_kernel(const float* __restrict__ x,
                                float* __restrict__ y,
                                int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    int stride = blockDim.x * gridDim.x;
    for (int i = idx; i < n; i += stride) {
        y[i] = sqrtf(x[i]);
    }
}

A kernelben a __restrict__ kulcsszó jelzi a fordítónak, hogy a mutatók nem fednek át, ami segíthet a vektorizált betöltésben. A memória-hozzáférés a természetes sorrendben, összevont (coalesced) módon történik, mivel a szomszédos szálak szomszédos címeket olvasnak. A map kernel jellemzően memória-korlátos: a futásidőt a globális memória sávszélessége határozza meg, nem a számítási műveletek.

A map tipikus hibái közé tartozik az indexhatár túllépése (i < n ellenőrzés elhagyása), a túl kicsi grid (alacsony kihasználtság), valamint a nem coalesced hozzáférés, ha az indexelés például transzponált vagy stride-olt. A <<<grid, block>>> konfigurációt úgy kell megválasztani, hogy a blokkszám legalább annyi legyen, amennyi az SM-ek számának többszöröse, hogy az ütemező el tudja rejteni a memória késleltetést.

21.1.3 Reduce: aggregáció fából

A reduce egy asszociatív művelettel egyetlen skalárt állít elő. Mivel a művelet asszociatív, az elemek tetszőleges csoportosításban összegezhetők. A GPU-s megvalósítás tipikus váza: minden blokk a saját részét egy bináris fa szerint redukálja, majd a blokkok részeredményeit egy második lépésben (például atomicAdd-del vagy egy második kernellel) egyesíti.

A blokkon belüli redukció a shared memory-t használja a részeredmények tárolására. A __syncthreads() hívások biztosítják, hogy a fa minden szintjén minden szál lássa a többi szál által írt értékeket, mielőtt a következő szintre lép.

// CUDA C++ (C++17, nvcc)
__global__ void reduce_sum_kernel(const float* __restrict__ in,
                                  float* __restrict__ out,
                                  int n) {
    __shared__ float sdata[256];
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;
    int stride = blockDim.x * gridDim.x;

    float sum = 0.0f;
    for (int i = idx; i < n; i += stride) {
        sum += in[i];          // soros részösszeg a szálra jutó elemekre
    }

    sdata[tid] = sum;
    __syncthreads();

    for (int s = blockDim.x / 2; s > 0; s >>= 1) {
        if (tid < s) {
            sdata[tid] += sdata[tid + s];
        }
        __syncthreads();
    }

    if (tid == 0) {
        atomicAdd(out, sdata[0]);   // blokk eredménye a globális kimenetbe
    }
}

Ez a kernel először minden szálra kiszámítja a rá eső elemek részösszegét, majd a blokk szintjén bináris fával redukál. Az atomicAdd a blokkok közötti összegzést végzi. Ez a kernel már a szekvenciális címzésű fát használja, ezért a shared memóriában nincs bankütközés; a fennmaradó költség az utolsó öt szint warpon belüli divergenciája és __syncthreads() hívásai, valamint az atomicAdd-ek versengése, ha sok blokk ír ugyanarra a címre. A 16. fejezet (16.1) warp-shuffle-ös és warp-szinten kibontott változatai ezeket csökkentik; itt a minta szerkezetére koncentrálunk.

Fontos megjegyezni, hogy a lebegőpontos összeadás nem asszociatív a kerekítés miatt. A redukció sorrendje megváltoztathatja az eredményt, ezért a GPU-s és CPU-s referenciák csak egy tűréshatáron belül hasonlíthatók össze. Ugyanez vonatkozik a scan-re is.

21.1.4 Scan: prefix összeg

A scan minden kimeneti eleme az összes korábbi bemenettől függ, ezért a párhuzamosítás nem triviális. A gyakorlatban elterjedt megoldás a háromlépéses, blokkszintű scan: minden blokk kiszámítja a saját szeletének lokális prefixét, a szelet végösszegét eltárolja, majd egy második lépésben kiszámítja a szeletek közötti offseteket, végül egy harmadik lépés hozzáadja az offseteket a lokális eredményekhez.

Az alábbi példa egy egyszerű, de helyes implementációt mutat be, amely a Hillis–Steele-féle naiv inkluzív scan-t használja a blokkon belül, majd a blokkok közötti offseteket egyetlen szálon számítja ki. Ez a megközelítés kis blokkszám esetén elfogadható, és jól szemlélteti a minta szerkezetét.

// CUDA C++ (C++17, nvcc)
__global__ void scan_block_kernel(const float* __restrict__ in,
                                  float* __restrict__ out,
                                  float* __restrict__ block_sums,
                                  int n) {
    extern __shared__ float temp[];   // dinamikus shared memória
    int tid = threadIdx.x;
    int idx = blockIdx.x * blockDim.x + tid;
    float val = (idx < n) ? in[idx] : 0.0f;

    temp[tid] = val;
    __syncthreads();

    // Hillis–Steele inclusive scan a blokkon belül
    for (int offset = 1; offset < blockDim.x; offset <<= 1) {
        float other = 0.0f;
        if (tid >= offset) {
            other = temp[tid - offset];
        }
        __syncthreads();
        temp[tid] += other;
        __syncthreads();
    }

    // exclusive scan: a bemeneti elem nélkül
    float exclusive = (tid == 0) ? 0.0f : temp[tid - 1];
    if (idx < n) {
        out[idx] = exclusive;
    }

    // a blokk teljes összege (inclusive scan utolsó eleme)
    if (tid == blockDim.x - 1) {
        block_sums[blockIdx.x] = temp[tid];
    }
}

A blokkok végösszegeit egy block_sums tömbben tároljuk, amelynek mérete gridDim.x. A következő kernel kiszámítja az offseteket (a block_sums exclusive scan-jét), az utolsó kernel pedig hozzáadja az offsetet a lokális eredményekhez.

// CUDA C++ (C++17, nvcc)
__global__ void scan_offset_kernel(const float* __restrict__ block_sums,
                                   float* __restrict__ block_offsets,
                                   int num_blocks) {
    if (blockIdx.x == 0 && threadIdx.x == 0) {
        float sum = 0.0f;
        for (int i = 0; i < num_blocks; ++i) {
            block_offsets[i] = sum;
            sum += block_sums[i];
        }
    }
}

__global__ void scan_add_offset_kernel(float* __restrict__ out,
                                       const float* __restrict__ block_offsets,
                                       int n) {
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < n) {
        out[idx] += block_offsets[blockIdx.x];
    }
}

Az alábbi ábra a három kernel minden lépését végigköveti egy kis bemeneten (N=8N = 8, blokkméret 4); a vastag vonalak a két __syncthreads() helyét jelölik a Hillis–Steele-szintek olvasása és írása között.

Ez a háromlépéses szerkezet jól mutatja a scan kompozíciós természetét: a blokkon belüli scan egy O(Blog⁡B)O(B\log B) munkájú Hillis–Steele-scan (a Blelloch-féle változat munkája O(B)O(B); BB a blokkméret), a blokkok közötti offset-számítás egy újabb scan, az offset hozzáadása pedig map. A gyakorlatban nagyobb adatokra a CUB cub::DeviceScan::ExclusiveSum vagy a 16. fejezetben bemutatott optimalizált változatok használata javasolt; a fenti kód a tanulást szolgálja. Korlátai: a blokkméret legfeljebb 1024 szál (és ennyi float fér a dinamikus shared memóriába), az offset-kernel egyetlen szálon O(grid)O(\text{grid}) lépésben fut, ami sok blokknál szűk keresztmetszet – ilyenkor az offsetek scan-jét is párhuzamosan (rekurzívan) kell elvégezni.

A scan tipikus hibái közé tartozik:

  • az exclusive és inclusive konverzió eltévesztése (az első elem semleges eleme);
  • a blokkok közötti offset hiánya, ami a szeletek határán helytelen eredményt ad;
  • a __syncthreads() elhagyása a Hillis–Steele iterációban, ami versenyhelyzetet okoz;
  • a shared memória méretének helytelen megadása a kernelindításnál.

21.1.5 Kompozíció: map – reduce – scan

A valós alkalmazásokban a három minta szinte soha nem jelenik meg elszigetelten. Egy tipikus adatfeldolgozási lánc:

  1. Map előkészíti a nyers adatot (átalakítás, mértékegység-konverzió, nemlinearitás).
  2. Reduce aggregálja a transzformált adatot (összeg, átlag, maximum).
  3. Scan kumulatív mennyiséget képez (kumulatív összeg, eloszlásfüggvény).

Egy konkrét példa a normalizálás: a bemeneti vektorból először reduce-szal kiszámítjuk az átlagot (vagy egy menetben a ∑x\sum x és ∑x2\sum x^2 összeget), majd map + reduce adja a szórást, végül egy újabb map normalizálja az elemeket. A laborban ezt a láncot egy egyszerűbb változatban valósítjuk meg: y[i] = sqrtf(x[i]) map, sum = sum(y) reduce, z = exclusive_scan(y) scan.

A kompozíció során három dolgot kell kiemelten kezelni:

  • Pufferek élettartama: a map kimenete (y) a reduce és a scan bemenete. A GPU memóriát a lánc végéig fenn kell tartani; a puffereket addig kell fenntartani, amíg bármely kernel használja őket. A cudaFree implicit szinkronizál az eszközzel (megvárja a futó kernelek befejezését), a stream-sorrendű cudaFreeAsync esetén viszont a felszabadítást a megfelelő streamben, a használó kernelek után kell sorba állítani.
  • Szinkronizáció: a kernelindítások aszinkronok, ezért a következő kernel indítása előtt ugyanazon a streamen belül a sorrend garantált, de a CPU oldali ellenőrzéshez cudaDeviceSynchronize kell. Ha külön streameket használunk, explicit eseményekkel kell a függőséget jelölni.
  • Numerikus konzisztencia: a reduce és a scan sorrendje befolyásolja a lebegőpontos eredményt. Az ellenőrzéshez mindig tűréshatárt adjunk meg, és a várt értéket CPU-n, nagyobb (FP64) pontossággal számítsuk, a tűrést pedig a GPU-s pontossághoz (itt FP32) igazítsuk.

21.1.6 Labor: minták láncolása

A labor célja a három minta implementálása és összekapcsolása egy ellenőrizhető példán. A feladat:

  • Bemenet: N=1024N = 1024 elemű float vektor, x[i]=(imod⁡512)⋅10−3x[i] = (i \bmod 512) \cdot 10^{-3}.
  • Map: y[i]=x[i]y[i] = \sqrt{x[i]}.
  • Reduce: s=∑i=0N−1y[i]s = \sum_{i=0}^{N-1} y[i].
  • Scan: z[i]=∑j=0i−1y[j]z[i] = \sum_{j=0}^{i-1} y[j] (exclusive prefix sum).
  • Ellenőrzés: CPU-referenciával hasonlítsa össze az y, s és z értékeket; a hibakorlát: y abszolút hibája ≤10−6\le 10^{-6}, az s és z relatív hibája ≤10−4\le 10^{-4}, double precíziós CPU-referenciához képest (az összeg kb. 488, itt 1 ulp ≈3⋅10−5\approx 3\cdot 10^{-5}, ezért a 10−510^{-5} abszolút korlát nem teljesíthető).
  • Mérés: warm-up 10 futtatás, majd 100 egyenként mért ismétlés; adja meg a teljes lánc mediánját és szórását. A kernelenkénti medián és szórás kiegészítő feladat: kernelenként külön eseménypárral és ismétlésenkénti idők tömbjével (vagy Nsight Systems-szel) mérendő; a mellékelt váz csak a teljes láncot méri.

Az alábbi program a labor main függvényét adja; a lab.cu fájl teljessé tételéhez a fenti öt kernel definícióját a jelölt helyre be kell másolni (egyetlen fordítási egység). A kód a fenti map, reduce és scan kerneleket használja, és elvégzi a CPU-s ellenőrzést, valamint az időmérést.

// CUDA C++ (C++17, nvcc)
#include <cstdio>
#include <cstdlib>
#include <cmath>
#include <algorithm>
#include <vector>
#include <cuda_runtime.h>

#define CUDA_CHECK(call) do {                                      \
    cudaError_t err_ = (call);                                      \
    if (err_ != cudaSuccess) {                                      \
        std::fprintf(stderr, "CUDA error in %s at line %d: %s\n",   \
                     __FILE__, __LINE__, cudaGetErrorString(err_)); \
        std::exit(EXIT_FAILURE);                                    \
    }                                                               \
} while (0)

// --- Kernelek ---
// IDE MÁSOLANDÓ a fenti öt kernel teljes definíciója (map_sqrt_kernel,
// reduce_sum_kernel, scan_block_kernel, scan_offset_kernel,
// scan_add_offset_kernel) változtatás nélkül, ugyanebbe a lab.cu fájlba.
// Deklaráció önmagában nem elég: definíció nélkül a program nem linkelhető.

int main() {
    const int N = 1024;
    const int block = 256;
    const int grid = (N + block - 1) / block;   // 4 blokk

    // Host bemenet
    std::vector<float> h_x(N);
    for (int i = 0; i < N; ++i) {
        h_x[i] = static_cast<float>(i % 512) * 1e-3f;
    }

    // GPU allokációk
    float *d_x, *d_y, *d_z, *d_sum, *d_block_sums, *d_block_offsets;
    CUDA_CHECK(cudaMalloc(&d_x, N * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&d_y, N * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&d_z, N * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&d_sum, sizeof(float)));
    CUDA_CHECK(cudaMalloc(&d_block_sums, grid * sizeof(float)));
    CUDA_CHECK(cudaMalloc(&d_block_offsets, grid * sizeof(float)));

    CUDA_CHECK(cudaMemcpy(d_x, h_x.data(), N * sizeof(float),
                          cudaMemcpyHostToDevice));

    // Események az időméréshez
    cudaEvent_t start, stop;
    CUDA_CHECK(cudaEventCreate(&start));
    CUDA_CHECK(cudaEventCreate(&stop));

    // Warm-up
    for (int i = 0; i < 10; ++i) {
        map_sqrt_kernel<<<grid, block>>>(d_x, d_y, N);
        CUDA_CHECK(cudaMemsetAsync(d_sum, 0, sizeof(float)));  // atomicAdd előtt nullázni kell
        reduce_sum_kernel<<<grid, block>>>(d_y, d_sum, N);
        scan_block_kernel<<<grid, block, block * sizeof(float)>>>
            (d_y, d_z, d_block_sums, N);
        scan_offset_kernel<<<1, 1>>>(d_block_sums, d_block_offsets, grid);
        scan_add_offset_kernel<<<grid, block>>>(d_z, d_block_offsets, N);
    }
    CUDA_CHECK(cudaGetLastError());      // indítási hibák ellenőrzése
    CUDA_CHECK(cudaDeviceSynchronize());

    // Mérés: 100 ismétlés, láncenként külön eseménypárral
    std::vector<float> t(100);
    for (int i = 0; i < 100; ++i) {
        CUDA_CHECK(cudaEventRecord(start));
        map_sqrt_kernel<<<grid, block>>>(d_x, d_y, N);
        CUDA_CHECK(cudaMemsetAsync(d_sum, 0, sizeof(float)));  // atomicAdd előtt nullázni kell
        reduce_sum_kernel<<<grid, block>>>(d_y, d_sum, N);
        scan_block_kernel<<<grid, block, block * sizeof(float)>>>
            (d_y, d_z, d_block_sums, N);
        scan_offset_kernel<<<1, 1>>>(d_block_sums, d_block_offsets, grid);
        scan_add_offset_kernel<<<grid, block>>>(d_z, d_block_offsets, N);
        CUDA_CHECK(cudaGetLastError());
        CUDA_CHECK(cudaEventRecord(stop));
        CUDA_CHECK(cudaEventSynchronize(stop));
        CUDA_CHECK(cudaEventElapsedTime(&t[i], start, stop));
    }
    std::vector<float> sorted_t(t);
    std::sort(sorted_t.begin(), sorted_t.end());
    const float med_ms = 0.5f * (sorted_t[49] + sorted_t[50]);
    float mean_ms = 0.0f, ss = 0.0f;                 // mintaszórás két menetben
    for (float x : t) mean_ms += x;
    mean_ms /= 100.0f;
    for (float x : t) ss += (x - mean_ms) * (x - mean_ms);
    const float sd_ms = std::sqrt(ss / 99.0f);

    // Eredmények letöltése
    std::vector<float> h_y(N), h_z(N);
    float h_sum = 0.0f;
    CUDA_CHECK(cudaMemcpy(h_y.data(), d_y, N * sizeof(float),
                          cudaMemcpyDeviceToHost));
    CUDA_CHECK(cudaMemcpy(h_z.data(), d_z, N * sizeof(float),
                          cudaMemcpyDeviceToHost));
    CUDA_CHECK(cudaMemcpy(&h_sum, d_sum, sizeof(float),
                          cudaMemcpyDeviceToHost));

    // CPU referencia double precizióval (a GPU float eredményeit ehhez mérjük)
    std::vector<double> ref_y(N), ref_z(N);
    double ref_sum = 0.0;
    for (int i = 0; i < N; ++i) {
        ref_y[i] = std::sqrt(static_cast<double>(h_x[i]));
        ref_sum += ref_y[i];
    }
    ref_z[0] = 0.0;
    for (int i = 1; i < N; ++i) {
        ref_z[i] = ref_z[i - 1] + ref_y[i - 1];
    }

    // Ellenőrzés: y abszolút, z és sum relatív hibával
    double max_err_y = 0.0, max_rel_z = 0.0;
    for (int i = 0; i < N; ++i) {
        max_err_y = std::max(max_err_y, std::fabs(h_y[i] - ref_y[i]));
        max_rel_z = std::max(max_rel_z,
            std::fabs(h_z[i] - ref_z[i]) / std::max(ref_z[i], 1.0));
    }
    double sum_rel = std::fabs(h_sum - ref_sum) / ref_sum;
    // Összefüggés: exclusive scan utolsó eleme + utolsó y = sum
    double scan_sum_from_z = static_cast<double>(h_z[N - 1]) + h_y[N - 1];

    std::printf("Teljes lanc ido: median %.4f ms, szoras %.4f ms (100 ismetles)\n", med_ms,
        sd_ms);
    std::printf("Max abs elteres y: %.3e, max rel elteres z: %.3e\n",
                max_err_y, max_rel_z);
    std::printf("Sum rel elteres: %.3e\n", sum_rel);
    std::printf("Sum GPU: %.6f, CPU: %.6f, z[n-1]+y[n-1]: %.6f\n",
                h_sum, ref_sum, scan_sum_from_z);

    CUDA_CHECK(cudaFree(d_x));
    CUDA_CHECK(cudaFree(d_y));
    CUDA_CHECK(cudaFree(d_z));
    CUDA_CHECK(cudaFree(d_sum));
    CUDA_CHECK(cudaFree(d_block_sums));
    CUDA_CHECK(cudaFree(d_block_offsets));
    CUDA_CHECK(cudaEventDestroy(start));
    CUDA_CHECK(cudaEventDestroy(stop));

    return (max_err_y < 1e-6 && max_rel_z < 1e-4 && sum_rel < 1e-4) ? 0 : 1;
}

A labor elvégzése után a mérési naplóban rögzíteni kell a mért futásidőt, valamint a várt eredményt (CPU referencia) és a mért eredményt (GPU) egymástól elkülönítve. A fenti program kimenetében a Sum GPU a mért, a Sum CPU a várt érték; a max_err_y, max_rel_z és sum_rel a kettő eltérése (a nem futtatott kódhoz tartozó értékeket a futtatás után kell kitölteni).

A mérési napló szerkezete:

Kernel Medián (µs) Szórás (µs) Megjegyzés (a kernelenkénti sorok a kiegészítő feladat eredményei)
map_sqrt_kernel <mért> <mért> Memória-korlátos, coalesced
reduce_sum_kernel <mért> <mért> Blokkon belüli fa
scan_block_kernel <mért> <mért> Hillis–Steele, shared mem
scan_offset_kernel <mért> <mért> Egy szál, kicsi munka
scan_add_offset_kernel <mért> <mért> Map-szerű
Teljes lánc <mért> <mért> 100 ismétlés mediánja

A laborban az N = 1024 érték kicsi, ezért a kernelindítási overhead dominálhat. A cél a minták helyes összekapcsolása, nem a csúcsteljesítmény mérése. Nagyobb N esetén a scan-t CUB-bal vagy a 16. fejezet optimalizált módszerével érdemes megvalósítani.

21.1.7 Gyakori hibák és megelőzésük

A három minta implementálásakor a következő tipikus hibák fordulnak elő:

  • Map:
    • Az i < n ellenőrzés elhagyása, ami out-of-bounds hozzáférést okoz.
    • Nem coalesced hozzáférés, ha az indexelés nem a szomszédos szálaknak megfelelő.
    • Túl nagy block érték, ami regiszternyomást és alacsony occupancy-t eredményez.
  • Reduce:
    • __syncthreads() elhagyása a fa szintjei között, ami versenyhelyzetet okoz.
    • Nem megfelelő shared memória méret, ha a block méret nem egyezik a kernelben feltételezettel.
    • A blokkok közötti összegzéshez atomicAdd helyett nem atomi írás, ami elveszett frissítést eredményez.
  • Scan:
    • Az exclusive és inclusive konverzió eltévesztése: exclusive scan esetén az első elem a semleges elem.
    • A blokkok közötti offset hiánya, ami a szeletek határán helytelen kumulatív értéket ad.
    • A Hillis–Steele iterációban a __syncthreads() párok helytelen elhelyezése, ami részlegesen frissített értékek olvasásához vezet.
  • Kompozíció:
    • A közbülső pufferek (d_y, d_block_sums) felszabadítása a lánc befejezése előtt (különösen cudaFreeAsync vagy több stream esetén, ahol nincs implicit szinkronizáció).
    • A cudaDeviceSynchronize hiánya, ami miatt a CPU oldali ellenőrzés korábban fut, mint ahogy a GPU befejezte a munkát.
    • A numerikus hibahatár elhagyása, ami hamis hibát jelez a lebegőpontos sorrend miatt.

21.1.8 Összegzés

A map, a reduce és a scan a GPGPU-programozás legalapvetőbb adatpárhuzamos építőkövei. A map független transzformációt, a reduce asszociatív aggregációt, a scan kumulatív műveletet valósít meg. Mindhárom minta a SIMT-végrehajtás természetes párhuzamosságát használja ki, de eltérő szinkronizációs és memória-hozzáférési igényekkel. A minták kompozíciója – például map → reduce → scan – a valós alkalmazások gerincét adja; a helyes pufferezés, szinkronizáció és numerikus ellenőrzés elengedhetetlen.

A következő alfejezet a feladatpárhuzamosságra és a terheléselosztásra összpontosít, ahol ezek a minták már mint újrahasznosítható építőelemek jelennek meg. A labor során szerzett tapasztalat – a kernelindítások sorrendje, a közbülső tárolók kezelése – közvetlenül alkalmazható lesz az összetettebb rendszerek tervezésekor.
