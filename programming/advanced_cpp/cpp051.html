14.2 Saját allokátor és custom container

Az előző alfejezetben áttekintettük az STL allokátor modellt és a PMR-t. Most egy saját allokátort és egy arra épülő egyedi konténert készítünk. A cél nem csupán az interfész megvalósítása, hanem annak megértése, hogyan csatolódik az allokátor a konténerhez, és milyen buktatók leselkednek a rebind, az állapotkezelés és a kivételbiztonság terén. A fejezetben egy bump-pointer arena allokátort és egy arena_vector nevű, dinamikus tömböt megvalósító konténert építünk, amely az allokátort használja. A példa a C++17/20 szabványnak megfelelő, de ahol a nyelv változott, azt jelezzük.

14.2.1 A saját allokátor felépítése

Az allokátor a std::allocator_traits sablonon keresztül csatlakozik a konténerekhez. A std::allocator_traits számos alapértelmezett típust és műveletet biztosít, így a saját allokátorunknak csak a minimális interfészt kell megvalósítania. A kötelező elemek:

  • value_type – a lefoglalandó elem típusa.
  • allocate(n) – legalább n * sizeof(T) bájt, megfelelően igazított memória foglalása.
  • deallocate(p, n) – az allocate által visszaadott memória felszabadítása, ahol n pontosan az allocate-nak átadott érték.
  • operator== (C++17-ben operator!= is; C++20-tól az ==-ből a != szintetizálódik) – az allokátorok egyenlősége: egyenlő allokátorok memóriája kölcsönösen felszabadítható.
  • konvertáló konstruktor Allocator<U>-ból (és a másolás), hogy a konténer a belső csomóponttípusra át tudja kötni az allokátort.

Opcionális elemek (az std::allocator_traits alapértelmezést ad hozzájuk): a pointer és társai, max_size(), rebind<U>, construct/destroy, a propagate_on_container_* jellemzők és az is_always_equal.

A modern C++ (C++11 óta) az std::allocator_traits használatát ajánlja a közvetlen allokátor interfész helyett. A traits automatikusan felismeri a rebind hiányát, és a template <typename U> struct rebind { using other = Allocator<U>; }; alapértelmezést alkalmazza, ha a sablonparaméter egyszerűen cserélhető. A rebind explicit megadása azonban olvashatóbbá teszi a kódot, és kompatibilis a régebbi konténerekkel is.

A következő példa egy minimális, nem állapotos allokátort mutat, amely a globális operator new-t használja:

// minimal_allocator.hpp
#pragma once
#include <cstddef>
#include <limits>
#include <memory>
#include <new>

template <typename T>
struct minimal_allocator {
    using value_type = T;
    using pointer = T*;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;

    template <typename U>
    struct rebind {
        using other = minimal_allocator<U>;
    };

    minimal_allocator() noexcept = default;
    template <typename U>
    minimal_allocator(const minimal_allocator<U>&) noexcept {}

    T* allocate(std::size_t n) {
        if (n > max_size()) throw std::bad_alloc();
        // Az operator new sosem ad vissza nullát: hiba esetén kivételt dob.
        return static_cast<T*>(::operator new(n * sizeof(T), std::align_val_t(alignof(T))));
    }

    void deallocate(T* p, std::size_t) noexcept {
        ::operator delete(p, std::align_val_t(alignof(T)));
    }

    std::size_t max_size() const noexcept {
        return std::numeric_limits<std::size_t>::max() / sizeof(T);
    }
};

template <typename T, typename U>
bool operator==(const minimal_allocator<T>&, const minimal_allocator<U>&) noexcept { return true; }
template <typename T, typename U>
bool operator!=(const minimal_allocator<T>&, const minimal_allocator<U>&) noexcept { return false; }

Ebben a kódban az ::operator new és ::operator delete túlterhelt, igazítást kezelő változatát használjuk (std::align_val_t, C++17). A max_size() fontos: ha hiányzik, a std::allocator_traits a size_t(-1) / sizeof(T) értéket adja vissza, ami általában megfelelő, de a pontos definíció segít a hibakeresésben. Az allokátorok egyenlőségét is definiálni kell; itt minden példány egyenlő, mert nincs állapotuk.

14.2.2 A rebind és a konténerillesztés

A rebind mechanizmus kritikus szerepet játszik a konténerekben. Tegyük fel, hogy egy std::list<T, Allocator = std::allocator<T>> konténer nem T típusú objektumokat, hanem belső csomópontokat (list_node<T>) foglal. A konténernek szüksége van egy Allocator<list_node<T>> allokátorra. Ezt a std::allocator_traits<Allocator>::template rebind_alloc<list_node<T>> segítségével tudja előállítani. A rebind tehát az allokátor típusparaméterének megváltoztatását teszi lehetővé anélkül, hogy a felhasználónak külön allokátort kellene megadnia.

A saját allokátorunknak tehát támogatnia kell ezt a rebindet. Ha a minimal_allocator-ban nem adtunk volna meg rebind-et, a std::allocator_traits akkor is működne, mert a sablonparaméter cseréje triviális. A minimal_allocator állapotmentes. Ha az allokátor állapottal rendelkezik (mint az alább bemutatott arena_allocator), a rebind konstrukciónak át kell vennie az állapotot, amit az arena_allocator(const arena_allocator<U>&) konstruktor biztosít.

14.2.3 Stateful allocator: állapot tárolása és terjedése

A stateful allocator olyan allokátor, amelynek példányai különböző állapotot hordoznak. Például egy arena allokátor egy adott memóriaterületre mutat, vagy egy naplózó allokátor egy számlálót tart. Az ilyen allokátorok esetében a konténerek műveleteinél (másolás, mozgatás, csere) gondosan kell kezelni az allokátor állapotának terjedését. A std::allocator_traits a következő típusjellemzőket vizsgálja:

  • propagate_on_container_copy_assignment
  • propagate_on_container_move_assignment
  • propagate_on_container_swap

Ha ezek a jellemzők std::true_type-ok, akkor a megfelelő konténer művelet során az allokátort is átmásolják/átmozgatják/kicserélik. Ha std::false_type, akkor az allokátor nem változik. Az alapértelmezés std::false_type, ami a nem állapotos allokátorokra helyes. Stateful allokátornál is szabályos érték, de tudatos döntést igényel, és a három művelet szabálya eltér. Másoló konstrukciónál nem a propagate_on_container_copy_assignment, hanem a select_on_container_copy_construction dönt (alapértelmezésben az allokátor másolata, így az állapot átkerül). A propagate_on_container_copy_assignment csak másoló értékadásnál számít: false esetén a cél a saját allokátorát (és arenáját) tartja meg, nem pedig „üres arena”-ra mutat. Move konstrukciónál az allokátort mozgatjuk, move assignmentnél a propagate_on_container_move_assignment és az allokátorok egyenlősége dönt, swap-nál a propagate_on_container_swap.

Másik fontos jellemző az is_always_equal, amely azt mondja meg, hogy az allokátor két példánya mindig egyenlő-e. Az alapértelmezett érték a C++17 óta a std::is_empty<Allocator>::type (ha az allokátor üres, akkor true, egyébként false). Ha az allokátor mindig egyenlő, a konténerek bizonyos optimalizációkat végezhetnek (pl. nem kell allokátort cserélni swapkor). Ezt a jellemzőt explicit módon is megadhatjuk.

Példánkban az arena allokátor nem mindig egyenlő, mert a pointer különbözik. A propagate_on_container_* jellemzőket std::true_type-ra állítjuk, hogy az állapot értékadáskor és cserekor is kövesse a konténert. Ez nem mindig a „legbiztonságosabb” választás: értékadás után a cél elemei a forrás arénájába kerülnek, és a cél régi puffere a régi allokátorral szabadítandó fel, ezért a propagáló értékadásnál a sorrendre figyelni kell (lásd az operator= implementációkat). Az allokátor állapota ráadásul az arena élettartamára is kihat.

14.2.4 Arena allokátor implementáció

Készítsünk egy egyszerű bump-pointer arena allokátort, amely egy előre lefoglalt memóriablokkból oszt ki, és nem szabadít fel egyedi elemeket. A felszabadítás az arena teljes újraindításakor történik. Az arena tárolja a memóriablokkot és az aktuális foglalási pozíciót jelző offsetet; az allokátor állapota csak egy, az arenára mutató pointer, így a másolt és rebindelt allokátorpéldányok ugyanazt az offsetet léptetik.

// arena.hpp
#pragma once
#include <cstddef>
#include <cstdint>
#include <new>

class arena {
public:
    explicit arena(std::size_t size)
        : memory_(static_cast<std::byte*>(::operator new(size, std::align_val_t(alignof(std::max_align_t))))),
          size_(size), offset_(0) {}

    ~arena() {
        ::operator delete(memory_, std::align_val_t(alignof(std::max_align_t)));
    }

    arena(const arena&) = delete;
    arena& operator=(const arena&) = delete;

    // Előfeltétel: az alignment kettő hatványa (nulla nem lehet).
    // A méretellenőrzés kivonással történik, így nem csordulhat túl.
    void* allocate(std::size_t n, std::size_t alignment) {
        if (alignment == 0 || (alignment & (alignment - 1)) != 0) throw std::bad_alloc();
        std::uintptr_t addr = reinterpret_cast<std::uintptr_t>(memory_) + offset_;
        std::size_t misalignment = static_cast<std::size_t>(addr & (alignment - 1));
        std::size_t padding = misalignment == 0 ? 0 : alignment - misalignment;
        std::size_t remaining = size_ - offset_;
        if (padding > remaining || n > remaining - padding) {
            throw std::bad_alloc();
        }
        void* result = memory_ + offset_ + padding;
        offset_ += padding + n;
        return result;
    }

    void deallocate(void*, std::size_t) noexcept {
        // Bump pointer: semmit sem teszünk; a memória az arena destruktorakor szabadul fel.
    }

    // A reset után egyetlen, az arenából foglalt memóriát használó konténer
    // vagy objektum sem lehet élő. Az arena T-destruktort nem hív.
    void reset() noexcept {
        offset_ = 0;
    }

    std::size_t used() const noexcept { return offset_; }
    std::size_t capacity() const noexcept { return size_; }

private:
    std::byte* memory_;
    std::size_t size_;
    std::size_t offset_;
};

Az allocate függvény (a reset előfeltételével együtt) igazítja a kért memóriát a alignment paraméterhez. A deallocate szándékosan üres, mert a bump-pointer stratégiában nem szabadítunk fel egyedi blokkokat – ezt a felhasználónak tudnia kell. Az arena nem másolható, mert a memória tulajdonjoga egyértelműen egy példányhoz tartozik.

Most az arena allokátor sablon:

// arena_allocator.hpp
#pragma once
#include <cstddef>
#include <limits>
#include <memory>
#include <new>
#include <type_traits>
#include "arena.hpp"

template <typename T>
class arena_allocator {
public:
    using value_type = T;
    using pointer = T*;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;

    using propagate_on_container_copy_assignment = std::true_type;
    using propagate_on_container_move_assignment = std::true_type;
    using propagate_on_container_swap = std::true_type;
    using is_always_equal = std::false_type;

    template <typename U>
    struct rebind {
        using other = arena_allocator<U>;
    };

    arena_allocator() noexcept = default;

    explicit arena_allocator(arena* a) noexcept : arena_(a) {}

    template <typename U>
    arena_allocator(const arena_allocator<U>& other) noexcept : arena_(other.arena_) {}

    T* allocate(std::size_t n) {
        if (!arena_) throw std::bad_alloc();
        if (n > max_size()) throw std::bad_alloc();
        return static_cast<T*>(arena_->allocate(n * sizeof(T), alignof(T)));
    }

    void deallocate(T* p, std::size_t n) noexcept {
        if (!arena_) return;
        arena_->deallocate(p, n * sizeof(T));
    }

    std::size_t max_size() const noexcept {
        return std::numeric_limits<std::size_t>::max() / sizeof(T);
    }

    arena* get_arena() const noexcept { return arena_; }

    template <typename U>
    friend class arena_allocator;

private:
    arena* arena_ = nullptr;  // állapot: az arena pointer
};

template <typename T, typename U>
bool operator==(const arena_allocator<T>& lhs, const arena_allocator<U>& rhs) noexcept {
    return lhs.get_arena() == rhs.get_arena();
}

template <typename T, typename U>
bool operator!=(const arena_allocator<T>& lhs, const arena_allocator<U>& rhs) noexcept {
    return !(lhs == rhs);
}

Ez az allokátor stateful, mert az arena_ pointer példányonként eltérhet. A propagate_on_container_* típusok std::true_type-ok, így a konténerek másolásakor/mozgatásakor az allokátor is átmásolódik, és az új konténer ugyanarra az arena-ra mutat. Ez azt jelenti, hogy az arena-nak élnie kell mindaddig, amíg bármely konténer használja. A biztonság kedvéért az arena-t általában a konténerek előtt hozzuk létre, és utánuk semmisítjük meg.

14.2.5 Egyedi konténer: arena_vector

Most egy saját, dinamikus tömbként viselkedő konténert készítünk, amely az allokátort használja. A konténer arena_vector<T, Allocator = std::allocator<T>> formában használható; az arena allokátorral a példákban explicit adjuk meg (arena_vector<int, arena_allocator<int>>). A tárolás T*-ot használ, ezért a static_assert kizárja a fancy pointert használó allokátorokat. A hangsúly az allokátor megfelelő használatán és a kivételbiztonságon van.

A konténer minimalista, de tartalmazza a legfontosabb műveleteket: push_back, pop_back, reserve, size, capacity, iterátorok, másolás, mozgatás. A következő kódban a std::allocator_traits-t használjuk, így a konténer automatikusan alkalmazkodik az allokátor képességeihez.

// arena_vector.hpp
#pragma once
#include <algorithm>
#include <cstddef>
#include <memory>
#include <stdexcept>
#include <type_traits>
#include <utility>

template <typename T, typename Allocator = std::allocator<T>>
class arena_vector {
public:
    using allocator_type = Allocator;
    using value_type = T;
    using size_type = std::size_t;
    using difference_type = std::ptrdiff_t;
    using pointer = typename std::allocator_traits<Allocator>::pointer;
    using const_pointer = typename std::allocator_traits<Allocator>::const_pointer;
    using reference = T&;
    using const_reference = const T&;
    using iterator = T*;
    using const_iterator = const T*;

private:
    using alloc_traits = std::allocator_traits<Allocator>;
    // A tárolás nyers T*-ot használ, ezért fancy pointeres allokátort nem támogatunk.
    static_assert(std::is_same_v<pointer, T*>,
                  "arena_vector: csak T* pointertípusú allokátor támogatott");

    allocator_type alloc_;
    T* data_ = nullptr;
    size_type size_ = 0;
    size_type capacity_ = 0;

    void destroy_elements(T* p, size_type n) noexcept {
        for (size_type i = 0; i < n; ++i) {
            alloc_traits::destroy(alloc_, p + i);
        }
    }

    void deallocate_buffer(T* p, size_type cap) noexcept {
        if (p) {
            alloc_traits::deallocate(alloc_, p, cap);
        }
    }

    // Túlcsordulás- és max_size-biztos kapacitásnövelés.
    size_type next_capacity() const {
        const size_type max = alloc_traits::max_size(alloc_);
        if (size_ >= max) throw std::length_error("arena_vector: max_size");
        if (capacity_ > max / 2) return max;
        return capacity_ == 0 ? 1 : capacity_ * 2;
    }

public:
    explicit arena_vector(const Allocator& alloc = Allocator()) noexcept
        : alloc_(alloc) {}

    // Delegáló konstruktor: a célkonstruktor lefutása után az objektum
    // felépítettnek számít, így kivétel esetén a destruktor takarít.
    explicit arena_vector(size_type count, const T& value = T(), const Allocator& alloc = Allocator())
        : arena_vector(alloc) {
        resize(count, value);
    }

    arena_vector(const arena_vector& other)
        : arena_vector(alloc_traits::select_on_container_copy_construction(other.alloc_)) {
        reserve(other.size_);
        for (const auto& elem : other) {
            push_back(elem);
        }
    }

    arena_vector(arena_vector&& other) noexcept
        : alloc_(std::move(other.alloc_)), data_(other.data_), size_(other.size_), capacity_(other.capacity_) {
        other.data_ = nullptr;
        other.size_ = 0;
        other.capacity_ = 0;
    }

    ~arena_vector() {
        destroy_elements(data_, size_);
        deallocate_buffer(data_, capacity_);
    }

    // Másoló értékadás (alapszintű kivételgarancia)
    arena_vector& operator=(const arena_vector& other) {
        if (this == &other) return *this;
        if constexpr (alloc_traits::propagate_on_container_copy_assignment::value) {
            if (alloc_ != other.alloc_) {
                // Előbb az elemek megsemmisítése, aztán a puffer felszabadítása
                // a RÉGI allokátorral, és csak ezután cseréljük az allokátort.
                clear();
                deallocate_buffer(data_, capacity_);
                data_ = nullptr;
                capacity_ = 0;
            }
            alloc_ = other.alloc_;
        }
        clear();
        reserve(other.size_);
        for (const auto& elem : other) {
            push_back(elem);
        }
        return *this;
    }

    // Mozgató értékadás
    arena_vector& operator=(arena_vector&& other) noexcept(
        alloc_traits::propagate_on_container_move_assignment::value ||
        alloc_traits::is_always_equal::value) {
        if (this == &other) return *this;
        clear();
        if constexpr (alloc_traits::propagate_on_container_move_assignment::value) {
            deallocate_buffer(data_, capacity_);  // régi puffer, régi allokátorral
            alloc_ = std::move(other.alloc_);
            data_ = other.data_;
            size_ = other.size_;
            capacity_ = other.capacity_;
            other.data_ = nullptr;
            other.size_ = other.capacity_ = 0;
        } else {
            // Az allokátor nem propagál (ettől a típusa még mozgatható);
            // ha az allokátorok egyenlőek, átvehetjük a puffert.
            if (alloc_ == other.alloc_) {
                deallocate_buffer(data_, capacity_);  // a cél régi puffere
                data_ = other.data_;
                size_ = other.size_;
                capacity_ = other.capacity_;
                other.data_ = nullptr;
                other.size_ = other.capacity_ = 0;
            } else {
                // Kénytelenek vagyunk elemenként átmozgatni.
                reserve(other.size_);
                for (auto& elem : other) {
                    push_back(std::move(elem));
                }
                other.clear();
            }
        }
        return *this;
    }

    // Aliasbiztos beszúrás: ha növelni kell, az értéket előbb lemásoljuk/átvesszük,
    // mert a reserve megsemmisítené a value mögötti régi elemet.
    void push_back(const T& value) {
        if (size_ == capacity_) {
            T tmp(value);
            reserve(next_capacity());
            alloc_traits::construct(alloc_, data_ + size_, std::move(tmp));
        } else {
            alloc_traits::construct(alloc_, data_ + size_, value);
        }
        ++size_;
    }

    void push_back(T&& value) {
        if (size_ == capacity_) {
            T tmp(std::move(value));
            reserve(next_capacity());
            alloc_traits::construct(alloc_, data_ + size_, std::move(tmp));
        } else {
            alloc_traits::construct(alloc_, data_ + size_, std::move(value));
        }
        ++size_;
    }

    void pop_back() {
        if (size_ > 0) {
            alloc_traits::destroy(alloc_, data_ + size_ - 1);
            --size_;
        }
    }

    // Erős garancia csak akkor, ha a T másolható, vagy a mozgató konstruktora nem dob
    // (std::move_if_noexcept); másolhatatlan, dobó mozgatású T-nél csak alapszintű.
    void reserve(size_type new_cap) {
        if (new_cap <= capacity_) return;
        if (new_cap > alloc_traits::max_size(alloc_)) throw std::length_error("arena_vector::reserve");
        T* new_data = alloc_traits::allocate(alloc_, new_cap);
        size_type i = 0;
        try {
            for (; i < size_; ++i) {
                alloc_traits::construct(alloc_, new_data + i, std::move_if_noexcept(data_[i]));
            }
        } catch (...) {
            for (size_type j = 0; j < i; ++j) {
                alloc_traits::destroy(alloc_, new_data + j);
            }
            alloc_traits::deallocate(alloc_, new_data, new_cap);
            throw;
        }
        destroy_elements(data_, size_);
        deallocate_buffer(data_, capacity_);
        data_ = new_data;
        capacity_ = new_cap;
    }

    void resize(size_type count, const T& value = T()) {
        if (count < size_) {
            while (size_ > count) pop_back();
        } else if (count > size_) {
            if (count > capacity_) {
                T tmp(value);  // aliasbiztos: a value a bufferünkre mutathat
                reserve(count);
                for (size_type i = size_; i < count; ++i) {
                    alloc_traits::construct(alloc_, data_ + i, tmp);
                    ++size_;
                }
            } else {
                for (size_type i = size_; i < count; ++i) {
                    alloc_traits::construct(alloc_, data_ + i, value);
                    ++size_;
                }
            }
        }
    }

    void clear() noexcept {
        destroy_elements(data_, size_);
        size_ = 0;
    }

    T& operator[](size_type idx) { return data_[idx]; }
    const T& operator[](size_type idx) const { return data_[idx]; }
    T& at(size_type idx) {
        if (idx >= size_) throw std::out_of_range("arena_vector::at");
        return data_[idx];
    }
    const T& at(size_type idx) const {
        if (idx >= size_) throw std::out_of_range("arena_vector::at");
        return data_[idx];
    }

    T* data() noexcept { return data_; }
    const T* data() const noexcept { return data_; }
    size_type size() const noexcept { return size_; }
    size_type capacity() const noexcept { return capacity_; }
    bool empty() const noexcept { return size_ == 0; }

    iterator begin() noexcept { return data_; }
    const_iterator begin() const noexcept { return data_; }
    const_iterator cbegin() const noexcept { return data_; }
    iterator end() noexcept { return data_ + size_; }
    const_iterator end() const noexcept { return data_ + size_; }
    const_iterator cend() const noexcept { return data_ + size_; }

    allocator_type get_allocator() const { return alloc_; }

    void swap(arena_vector& other) noexcept(
        alloc_traits::propagate_on_container_swap::value ||
        alloc_traits::is_always_equal::value) {
        using std::swap;
        if constexpr (alloc_traits::propagate_on_container_swap::value) {
            swap(alloc_, other.alloc_);
        } else {
            // A szabvány szerint egyenlőtlen, nem propagáló allokátoroknál a swap
            // nem definiált viselkedés; itt kivételt dobunk (noexcept feltételnél
            // ez std::terminate-ra vezethet).
            if (alloc_ != other.alloc_) {
                throw std::logic_error("Cannot swap arena_vector with unequal non-propagating allocators");
            }
        }
        swap(data_, other.data_);
        swap(size_, other.size_);
        swap(capacity_, other.capacity_);
    }
};

template <typename T, typename Allocator>
void swap(arena_vector<T, Allocator>& lhs, arena_vector<T, Allocator>& rhs) noexcept(noexcept(lhs.swap(rhs))) {
    lhs.swap(rhs);
}

A konténer implementációja számos fontos részletet tartalmaz:

  • A select_on_container_copy_construction hívás a másoló konstruktorban az allokátor terjedésének szabványos módja. Ez lehetővé teszi, hogy az allokátor a másoláskor speciális állapotot vegyen fel (pl. friss arena-t).
  • A mozgató konstruktor feltétel nélkül noexcept: az allokátort mozgatja és a puffert átveszi. A feltételes noexcept a mozgató értékadáson van: a propagate_on_container_move_assignment vagy az is_always_equal értékétől függ, mert a nem propagáló, nem egyenlő allokátoros ágban elemenként kell mozgatni, ami kivételt dobhat.
  • A reserve kivételbiztos: ha az elemek konstruálása közben kivétel történik, a már létrehozott elemeket megsemmisíti, az új puffert felszabadítja, majd újradobja a kivételt. Ez erős kivételgaranciát ad, ha a T másolható vagy a mozgató konstruktora nem dob (std::move_if_noexcept); másolhatatlan, dobó mozgatású T-nél a garancia csak alapszintű, mert a korábban átmozgatott forráselemek már megváltozhattak.
  • A push_back az std::allocator_traits::construct-ot használja, ami nem elavult: a C++17-ben elavult és a C++20-ban eltávolított az std::allocator<T>::construct tagfüggvénye. Allokátor-tudatos konténerben az allocator_traits::construct/destroy használata kötelező (így érvényesülnek az allokátor konstrukciós testreszabásai, például a scoped_allocator_adaptor vagy a PMR uses-allocator konstrukció); a std::construct_at megkerülné az allokátort.
  • A push_back és a resize aliasbiztos: ha növelni kell, az értéket a reserve előtt átvesszük (T tmp(value)), mert a reserve megsemmisítené a value mögötti régi elemet (v.push_back(v[0])). A konstruktorok delegálnak az alapkonstruktorra, így részleges felépülés után kivételnél a destruktor takarít. A kapacitás duplázása max_size-ellenőrzött, nem csordulhat túl.

14.2.6 Hibák és buktatók

A saját allokátor és konténer készítése során számos gyakori hiba fordulhat elő:

  • A rebind hiánya vagy helytelen definiálása. Bár a modern allocator_traits kezeli a hiányt, a régi kóddal való együttműködéshez vagy a nem triviális sablonparaméterekhez explicit rebind kell. Ha az allokátor állapottal rendelkezik, a rebind konstruktornak át kell vennie az állapotot.
  • Az allocate és deallocate aszimmetriája. A deallocate-nek pontosan ugyanazt az n értéket kell kapnia, mint az allocate-nak. Ha a konténer nem tárolja a kapacitást, vagy rosszul adja át, a viselkedés nem definiált.
  • A max_size hiánya vagy helytelen értéke. Ez túl nagy foglalási kísérletekhez vezethet, amelyek std::bad_alloc-ot dobnak, de a logikai hibát nehéz észrevenni.
  • A stateful allocator terjedésének elhanyagolása. Ha a propagate_on_container_copy_assignment stb. false, a cél értékadáskor megtartja a saját allokátorát; ez szabályos, de tudni kell róla, hogy az elemek a cél arénájába kerülnek, és a move assignment/swap egyenlőtlen allokátoroknál másképp viselkedik. Hibát a téves feltételezés okoz, nem maga a false érték. Másoló konstrukciónál a select_on_container_copy_construction dönt.
  • Az allokátor egyenlőségének helytelen definiálása. Ha két állapotos allokátor egyenlőnek tekinti magát, pedig különböző erőforrásokat kezelnek, a konténerek optimalizációja (pl. swap) hibás működést okozhat. Az is_always_equal-t összhangban kell tartani az operator== viselkedésével.
  • A kivételbiztonság megsértése a konténerben. Ha a reserve vagy push_back nem kezeli a konstruktorok kivételeit, memóriaszivárgás vagy dupla felszabadítás történhet. A fenti példában a try-catch blokk gondoskodik a takarításról.
  • Az allokátor élettartamának figyelmen kívül hagyása. Ha a stateful allokátor egy külső erőforrásra (pl. arena) mutat, az erőforrásnak élnie kell mindaddig, amíg a konténer használja. Az arena-t általában a konténerek után szabadítjuk fel, vagy megosztott tulajdonlással (shared_ptr) kezeljük.

14.2.7 Labor: reprodukálható build, teszt és mérés

Az alfejezet végén egy ellenőrzött példát mutatunk be. A cél a saját allokátor és a custom container helyes működésének igazolása, valamint egy egyszerű teljesítménymérés.

14.2.7.1 Fordítási környezet

A példát a következő környezetben ellenőriztük (a konkrét verziókat a mérési naplóban rögzítjük):

  • Fordító: g++ 15.2.0 (Ubuntu), Linux x86-64; a Clang és az MSVC nem szerepelt az ellenőrzésben, ott a fordítás és a futás még nem ellenőrzött
  • Szabvány: C++20 (-std=c++20)
  • Tesztbuild: -O2, -DNDEBUG nélkül, hogy az assert-ek ténylegesen ellenőrizzenek; a benchmark külön -O2 -DNDEBUG buildben fut
  • Figyelmeztetések: -Wall -Wextra -Wpedantic
  • Sanitizerek (külön build): -fsanitize=address,undefined

14.2.7.2 A példaprogram

A következő main.cpp egy arena-t hoz létre, abba egy arena_vector<int>-et, és elvégez néhány műveletet. A program ellenőrzi az eredményeket (aliasteszttel és nem triviális std::string elemekkel végzett, különböző arenák közötti értékadással is), és kiírja a felhasznált arena memóriát. A három fejléc mindegyike #pragma once-tal védett, mert az arena_allocator.hpp maga is bevonja az arena.hpp-t; védelem nélkül a main.cpp-ben az arena osztály kétszer definiálódna.

// main.cpp
#include "arena.hpp"
#include "arena_allocator.hpp"
#include "arena_vector.hpp"
#include <cassert>
#include <iostream>
#include <string>

int main() {
    constexpr std::size_t arena_size = 1 << 20; // 1 MiB
    arena ar(arena_size);

    using alloc_t = arena_allocator<int>;
    alloc_t alloc(&ar);
    arena_vector<int, alloc_t> vec(alloc);

    for (int i = 0; i < 1000; ++i) {
        vec.push_back(i);
    }
    assert(vec.size() == 1000);
    assert(vec.capacity() >= 1000);
    assert(ar.used() >= 1000 * sizeof(int));
    assert(ar.used() <= arena_size);

    for (int i = 0; i < 1000; ++i) {
        assert(vec[i] == i);
    }

    // Másolás: az allokátor terjed, ezért a másolat ugyanarra az arena-ra mutat.
    arena_vector<int, alloc_t> vec2 = vec;
    assert(vec2.size() == 1000);
    assert(vec2.get_allocator().get_arena() == &ar);

    // A másolat módosítása nem befolyásolja az eredetit (mély másolás).
    vec2[0] = 42;
    assert(vec[0] == 0);

    // Foglalási összeg levezetése: az 1000 elemig duplázó növekedés
    // 1+2+4+...+1024 = 2047 int = 8188 bájt, a másolat reserve(1000) pedig
    // 4000 bájt; az arena nem használja újra a régi blokkokat: 12188 bájt.
    assert(ar.used() == 12188);

    // Aliasteszt: a saját elemére hivatkozó push_back növekedéskor is helyes.
    arena_vector<int, alloc_t> a(alloc);
    a.push_back(7);
    a.push_back(a[0]);          // size_ == capacity_ == 1: növekedés közben
    assert(a.size() == 2 && a[1] == 7);

    // Nem triviális elemtípus, eltérő arenák közti másoló értékadás (ASan-nal
    // futtatva nem lehet szivárgás).
    arena ar2(arena_size);
    using salloc_t = arena_allocator<std::string>;
    arena_vector<std::string, salloc_t> s1{salloc_t(&ar)};
    arena_vector<std::string, salloc_t> s2{salloc_t(&ar2)};
    for (int i = 0; i < 5; ++i) s1.push_back(std::string(100, 'x'));
    s2.push_back(std::string(100, 'y'));
    s2 = s1;
    assert(s2.size() == 5 && s2.get_allocator().get_arena() == &ar);

    std::cout << "Arena used: " << ar.used() << " bytes\n";
    std::cout << "All tests passed.\n";
    return 0;
}

14.2.7.3 Build parancs

Egy egyszerű Makefile vagy közvetlen g++ parancs elegendő:

g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic -I. main.cpp -o arena_test
./arena_test

A sanitizeres ellenőrzéshez:

g++ -std=c++20 -O1 -g -fsanitize=address,undefined -I. main.cpp -o arena_test_san
./arena_test_san

A tesztet (-DNDEBUG nélkül, az assert-ek aktívak) és a sanitizeres buildet a g++ 15.2.0-val lefuttattuk, mindkettő hibátlanul lefutott (az ASan/UBSan nem jelzett hibát). Clanggel és MSVC-vel nem futtattuk, ezért azokra nem állítunk ellenőrzött eredményt. A mérési napló sablonja:

  • Fordító és verzió: g++ 15.2.0 (Ubuntu); más fordítónál a g++ --version/clang++ --version kimenete (kitöltendő)
  • Szabvány: C++20
  • Optimalizáció: -O2 (tesztbuild, assert aktív); a benchmark: -O2 -DNDEBUG
  • Operációs rendszer: Linux x86-64 (más rendszeren kitöltendő)
  • A teszt determinisztikus, a futásidő nem releváns; a teszt sikerét az assert-ek és a „All tests passed.” kimenet jelzi.
  • Arena-felhasználás (az assert(ar.used() == 12188) ellenőrzi): az 1000 elemig duplázó növekedés 1 + 2 + 4 + … + 1024 = 2047 int = 8188 bájt, mert a bump arena a felszabadított puffereket nem használja újra; a vec2 másolat reserve(1000)-je további 4000 bájt, összesen 12 188 bájt (nem „legfeljebb 8192”). Ez egyben tanulság a bump allokátor memóriapazarlásáról. Az érték a kód növekedési stratégiájából adódik (nem a standard könyvtárból), és az 1 MiB-os arena alatt marad.

14.2.7.4 Egyszerű benchmark

A teljesítmény összehasonlításához az arena_vector-t a std::vector-ral mérjük. Az előző változat mindkét oldalon reserve(N)-nel indult, így egyetlen allokációt végzett, és a push_back ciklust mérte, nem az allokátort; az arena 16 MB-os foglalása pedig az időmérésen belül volt. A mostani benchmark allokációintenzív: 10 000 kis konténert épít egymás után reserve nélkül (100 elem, 1, 2, …, 128 kapacitású növekedéssel), az arena létrehozása az időmérésen kívül, a reset() az időmérésen belül van, steady_clock-kal mér, és az eredményt (ellenőrző összeg) felhasználja, hogy az optimalizáló ne tüntethesse el a munkát:

// benchmark.cpp
#include <chrono>
#include <cstddef>
#include <cstdint>
#include <iostream>
#include <vector>
#include "arena.hpp"
#include "arena_allocator.hpp"
#include "arena_vector.hpp"

template <typename Func>
double measure_us(Func&& f, int runs) {
    double total = 0;
    for (int i = 0; i < runs; ++i) {
        auto start = std::chrono::steady_clock::now();
        f();
        auto end = std::chrono::steady_clock::now();
        total += std::chrono::duration<double, std::micro>(end - start).count();
    }
    return total / runs; // átlag mikroszekundum
}

int main() {
    constexpr std::size_t K = 10'000;  // ennyi kis konténert építünk
    constexpr std::size_t M = 100;     // elem/konténer, reserve NÉLKÜL (növekedés: 1, 2, ..., 128)
    constexpr int runs = 20;
    std::uint64_t sink = 0;            // az eredményt felhasználjuk, hogy a munka ne tűnjön el

    // Az arena létrehozása az időmérésen kívül történik; a reset() az időmérésen belül van.
    // Konténerenként 255 int = 1020 bájt, K * 256 * sizeof(int) bőven elég.
    arena ar(K * 256 * sizeof(int));

    double t1 = measure_us([&] {
        for (std::size_t k = 0; k < K; ++k) {
            std::vector<int> v;
            for (std::size_t i = 0; i < M; ++i) v.push_back(static_cast<int>(i));
            sink += static_cast<std::uint64_t>(v.back());
        }
    }, runs);

    double t2 = measure_us([&] {
        ar.reset();
        arena_allocator<int> alloc(&ar);
        for (std::size_t k = 0; k < K; ++k) {
            arena_vector<int, arena_allocator<int>> v(alloc);
            for (std::size_t i = 0; i < M; ++i) v.push_back(static_cast<int>(i));
            sink += static_cast<std::uint64_t>(v[M - 1]);
        }
    }, runs);

    std::cout << "std::vector:   " << t1 << " us\n";
    std::cout << "arena_vector:  " << t2 << " us\n";
    std::cout << "Arany: " << t2 / t1 << "  (ellenőrző összeg: " << sink << ")\n";
}

A benchmark fordítása és futása (g++ -std=c++20 -O2 -DNDEBUG -I. benchmark.cpp -o benchmark) g++ 15.2.0-val hibátlan volt, de ez a szöveg nem közöl mért időket: azok a futtató gépre, a malloc-implementációra és a terhelésre érzékenyek, a szerkesztői futás pedig nem reprezentatív mérés. A mérési napló kitöltendő:

  • Fordító, kapcsolók: kitöltendő
  • Hardver (CPU, RAM) és OS: kitöltendő
  • std::vector átlagos futási idő (20 futás): kitöltendő (<mért> µs)
  • arena_vector átlagos futási idő (20 futás): kitöltendő (<mért> µs)
  • Szórás/variancia és a nyers futásidők: kitöltendő; arány csak variancia ismeretében értelmezhető

A várt irány (hipotézis, nem eredmény): az arena a malloc/free párokat és az újrafoglalási költséget egyetlen bump-pointer léptetésre cseréli, ezért allokációintenzív terhelésnél lehet gyorsabb, de a memóriahasználata nagyobb, mert a régi blokkokat nem használja újra (lásd fent: 12 188 bájt). Hogy a különbség az allokációs stratégiának tulajdonítható-e, csak az elemfeltöltés és az allokáció külön mérésével, nyers adat és variancia alapján dönthető el.

14.2.8 Összefoglalás

Ebben az alfejezetben egy saját, stateful arena allokátort és egy rá épülő egyedi konténert valósítottunk meg. Láttuk, hogyan működik a rebind, hogyan kell az allocate/deallocate szerződést betartani, és hogyan terjed az allokátor állapota a konténerekben. A kivételbiztos reserve implementációja rávilágított a konténerépítés egyik kritikus pontjára. A labor során reprodukálható buildben (g++ 15.2.0) ellenőriztük a működést, sanitizerekkel teszteltünk, és egy allokációintenzív benchmarkot adtunk, amelynek mért értékeit az olvasó tölti ki. A következő alfejezetben ezeket a fogalmakat bővítjük, amikor a konténerek módosításával és kiterjesztésével foglalkozunk.

14.2.8.1 Önellenőrző kérdések

  1. Mi a rebind szerepe egy allokátorban, és miért van rá szükség a konténerekben?
  2. Mit jelentenek a propagate_on_container_copy_assignment, propagate_on_container_move_assignment és propagate_on_container_swap típusjellemzők? Mi a következménye, ha stateful allokátornál std::false_type-ként vannak definiálva?
  3. Hogyan biztosítja a reserve függvény a kivételbiztonságot? Mi történik, ha a konstruktor kivételt dob?
  4. Miért fontos, hogy az arena_allocator is_always_equal értéke std::false_type legyen? Mi lenne a hiba, ha std::true_type lenne?
  5. Milyen élettartam-szabályt kell betartani az arena és a konténer között? Mi történik, ha az arena megsemmisül, mielőtt a konténer?

Ezek a kérdések segítenek ellenőrizni, hogy az olvasó megértette-e az allokátorok és a konténerek közötti kapcsolatot. A válaszok a fejezet szövegében megtalálhatók.
