15.1 Iterátorkategóriák és hierarchia

Az STL egyik legnagyobb absztrakciós ereje abban rejlik, hogy az algoritmusokat elválasztja az adatszerkezetektől. Ezt az elválasztást az iterátorok teszik lehetővé: egy jól megírt algoritmus nem tudja, hogy az elemek egy std::vector-ban, egy láncolt listában vagy éppen egy bemeneti adatfolyamban vannak-e, csak annyit tud, hogy a kapott iterátor milyen műveleteket támogat. Az iterátorok képességeit a szabvány iterátorkategóriákba sorolja, ezek a kategóriák pedig egy – hagyományosan és a C++20-as conceptekben is – jól definiált hierarchiát alkotnak az input iterátortól a random access (és C++20-tól a contiguous) iterátorig. Ebben az alfejezetben ezt a hierarchiát vizsgáljuk meg, megértjük az iterator_traits szerepét, és egy saját iterátoron keresztül bemutatjuk a helyes kategóriaválasztást és a tipikus hibákat.

15.1.1 Az iterátorkategóriák áttekintése

A C++ szabvány a C++98 óta az input, output, forward, bidirectional és random access kategóriát különbözteti meg, a C++20 pedig hozzáadta a contiguous kategóriát. A bejáró (nem output) kategóriákat az alábbi táblázat foglalja össze; a hagyományos std::iterator_traits<It>::iterator_category ezek közül az első négyet tudja kifejezni, a contiguous kategóriát csak az iterator_concept jelölheti:

Kategória Leírás Tipikus példa
std::input_iterator_tag Csak olvasás, egymenetes bejárás: az iterátor léptetése után a korábbi másolatai nem használhatók tovább (az aktuális elem ismételt olvasása *it-tel megengedett). std::istream_iterator<T>
std::forward_iterator_tag Olvasás, többmenetes bejárás: ugyanaz a sorozat többször is bejárható, az iterátor másolatai egymástól függetlenek. std::forward_list<T>::iterator
std::bidirectional_iterator_tag A forward iterátor összes képessége, valamint a visszafelé lépés (operator--). std::list<T>::iterator
std::random_access_iterator_tag A bidirectional iterátor összes képessége, valamint konstans idejű tetszőleges elérés (operator[], operator+, operator-, rendezési relációk). std::vector<T>::iterator, beépített pointer
std::contiguous_iterator_tag C++20-tól: a random access iterátor képességei, és garantáltan folytonos memóriában lévő elemekre mutat, így a pointer-aritmetika érvényes. std::vector<T>::iterator, std::array<T,N>::iterator, std::span<T>::iterator

Fontos megjegyezni, hogy az output_iterator_tag nem illeszkedik ebbe a hierarchiába: az output iterátor írásra szolgál, és képességei nem tartalmazzák a fenti „bejáró” iterátorok tulajdonságait. Egy output iterátor lehet akár csak írási, egymenetes, és nem feltétlenül összehasonlítható. A std::ostream_iterator<T> és a std::back_insert_iterator<Container> tipikus példák. A hierarchia tehát a bejárási irány és az elérési mód szerinti, és az output iterátor külön ágként kezelendő.

A C++20 bevezette a concept-eket, amelyek az iterátorkategóriákat sokkal pontosabban definiálják. A std::input_iterator, std::forward_iterator, std::bidirectional_iterator, std::random_access_iterator és std::contiguous_iterator conceptek hierarchiája megegyezik a fenti tag-osztályok által képviselt sorrenddel, de a conceptek a tényleges műveleteket és a szemantikát is ellenőrzik, nem csupán egy típusdefiníciót. Ezenkívül a std::input_or_output_iterator concept az alap, amely minden iterátorra igaz, beleértve az output iterátorokat is. A gyakorlatban a modern kódban ezeket a concepteket használjuk, de a régebbi kódokkal való kompatibilitás miatt az iterator_category tag továbbra is fontos.

15.1.2 Az iterator_traits szerepe

Az algoritmusok számára az iterátor tulajdonságait (mint például az elem típusa, a különbség típusa, a referencia típusa és a kategória) egységes módon kell elérni. Erre szolgál a std::iterator_traits<It> sablon. Az iterator_traits elsődleges sablonja az iterátor belső típusdefinícióit használja; az alábbi kód egyszerűsített vázlat: C++20-ban az elsődleges sablon további fallbackeket tartalmaz (ha a tagtípusok hiányoznak, de az iterátor teljesíti a Cpp17-iterátor követelményeket, a típusokat az iterátor műveleteiből vezeti le; egyébként a sablon üres):

template<class It>
struct iterator_traits {
    using value_type        = typename It::value_type;
    using difference_type   = typename It::difference_type;
    using pointer           = typename It::pointer;
    using reference         = typename It::reference;
    using iterator_category = typename It::iterator_category;
};

Az STL kompatibilitás érdekében a beépített pointerekre is van specializáció:

template<class T>
struct iterator_traits<T*> {
    using value_type        = std::remove_cv_t<T>;
    using difference_type   = std::ptrdiff_t;
    using pointer           = T*;
    using reference         = T&;
    using iterator_category = std::random_access_iterator_tag;
    using iterator_concept  = std::contiguous_iterator_tag;    // C++20-tól; az iterator_category a kompatibilitás miatt marad random access
};

A C++20 szabvány bevezetett további segédtípusokat is, amelyek az iterator_traits-ra épülnek, de a conceptekkel jobban integrálhatók:

  • std::iter_value_t<It> – az iterátor value_type-ja.
  • std::iter_reference_t<It> – a *it kifejezés tényleges típusa (decltype(*it)); ez nem feltétlenül egyezik az iterátor reference tagtípusával.
  • std::iter_difference_t<It> – az iterátor difference_type-ja.
  • std::iter_rvalue_reference_t<It> – a ranges::iter_move(it) típusa; proxy iterátornál ez érték vagy proxy is lehet, nem feltétlenül rvalue referencia.
  • std::iter_common_reference_t<It> – a std::common_reference_t<iter_reference_t<It>, iter_value_t<It>&> típus.

Ezek a típusok a conceptekben és a generikus kódban teszik lehetővé, hogy az iterátor tulajdonságait anélkül kérdezzük le, hogy közvetlenül az iterator_traits-ot bántanánk.

15.1.3 Az egyes kategóriák műveleti követelményei

A kategóriák közötti különbségek a támogatott műveletekben és azok szemantikájában rejlenek. Az alábbiakban röviden összefoglaljuk a legfontosabb elvárásokat. (A pontos formális követelményeket a szabvány és a cppreference definiálja; itt a gyakorlati megértésre helyezzük a hangsúlyt.)

15.1.3.1 Input iterátor

Egy input iterátor (std::input_iterator concept) a következő műveleteket támogatja:

  • *it – az aktuális elem olvasása (a típusa lehet érték vagy referencia).
  • ++it és it++ – előre lépés (az it++ visszatérési értéke input iterátornál nem feltétlenül a régi iterátor másolata).
  • A mozgathatóság (a std::weakly_incrementable a std::movable-t követeli; a másolhatóság az input iterátornál nem feltétel, a move-only iterátor is lehet).

A C++20 std::input_iterator nem követel egyenlőség-összehasonlítást a saját típusával (a sorozat végét egy külön sentinel jelzi, lásd std::sentinel_for), és nem követel alapértelmezett konstruálhatóságot sem (a P2325R3 hibajavítás kivette a weakly_incrementable-ből). A hagyományos (Cpp17InputIterator, iterator_traits-alapú) modell szigorúbb; a két modell közti különbséget az alábbi táblázat foglalja össze.

Követelmény Cpp17InputIterator (régi) std::input_iterator (C++20)
it1 == it2 ugyanazon típuson igen nem (sentinel is lehet)
másolhatóság igen nem, elég a mozgathatóság
alapértelmezett konstruálhatóság nem (a Cpp17ForwardIterator-tól igen) nem (a forward_iterator-tól igen)
it++ visszatérési típusa a régi érték másolata (dereferálható) tetszőleges (void is lehet)

Az input iterátor egymenetes: ha egyszer már továbbléptünk, nem feltétlenül tudunk visszamenni, és a korábbi másolatok esetleg érvénytelenek lesznek. Az operator* eredménye lehet prvalue is (pl. egy generáló iterátornál), így nem garantált, hogy az eredmény címe stabil. Az std::istream_iterator<int> tipikus példa: a bemeneti folyamot olvassa, minden ++ művelet új elemet olvas be; a *it a gyorsítótárazott értékre const T&-t ad.

15.1.3.2 Forward iterátor

A forward iterátor (std::forward_iterator) mindent tud, amit az input iterátor, de többmenetes: a sorozat többször is bejárható, és az iterátor másolatai függetlenek. A std::forward_iterator concept az std::input_iterator-t, az std::incrementable-t (ami másolhatóságot, alapértelmezett konstruálhatóságot és egyenlőség-összehasonlíthatóságot, azaz regular-t jelent), valamint a std::sentinel_for<It, It>-t követeli meg; az iterator_concept (vagy iterator_category) legalább forward_iterator_tag. A C++20 concept nem követeli meg, hogy a reference lvalue referencia legyen: proxy vagy prvalue dereferálás is megengedett (pl. a std::views::iota iterátora prvalue-t ad, mégis random access). Az lvalue-referencia követelmény a régi Cpp17ForwardIterator követelménye, és az iterator_category = forward_iterator_tag állítás jogosságához tartozik. A forward iterátor lehetővé teszi a std::forward_list vagy egy saját láncolt lista bejárását.

15.1.3.3 Bidirectional iterátor

A bidirectional iterátor (std::bidirectional_iterator) a forward iterátor összes képességét bővíti a hátrafelé lépéssel: --it és it-- műveletek. Ezáltal olyan adatszerkezetek bejárhatók, amelyekben a visszafelé mutató link is rendelkezésre áll, mint például a std::list vagy a std::set. A bidirectional iterátor a fordított bejárást is támogatja, ami lehetővé teszi a std::reverse_iterator használatát.

15.1.3.4 Random access iterátor

A random access iterátor (std::random_access_iterator) a bidirectional iterátor képességeit egészíti ki konstans idejű tetszőleges eléréssel:

  • it + n, it - n, it += n, it -= n, n + it – az iterátor léptetése egész számmal.
  • it[n] – az n-edik elem elérése (ekvivalens *(it + n)-nel).
  • it1 - it2 – két iterátor különbsége (visszatérési típus difference_type).
  • Rendezési relációk: it1 < it2, it1 > it2, it1 <= it2, it1 >= it2 – ezek a műveletek a mutatott elemek sorrendjét tükrözik.

A beépített pointer természetesen teljesíti ezeket a követelményeket, és a std::vector<T>::iterator is (a szabvány megengedi, hogy pointer legyen, de a libstdc++, a libc++ és az MSVC STL is osztályt használ; ezért nem szabad T*-ként kezelni, a nyers pointert std::to_address(it) vagy v.data() adja). A random access iterátorok lehetővé teszik a std::sort, a std::binary_search és más, indexelést igénylő algoritmusok hatékony használatát.

15.1.3.5 Contiguous iterátor (C++20)

A C++20 bevezette a std::contiguous_iterator conceptet, amely a random access iterátor képességeit tovább szigorítja: az iterátor által mutatott elemek folytonos memóriaterületen helyezkednek el, és a pointer-aritmetika érvényes. Ez azt jelenti, hogy ha it egy ilyen iterátor, akkor a *(it + n) ekvivalens a *(std::to_address(it) + n) kifejezéssel. A std::vector, std::array, std::basic_string és a std::span iterátorai contiguous iterátorok. Ez a tulajdonság kritikus például a std::memcpy-vel való optimalizálásokhoz vagy a C API-kkal való átjárhatósághoz.

A contiguous_iterator_tag C++20 előtt nem létezett, ezért a C++20-as kódban egy iterátor iterator_concept tagje lehet std::contiguous_iterator_tag, míg az iterator_category tagje továbbra is std::random_access_iterator_tag marad a kompatibilitás érdekében. A conceptek az ITER_CONCEPT kiválasztási algoritmussal döntenek: ha az iterator_traits<It> az elsődleges sablonból generálódik, akkor az It::iterator_concept tagot (ennek hiányában az It::iterator_category-t) nézik, egyébként az iterator_traits<It> megfelelő tagját (a pointer-specializáció iterator_concept-je contiguous_iterator_tag). Az elsődleges iterator_traits maga nem definiál iterator_concept tagot.

Megjegyzés a std::vector<bool> iterátorára: proxy referenciát ad, ezért nem contiguous (és a Cpp17ForwardIterator követelményei sem teljesülnek), de a C++20 concept szerint random access lehet. A contiguous elrendezés pedig önmagában nem teszi a T elemtípust triviálisan másolhatóvá: a memcpy-optimalizáció külön feltétele a trivial copyability és az élettartam.

15.1.3.6 Output iterátor

Az output iterátor (std::output_iterator<It, T> concept) az írásra szolgál. A *it = value művelet kiírja az értéket, a ++it pedig továbblép a következő írási pozícióra. Az output iterátor általában egymenetes, és nem feltétlenül támogatja az olvasást vagy az összehasonlítást. Példák: std::ostream_iterator<int>, std::back_insert_iterator<std::vector<int>>, std::insert_iterator<std::set<int>>. A C++20 std::output_iterator concept két paramétert vár: az iterátor típusát és az írandó érték típusát, így ellenőrzi, hogy a *it = value kifejezés érvényes-e.

15.1.4 Az iterátorkategóriák és a C++20 conceptek kapcsolata

A C++20 szabvány az iterátorokat a <iterator> fejlécben definiált conceptekkel írja le. A hierarchia a következő:

  • std::input_or_output_iterator – az alap, minden iterátorra igaz.
  • std::input_iterator – az input_or_output_iterator-t bővíti olvasási képességekkel.
  • std::forward_iterator – az input_iterator-t bővíti többmenetes bejárással.
  • std::bidirectional_iterator – a forward_iterator-t bővíti a -- támogatásával.
  • std::random_access_iterator – a bidirectional_iterator-t bővíti a véletlen eléréssel.
  • std::contiguous_iterator – a random_access_iterator-t bővíti a folytonos memória garanciával.

Ezen kívül külön concept az std::output_iterator<It, T>, amely az írási képességet ellenőrzi.

Fontos, hogy a conceptek nem csupán a iterator_category típusdefiníciót nézik, hanem a tényleges műveletek meglétét és a visszatérési típusokat is. Ez lehetővé teszi, hogy egy iterátor akkor is teljesítse a conceptet, ha az iterator_category tag hiányzik, feltéve, hogy a szükséges műveletek rendelkezésre állnak. (A C++20 iterator_traits a hiányzó tagtípusokat bizonyos feltételekkel az iterátor műveleteiből vezeti le, de a levezetett kategória nem feltétlenül a szándékolt, ezért a gyakorlatban érdemes a tag-eket megadni.) A conceptek a szintaxist ellenőrzik; a szemantikai (többmenetes, komplexitási) követelményeket a fordító nem bizonyítja.

15.1.5 Gyakorlati példa: egyszerű forward iterátor láncolt listához

A kategóriák megértéséhez hozzunk létre egy minimális, saját láncolt listát, amelynek iterátora forward iterátor. A példa szemlélteti a szükséges típusdefiníciókat, a műveleteket, és azt, hogyan ellenőrizhetjük a conceptekkel a kategóriát. A kód C++20-as, de a hagyományos iterator_category tag-et is tartalmazza.

// Fordítás: g++ -std=c++20 -Wall -Wextra -pedantic forward_list_demo.cpp
#include <iterator>
#include <cstddef>
#include <concepts>
#include <memory>
#include <type_traits>
#include <iostream>
#include <algorithm>
#include <vector>

// Minimális csomópont
template <typename T>
struct Node {
    T data;
    Node* next = nullptr;
};

// Forward iterátor a láncolt listához
template <typename T>
class ForwardListIterator {
public:
    // ----- Iterator traits -----
    using value_type        = T;
    using difference_type   = std::ptrdiff_t;
    using pointer           = T*;
    using reference         = T&;
    using iterator_category = std::forward_iterator_tag; // Hagyományos jelölés
    // C++20: az iterator_concept megadása opcionális; ha hiányzik,
    // a conceptek az iterator_category-t használják.
    using iterator_concept  = std::forward_iterator_tag;

    // Konstruktorok
    ForwardListIterator() = default;
    explicit ForwardListIterator(Node<T>* node) : current_(node) {}

    // Hozzáférés
    reference operator*() const { return current_->data; }
    pointer operator->() const { return std::addressof(current_->data); }

    // Léptetés
    ForwardListIterator& operator++() {
        current_ = current_->next;
        return *this;
    }
    ForwardListIterator operator++(int) {
        ForwardListIterator tmp = *this;
        ++(*this);
        return tmp;
    }

    // Összehasonlítás
    bool operator==(const ForwardListIterator& other) const {
        return current_ == other.current_;
    }
    // C++20: az operator!= automatikusan generálódik az operator== -ből,
    // de explicit is megadható a régebbi szabványokhoz.

private:
    Node<T>* current_ = nullptr;
};

// Egyszerű láncolt lista konténer
template <typename T>
class SimpleForwardList {
public:
    using iterator = ForwardListIterator<T>;

    SimpleForwardList() = default;
    // A lista a csomópontok egyedüli tulajdonosa: a másolás tiltott (az implicit
    // másolás két listát ugyanarra a láncra irányítana, és kettős törlést okozna).
    SimpleForwardList(const SimpleForwardList&) = delete;
    SimpleForwardList& operator=(const SimpleForwardList&) = delete;
    ~SimpleForwardList() {
        while (head_) {
            Node<T>* next = head_->next;
            delete head_;
            head_ = next;
        }
    }

    void push_front(const T& value) {
        Node<T>* newNode = new Node<T>{value, head_};
        head_ = newNode;
    }

    iterator begin() { return iterator(head_); }
    iterator end()   { return iterator(nullptr); }

private:
    Node<T>* head_ = nullptr;
};

int main() {
    // Statikus ellenőrzés: az iterátor teljesíti a forward_iterator conceptet
    static_assert(std::forward_iterator<ForwardListIterator<int>>);
    static_assert(std::input_iterator<ForwardListIterator<int>>);
    // Nem teljesíti a bidirectional_iterator-t, mert nincs operator--
    static_assert(!std::bidirectional_iterator<ForwardListIterator<int>>);

    // Az iterator_traits ellenőrzése
    static_assert(std::same_as<std::iterator_traits<ForwardListIterator<int>>::iterator_category,
                               std::forward_iterator_tag>);
    static_assert(std::same_as<std::iter_value_t<ForwardListIterator<int>>, int>);
    static_assert(std::same_as<std::iter_reference_t<ForwardListIterator<int>>, int&>);

    SimpleForwardList<int> list;
    list.push_front(3);
    list.push_front(2);
    list.push_front(1);

    // Algoritmus használata
    std::for_each(list.begin(), list.end(), [](int x) { std::cout << x << ' '; });
    std::cout << '\n';

    // A std::copy input iterátorral is működik; itt a másolat tartalmát ellenőrizzük
    std::vector<int> from_list;
    std::copy(list.begin(), list.end(), std::back_inserter(from_list));
    // from_list: {1, 2, 3}

    // A std::max_element többmenetes bejárást igényel: legalább forward iterátor kell
    auto it = std::max_element(list.begin(), list.end());
    std::cout << *it << '\n'; // 3
}

Ez a példa bemutatja:

  • A szükséges öt típusdefiníciót (value_type, difference_type, pointer, reference, iterator_category).
  • A C++20 iterator_concept megadását (opcionális, de hasznos).
  • A static_assert-ekkel történő ellenőrzést a conceptek és az iterator_traits alapján.
  • A std::for_each és std::copy használatát (ezek input iterátorral is működnek), valamint a std::max_element-et, amely forward iterátort igényel, mert többmenetes bejárás kell hozzá.
  • A static_assert-ek csak a szintaktikai követelményeket ellenőrzik; a szemantikát (többmenetesség, a másolatok függetlensége) külön tesztelni kell.
  • Az operator-> a std::addressof-ot használja, mert egy túlterhelt operator&-del rendelkező T esetén a &current_->data nem T*-ot adna.

15.1.6 Tipikus hibák és elkerülésük

Az iterátorok implementálása során számos gyakori hiba fordul elő, amelyek közül a legfontosabbakat érdemes ismerni.

15.1.6.1 Hiányzó vagy helytelen iterator_category

Ha az iterátor osztály nem definiálja mind az öt tagtípust, C++20 előtt az std::iterator_traits üres vagy hibás volt, C++20-tól pedig megpróbálja levezetni a típusokat az iterátor műveleteiből; a levezetett kategória azonban nem feltétlenül az, amit szánunk, és a hagyományos, iterator_traits-ra épülő algoritmusok (különösen a régebbi kódok) pontos tagokat várnak. Ezért mindig adjuk meg az öt típusdefiníciót közvetlenül az iterátorban (a régebbi kódban látható std::iterator bázisosztály C++17 óta elavult, új kódban ne használjuk).

15.1.6.2 Helytelen reference típus

A hagyományos Cpp17ForwardIterator modellben a reference típusnak lvalue referencia típusúnak kell lennie (pl. T&): ha egy iterátor iterator_category-ja forward_iterator_tag (vagy erősebb), de az operator* prvalue-t vagy proxyt ad, a régi (iterator_traits-alapú) algoritmusok a Cpp17 követelményekre építenek, és hibásan viselkedhetnek. A C++20 std::forward_iterator concept ezt nem követeli meg: egy reference = int, operator* → int iterátor is kielégíti, ezért a concept-alapú (ranges) kód elfogadja, a régi algoritmusok számára viszont az iterator_category nem lehet forward_iterator_tag. A proxy iterátor helyes mintája: iterator_concept = forward_iterator_tag (vagy erősebb), iterator_category = input_iterator_tag. Például a std::vector<bool> iterátora proxy referenciát ad (iter_reference_t nem bool&), ezért a Cpp17 modell szerint csak input iterátor, a C++20 conceptek szerint viszont std::random_access_iterator (de nem std::contiguous_iterator).

15.1.6.3 A postincrement (operator++(int)) helytelen visszatérési típusa

A postincrement operátornak a régi iterátor másolatát kell visszaadnia (általában érték szerint), nem referenciát. Ha referenciát adunk vissza, az érvénytelen lehet a függvényből való visszatérés után (dangling reference). A legtöbb implementációban a postincrement a fenti mintát követi: másolatot készít, előlépteti az aktuális iterátort, majd visszaadja a másolatot.

15.1.6.4 Hiányzó operator== vagy operator!=

A C++20 előtt mindkét összehasonlító operátort meg kellett adni. Bár a C++20-ban az operator!= automatikusan generálódik az operator==-ből, a régebbi szabványokkal való kompatibilitás érdekében érdemes mindkettőt explicit definiálni, vagy a C++20-ra támaszkodni, ha a projekt csak azt támogatja. A std::input_or_output_iterator és a std::input_iterator concept nem követeli meg az ==-t (a sorozat végét sentinel is jelezheti); a std::forward_iterator és az erősebb kategóriák igen.

15.1.6.5 A difference_type rossz megválasztása

A difference_type-nak előjeles egész típusnak kell lennie, amely képes reprezentálni a konténer két iterátora közötti maximális különbséget. Általában std::ptrdiff_t a megfelelő választás. Ha túl kicsi típust választunk (pl. int egy hatalmas konténerhez), túlcsordulás léphet fel. A std::iter_difference_t<It> segítségével ellenőrizhetjük.

15.1.6.6 A std::iterator_traits specializáció hiánya beépített pointerekre

Ez nem a saját iterátor hibája, de a generikus kód írásakor gondolni kell arra, hogy a beépített pointerek is iterátorok, és az std::iterator_traits már tartalmazza a szükséges specializációt. Ha saját iterator_traits-t írunk, ne feledkezzünk meg a pointerek specializációjáról, különben a pointereket használó algoritmusok nem fognak működni.

15.1.6.7 Az iterator_concept és az iterator_category összekeverése C++20-ban

A C++20 bevezette az iterator_concept típusdefiníciót, amely a conceptek által használt kategóriát pontosítja. Ha egy iterátor iterator_category-ja std::random_access_iterator_tag, de a tényleges műveletei nem teljesítik a random access követelményeit, akkor a std::random_access_iterator concept hamis lesz, annak ellenére, hogy az iterator_category azt állítja. Ha az iterátor megadja az It::iterator_concept tagot (az iterator_traits elsődleges sablonja esetén), a conceptek az ITER_CONCEPT algoritmus szerint ezt használják; az iterator_category ettől függetlenül a régi algoritmusok számára jelöl kategóriát, és lehet gyengébb (pl. proxy iterátornál input_iterator_tag), de soha nem ígérhet többet, mint amit az iterátor valóban tud. A legtöbb esetben a kettő megegyezik.

15.1.7 Labor: iterátorkategória-teszt készítése

A labor célja, hogy a fenti ismereteket egy reprodukálható, ellenőrizhető példán keresztül gyakoroljuk. A feladat egy saját iterátor implementálása, amely legalább forward iterátor, és annak ellenőrzése static_assert-ekkel és futási tesztekkel. Az alábbiakban egy lehetséges laborleírást adunk, amelyet az olvasó önállóan végezhet el.

15.1.7.1 Feladat

  1. Hozzunk létre egy saját, egyszerű konténert (pl. egy láncolt lista, mint a fenti SimpleForwardList, de lehet más is, például egy dinamikus tömb vagy egy fix méretű tömb; a konténer tulajdonkezelését is határozzuk meg: másolás tiltása vagy mély másolat).
  2. Implementáljunk hozzá egy iterátort, amely legalább forward iterátor kategóriájú. Ha kedvünk tartja, készíthetünk bidirectional vagy random access iterátort is.
  3. Az iterátor osztályban adjuk meg a szükséges típusdefiníciókat (value_type, difference_type, pointer, reference, iterator_category, és opcionálisan iterator_concept).
  4. Írjunk static_assert-eket annak ellenőrzésére, hogy az iterátor teljesíti-e a std::forward_iterator (vagy magasabb) conceptet, és hogy az std::iterator_traits megfelelő típusokat ad vissza.
  5. Írjunk egy main() függvényt, amely feltölti a konténert, bejárja az elemeit std::for_each segítségével, és ellenőrzi a helyes sorrendet.
  6. Készítsünk build parancsot, amely legalább GCC és Clang fordítóval, -std=c++20 kapcsolóval, -Wall -Wextra -pedantic figyelmeztetésekkel fordít. Futtassuk a programot, és rögzítsük a kimenetet.
  7. (Opcionális) Adjunk hozzá egy tesztesetet, amely a std::copy-t használja, és ellenőrzi, hogy a másolás helyesen működik.
  8. A mérési naplóban rögzítsük a használt fordítót, verziót, standardverziót, a program kimenetét, és a static_assert-ek sikerességét (fordítási időben). A mért és a várt eredményt külön jelöljük.

15.1.7.2 Példa a laborhoz (részlet)

A fenti SimpleForwardList példa jó kiindulópont, amelyet az olvasó kiegészíthet a static_assert-ekkel és a build scripttel. Az alábbi kódrészlet a fenti teljes példa után illeszthető be (önállóan nem fordul):

// Az iterátor típusa: SimpleForwardList<int>::iterator
using It = SimpleForwardList<int>::iterator;

static_assert(std::forward_iterator<It>);
static_assert(std::input_iterator<It>);
static_assert(!std::bidirectional_iterator<It>); // ha nincs operator--
static_assert(std::same_as<std::iter_value_t<It>, int>);
static_assert(std::same_as<std::iter_reference_t<It>, int&>);
static_assert(std::same_as<std::iter_difference_t<It>, std::ptrdiff_t>);
static_assert(std::same_as<std::iterator_traits<It>::iterator_category,
                           std::forward_iterator_tag>);

A build parancs (Linux környezetben, GCC):

g++ -std=c++20 -Wall -Wextra -pedantic -O2 -o iterator_lab iterator_lab.cpp

Futtatás:

./iterator_lab

Várt kimenet (a példában szereplő lista {1, 2, 3} esetén; két sor):

1 2 3 
3

Az első sor a for_each, a második a max_element eredménye; az első sor végén szóköz van.

A mérési naplóban ezt rögzíteni kell. A static_assert-ek fordítási időben futnak le, így ha a program lefordult, azok sikeresek.

15.1.7.3 Kiértékelés

A labor értékelésekor a következőket ellenőrizzük:

  • Az iterátor típusdefiníciói helyesek-e.
  • A static_assert-ek sikeresek-e.
  • A program futása a várt kimenetet produkálja-e.
  • A build script reprodukálható-e (a parancs lefuttatható).
  • A mérési napló tartalmazza-e a szükséges adatokat (fordító, verzió, standard, kimenet, várt vs. mért).

15.1.8 Önellenőrző kérdés

Az alábbi kérdéssel ellenőrizhetjük, hogy megértettük-e az anyagot:

Kérdés: Egy iterátor osztály a következő típusdefiníciókat tartalmazza:

using value_type        = int;
using difference_type   = std::ptrdiff_t;
using pointer           = int*;
using reference         = int;
using iterator_category = std::forward_iterator_tag;

Mi a probléma ebben a definícióban, és hogyan javítanánk? Teljesül-e emiatt a C++20 std::forward_iterator concept, és mi a helyzet a hagyományos (Cpp17) követelményekkel?

Válasz: A hagyományos Cpp17ForwardIterator követelmény szerint a reference lvalue referencia kell legyen, tehát a reference = int mellett az iterator_category = std::forward_iterator_tag állítás hamis: a régi algoritmusok a stabil címre építhetnek. A C++20 std::forward_iterator concept viszont nem követeli meg az lvalue referenciát, ezért (ha az operátorok egyébként rendben vannak) a concept teljesülhet; az iter_reference_t ilyenkor int. A javítás attól függ: ha az elemek valódi tárolóban vannak, using reference = int&; (és operator* ennek megfelelően referenciát ad); ha az iterátor értéket állít elő (pl. generáló iterátor), iterator_concept = std::forward_iterator_tag, iterator_category = std::input_iterator_tag.

Ez a kérdés a régi és az új iterátormodell közti különbséget emeli ki.

Ezzel az alfejezettel lefedtük az iterátorkategóriák hierarchiáját az input iterátortól a random access (és contiguous) iterátorig, megismertük az iterator_traits szerepét, és egy gyakorlati példán keresztül bemutattuk a helyes implementációt és a tipikus hibákat. A következő alfejezetben (15.2) a saját iterátorok készítésének részleteire térünk ki, építve az itt bevezetett fogalmakra.
