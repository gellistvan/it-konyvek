42.4 C++23 range-algoritmusok és ranges-labor

A C++20 ranges alapjai után a C++23 több olyan algoritmust tett a std::ranges névtérbe, amelyeket addig csak kézzel, ciklussal vagy a régi <numeric>/<algorithm> függvényekkel lehetett megoldani. Ez a rész ezeket a szerződés oldaláról tárgyalja: mi a pontos visszatérési típus, milyen range-kategória kell, mi történik üres bemenetnél, és hol tér el a viselkedés a megszokott std::accumulate-től. A záró labor egy naplóelemző pipeline-t épít fel kétszer, C++20-ban és C++23-ban, hogy a különbség ne csak stílusbeli legyen, hanem mérhető és ellenőrizhető.

A rész alapprofilja ISO C++23, -std=c++23. A konkrét fordító- és könyvtárverzió támogatását itt nem tekintjük ellenőrzöttnek: minden új képességhez feature-test makrót és compile probe-ot adunk, és ahol szükséges, fallbacket jelzünk. A C++20-ban már bevezetett ranges-alapokat (projection, sentinel, view pipeline, borrowed range) nem tanítjuk újra; ezekre a Ranges algoritmusok, projection és sentinel (30.3) és Szeletelő és átalakító view-k: chunk, slide, chunk_by, stride, join_with (42.3) részekre hivatkozunk.

42.4.1 A fold család: bal- és jobbasszociatív összegzés

A std::ranges::fold_left, fold_right, fold_left_first és fold_right_last a P2322 javaslat nyomán került a szabványba. Közös jellemzőjük, hogy determinisztikus sorrendben dolgozzák fel a range elemeit, ellentétben a C++17-es std::reduce-dzsel, amelynek a sorrendje nem meghatározott, és amely ezért nem is használható nem asszociatív művelettel. A foldok mindig balról jobbra, illetve jobbról balra haladnak, így a művelet asszociativitása nem követelmény.

A fold_left lényegében a ranges-esített accumulate. A deklarációja leegyszerűsítve:

template <std::input_range R, class T, class F>
  constexpr auto fold_left(R&& r, T init, F f);
  // a visszatérési típus: decay_t<invoke_result_t<F&, T, range_reference_t<R>>>

A visszatérési típus a hívott művelet eredménytípusa (decay-elve), az init ehhez konvertálódik; ez eltér a std::accumulate-től, amelynek akkumulátora az init típusa. Ezért a fold_left(v, 0, std::plus<>{}) long long elemeknél long long marad, és nem csordul túl, míg a std::accumulate(v.begin(), v.end(), 0) ugyanezen adatra int-ben fut. Az init típusa tehát csak akkor számít, ha a művelet nem bővít (például [](int a, int b){ return a + b; }). A f hívása f(acc, *it) alakú, és a követelmény, hogy az init és az eredmény a művelet típusába konvertálható legyen. A fold_right ugyanezt jobbról teszi, de bidirectional_range-et igényel, mert hátulról kell indulnia, és a művelet argumentumsorrendje megfordul: f(*it, acc).

A fold_left_first kezdőérték nélkül dolgozik: az első elemet használja kezdőértékként, ezért üres range esetén std::nullopt-ot ad vissza, nem hibát. A visszatérési típus std::optional<U>, ahol U = std::decay_t<std::invoke_result_t<F&, range_value_t<R>, range_reference_t<R>>>, tehát ez is a művelet eredménytípusa: ha az elemek int-ek, de a művelet double-t ad, az eredmény optional<double>. A fold_right_last ugyanez jobbról, szintén bidirectional_range-en.

A std::accumulate és a fold_left viszonya: az accumulate C++98 óta létezik, nincs sentinel-támogatása, és az akkumulátora az init típusa (C++20 óta constexpr). A fold_left ugyanazt a balról jobbra haladó szemantikát adja, de ranges-interfésszel (range vagy iterátor + sentinel) és constexpr-rel; projection-paramétere – a többi ranges-algoritmustól eltérően – nincs, a mezőkiválasztást views::transform-mal végezzük a fold előtt. A fold_right viszont olyan műveletet tesz lehetővé, amelynek az argumentumsorrendje számít, például nem kommutatív összefűzést.

Nézzünk egy kidolgozott példát, amely bemutatja az init típusának szerepét:

#include <algorithm>
#include <cassert>
#include <functional>
#include <vector>

std::vector<long long> v{1'000'000'000LL, 2'000'000'000LL, 3'000'000'000LL};

// A fold_left akkumulátora a művelet eredménytípusa: long long, 6000000000,
// az int típusú 0 init nem szűkít.
long long a = std::ranges::fold_left(v, 0, std::plus<>{});
long long b = std::ranges::fold_left(v, 0LL, std::plus<>{});

// Ellenpélda: a std::accumulate akkumulátora az init típusa (int),
// a részeredmények int-té szűkülnek, és a signed túlcsordulás UB
// (gyakorlatban 1705032704 jellegű, implementációfüggő eredmény).
// long long bad = std::accumulate(v.begin(), v.end(), 0);   // NE

A fold_left_first helyes használata:

#include <optional>
#include <ranges>

std::optional<long long> first_sum(const std::vector<long long>& v) {
    return std::ranges::fold_left_first(v, std::plus<>{});
}

void use(const std::vector<long long>& v) {
    if (auto s = first_sum(v)) {
        // *s csak akkor érvényes, ha a range nem volt üres.
    }
}

A fold_left_first eredménytípusa szintén a művelet eredményéből származik; int elemeknél std::plus<> mellett optional<int>, tehát ott a nagy összeg túlcsordulhat. Ilyenkor a műveletnek kell bővítenie (például [](long long a, int b){ return a + b; } vagy views::transform előtte). Ez nem a fold hibája, hanem a típusválasztásé.

42.4.2 Kereső és összehasonlító algoritmusok

A C++23 három, egymáshoz szorosan kapcsolódó csoportot adott a <algorithm>-hoz: a contains/contains_subrange és a starts_with/ends_with predikátumokat, a find_last családot, valamint az <algorithm>-ban lévő shift_left/shift_right-ot, valamint a <numeric>-ba tartozó ranges::iota-t.

A std::ranges::contains(r, value, proj) bool-t ad, és rövidzárral működik: az első egyezésnél megáll. A szabvány szerint ranges::find(…) != end-ként definiált, tehát a find is az első egyezésnél áll meg; az előnye, hogy a szándékot (létezés, nem pozíció) a típus is kifejezi. A contains_subrange(r, sub, pred, proj1, proj2) azt vizsgálja, hogy a sub összefüggő részsorozatként (a ranges::search értelmében, a sorrendet megtartva) előfordul-e az r-ben; a starts_with és az ends_with pedig a range elejét, illetve végét hasonlítja össze a megadott prefixszel, illetve szufixszel. Utóbbiaknál a két range elemeinek összehasonlíthatónak kell lenniük, de nem kell azonos típusúnak lenniük — például std::string és std::string_view karakterei összehasonlíthatók.

A find_last(r, value, proj) az utolsó előfordulást keresi, és std::ranges::subrange-et ad vissza, amelynek begin()-je a találatra mutat, end()-je pedig a range végére. Ha nincs találat, a subrange üres (begin() == end()), de a subrange-nek nincs operator bool-ja, ezért a helyes ellenőrzés if (!result.empty()), nem if (result). A find_last_if és a find_last_if_not predikátumos változatok; a teljes lista és a pontos követelmények a szabványban ellenőrizendők.

A std::ranges::iota(r, value) a <numeric> std::iota ranges-esített változata: a range-et növekvő értékekkel tölti fel. A std::ranges::shift_left(r, n) és a shift_right(r, n) a tartományon belül eltolja az elemeket, és subrange-et ad vissza: shift_left esetén {first, új_vég}, shift_right esetén {új_eleje, last}. A visszatérési értéket fel kell használni: shift_left után a t.end() az új logikai vég, és a [t.end(), last) farok elemei nem érvényesek (v.erase(t.end(), v.end())); shift_right után a [first, t.begin()) elöl lévő elemek érvénytelenek (v.erase(v.begin(), t.begin())). A shift_left az n >= size esetben üres tartományt ad vissza. A feature-test makró __cpp_lib_shift (C++20: 201806L, a ranges::shift_* C++23-as változatához 202202L); egyes libstdc++/libc++ kiadásokban a ranges::shift_* hiányozhat (a g++ 15.2 <algorithm>-jában nincs std::ranges::shift_left), ilyenkor az iterátoros std::shift_left (C++20) a fallback.

#include <algorithm>
#include <array>
#include <cassert>
#include <string>
#include <vector>

void search_examples(const std::vector<std::string>& lines) {
    // Az első FATAL előfordulásig nem megy tovább.
    bool has_fatal = std::ranges::contains(lines, std::string{"FATAL"});

    // Prefix- és szufixvizsgálat; a string_view elemei char-ok,
    // ezért a string és a string_view összehasonlítható.
    bool any_error = std::ranges::any_of(lines, [](const std::string& s) {
        return std::ranges::starts_with(s, std::string_view{"ERROR"});
    });
    bool any_trunc = std::ranges::any_of(lines, [](const std::string& s) {
        return std::ranges::ends_with(s, std::string_view{"..."});
    });
}

void shift_example(std::vector<int>& v, std::size_t n) {
    auto tail = std::ranges::shift_left(v, n);
    v.erase(tail.end(), v.end());   // a farok érvénytelen, törölni kell
}

A contains_subrange használatakor érdemes figyelni arra, hogy a részhalmazt ne allokáljuk minden hívásnál; egy std::array vagy egy std::string_view alkalmasabb lehet, ha az elemek összehasonlíthatók.

42.4.3 Labor: naplóelemző pipeline C++20 és C++23 változatban

A labor bemenete egy std::vector<std::string>, amelynek elemei "LEVEL ts bytes" formátumúak, ahol a LEVEL az ERROR, WARN vagy INFO valamelyike. A feladat: számoljuk ki az ERROR szintű sorok byte-összegét, döntsük el, hogy van-e adott szint, és keressük meg az utolsó ERROR bejegyzést. A C++20-as változat std::accumulate-et, std::find_if-et és reverse iterátort használ; a C++23-as változat views::filter/views::transform pipeline-t, ranges::fold_left-et, ranges::contains-t és ranges::find_last-ot.

A labor három fájlból áll. A közös loglab.hpp tartalmazza a bemeneti modellt (Entry, parse) és a helyességi kaput, amelyet mindkét változat main függvénye lefuttat: üres bemenet, nincs ERROR, csupa ERROR, egyetlen sor és vegyes bemenet. A kapu biztosítja, hogy a két implementáció ugyanazt az eredményt adja.

// loglab.hpp — közös bemeneti modell és helyességi kapu mindkét változathoz
#pragma once
#include <cstdint>
#include <cstdio>
#include <cstdlib>
#include <limits>
#include <optional>
#include <sstream>
#include <string>
#include <vector>

struct Entry {
    std::string level;
    std::int64_t ts;
    std::int64_t bytes;
};

// "LEVEL ts bytes" sorok; a hibás sort (nem szám, túl nagy szám, negatív
// bytes) kihagyja: a bytes mező nemnegatív, ezt a parser kényszeríti ki.
inline std::vector<Entry> parse(const std::vector<std::string>& lines) {
    std::vector<Entry> out;
    for (const std::string& line : lines) {
        std::istringstream in(line);
        Entry e;
        if (in >> e.level >> e.ts >> e.bytes && e.bytes >= 0) out.push_back(e);
    }
    return out;
}

// Ellenőrzött összeadás nemnegatív tagokra: a túlcsordulást a művelet ELŐTT
// vizsgálja, így UB nem keletkezik. Túlcsordulásnál az eredmény üres optional.
inline std::optional<std::int64_t> add_bytes(std::optional<std::int64_t> acc,
                                             std::int64_t b) {
    if (!acc || b > std::numeric_limits<std::int64_t>::max() - *acc) return std::nullopt;
    return *acc + b;
}

#define CHECK(condition) do {                                      \
    if (!(condition)) {                                            \
        std::fprintf(stderr, "CHECK failed at line %d\n", __LINE__); \
        std::exit(EXIT_FAILURE);                                   \
    }                                                              \
} while (0)

// A helyességi kapu: a határeseteken mindkét változatnak ugyanezt kell adnia.
template <class ErrorBytes, class HasLevel, class LastErrorTs>
void check_cases(ErrorBytes error_bytes, HasLevel has_level,
                 LastErrorTs last_error_ts) {
    const std::vector<Entry> empty;
    CHECK(error_bytes(empty) == 0 && !has_level(empty, "ERROR"));
    CHECK(last_error_ts(empty) == -1);

    const auto none = parse({"INFO 1 10", "WARN 2 20"});
    CHECK(error_bytes(none) == 0 && has_level(none, "WARN"));
    CHECK(last_error_ts(none) == -1);

    const auto all = parse({"ERROR 1 5", "ERROR 2 7"});
    CHECK(error_bytes(all) == 12 && last_error_ts(all) == 2);

    const auto one = parse({"ERROR 9 3"});
    CHECK(error_bytes(one) == 3 && last_error_ts(one) == 9);

    const auto mixed = parse({"ERROR 1 5", "INFO 2 1", "ERROR 3 4", "WARN 4 2"});
    CHECK(error_bytes(mixed) == 9 && last_error_ts(mixed) == 3);
    CHECK(!has_level(mixed, "DEBUG"));

    constexpr std::int64_t max = std::numeric_limits<std::int64_t>::max();
    const auto at_max = parse({"ERROR 1 9223372036854775806", "ERROR 2 1"});
    CHECK(error_bytes(at_max) == max);                       // pontosan max: még érvényes
    const auto over = parse({"ERROR 1 9223372036854775807", "ERROR 2 1"});
    CHECK(error_bytes(over) == std::nullopt);                // max+1: dokumentált hiba
    const auto bad = parse({"ERROR 1 -5", "ERROR 2 x", "ERROR 3 7"});
    CHECK(bad.size() == 1 && error_bytes(bad) == 7);         // negatív és hibás mező kiesik
}

A C++23-as változat:

// loglab23.cpp — C++23
#include "loglab.hpp"
#include <algorithm>
#include <ranges>

std::optional<std::int64_t> error_bytes(const std::vector<Entry>& es) {
    auto errs = es
        | std::views::filter([](const Entry& e) { return e.level == "ERROR"; })
        | std::views::transform([](const Entry& e) { return e.bytes; });
    return std::ranges::fold_left(errs, std::optional<std::int64_t>{0}, add_bytes);
}

bool has_level(const std::vector<Entry>& es, const std::string& lv) {
    return std::ranges::contains(es, lv, &Entry::level);
}

std::ranges::subrange<std::vector<Entry>::const_iterator>
last_error(const std::vector<Entry>& es) {
    static const std::string kErr = "ERROR";
    return std::ranges::find_last(es, kErr, &Entry::level);
}

int main() {
    check_cases(error_bytes, has_level, [](const std::vector<Entry>& es) {
        auto r = last_error(es);
        return r.empty() ? std::int64_t{-1} : r.begin()->ts;
    });
    std::puts("loglab23: ok");
}

A C++20-as megfelelő:

// loglab20.cpp — C++20
#include "loglab.hpp"
#include <algorithm>
#include <numeric>

std::optional<std::int64_t> error_bytes(const std::vector<Entry>& es) {
    return std::accumulate(es.begin(), es.end(), std::optional<std::int64_t>{0},
        [](std::optional<std::int64_t> acc, const Entry& e) {
            return e.level == "ERROR" ? add_bytes(acc, e.bytes) : acc;
        });
}

bool has_level(const std::vector<Entry>& es, const std::string& lv) {
    return std::find_if(es.begin(), es.end(),
        [&](const Entry& e) { return e.level == lv; }) != es.end();
}

auto last_error(const std::vector<Entry>& es) {
    return std::find_if(es.rbegin(), es.rend(),
        [](const Entry& e) { return e.level == "ERROR"; });
}

int main() {
    check_cases(error_bytes, has_level, [](const std::vector<Entry>& es) {
        auto it = last_error(es);
        return it == es.rend() ? std::int64_t{-1} : it->ts;
    });
    std::puts("loglab20: ok");
}

A benchmark és a helyességi kapuk együtt futnak. A mérés metodikája: azonos bemenet, azonos optimalizálási szint, előmelegítés, legalább néhány ismétlés, és az eredmény mediánja. A helyességi kapu minden esetben az, hogy a két implementáció ugyanazt az értéket adja az összes határesetre: üres bemenet, nincs ERROR, csupa ERROR, egyetlen sor, a max és a túlcsorduló max+1 összeg. A benchmark a hibaeredményt is azonosan kezeli: a mért függvény az optional-t adja vissza, és a mérés előtt a kapu már igazolta, hogy a két változat ugyanazt a hibát jelzi. A mérés eredménye nem része ennek a szövegnek; a tanuló laborjában keletkezik, és target-, fordító- és flagspecifikus.

#include <chrono>

template <class F>
double bench_ms(F&& f, int reps) {
    using clock = std::chrono::steady_clock;
    auto t0 = clock::now();
    for (int i = 0; i < reps; ++i) {
        volatile auto sink = f();   // holt kód kiesés ellen, nem univerzális barrier
        (void)sink;
    }
    auto t1 = clock::now();
    return std::chrono::duration<double, std::milli>(t1 - t0).count() / reps;
}

42.4.4 Gyakori hibák és javításuk

Az első és leggyakoribb hiba a fold_left és a std::accumulate összekeverése: az accumulate akkumulátora az init típusa (0 helyett 0LL kell), a fold_left akkumulátora a művelet eredménytípusa, ezért ott a 0 init nem szűkít. A második a fold_left_first eredményének kezeletlen optional-ja: a *opt üres optionalon nem definiált viselkedés, ezért előbb if (auto v = ...) kell. A harmadik a find_last eredményének bool-ként való használata: a subrange nem konvertálható bool-lá, helyette !r.empty(). A negyedik a shift_left visszatérési értékének eldobása (vagy iterátorként kezelése, miközben subrange-et ad), amitől a vektor vége szemét marad. Az ötödik a contains és a find összecserélése olyan helyen, ahol az iterátorra szükség van: a contains csak a létet adja vissza, pozíciót nem. Végül a benchmarknál a nem használt eredmény miatti holt kód kiesése, illetve a -O0-s mérés összehasonlíthatatlansága.

42.4.5 Összefoglaló

A C++23 ranges-algoritmusok a megszokott műveleteket adják vissza ranges-szerződéssel: a fold_left/fold_right determinisztikus sorrendű összegzés, az akkumulátor típusa a művelet eredménytípusa (az init ehhez konvertálódik), projection nélkül; a fold_left_first üres range-re nullopt-ot ad. A contains, contains_subrange, starts_with és ends_with rövidzáró predikátumok, a find_last subrange-et ad, a shift_left/shift_right pedig subrange-et ad vissza (shift_left: {first, új_vég}, shift_right: {új_eleje, last}). A laborban a C++20-as és C++23-as pipeline eredményét kötelező egyeztetni, és csak ezután szabad mérni.

42.4.6 Feladatok

  1. Alapvető. Írj egy average_error_ratio függvényt, amely a naplóbejegyzésekből kiszámítja az ERROR byte-ok és az összes byte arányát. Használj ranges::fold_left-et std::int64_t{0} kezdőértékkel az összegekhez, és csak a hányadost számold double-ban. Magyarázd meg, miért érdemes az összegeket egészben képezni.

  2. Közepes. Írj egy last_error_before_ts függvényt, amely a find_last_if-fel megkeresi az utolsó olyan bejegyzést, amelynek a timestampje kisebb, mint egy adott limit, és az ERROR szintű. Mi a visszatérési típus, és hogyan kezeled az üres eredményt?

  3. Nehéz. Írj egy dedup_in_place függvényt, amely egy rendezett std::vector<int>-ből eltávolítja az ismétlődőket (ranges::unique + erase), és egy drop_front(v, k) függvényt a shift_left gyakorlására; és add meg a komplexitást, valamint a helyességi kapukat.

  4. Diagnosztikai. A laborban a C++23-as változat lassabbnak bizonyul a C++20-asnál. Sorolj fel három lehetséges okot, és mindegyikhez adj egy ellenőrzési lépést.

42.4.7 Megoldások

1. megoldás. Az error_bytes és a total_bytes külön fold, mindkettő std::int64_t{0} initjel: az int64_t összegzés pontos, a double összegzés 2532^{53} felett kerekítene, ezért csak a hányadost számoljuk double-ban.

double average_error_ratio(const std::vector<Entry>& es) {
    auto bytes = es | std::views::transform([](const Entry& e) { return e.bytes; });
    std::int64_t total = std::ranges::fold_left(bytes, std::int64_t{0}, std::plus<>{});
    if (total == 0) return 0.0;
    auto errs = es
        | std::views::filter([](const Entry& e) { return e.level == "ERROR"; })
        | std::views::transform([](const Entry& e) { return e.bytes; });
    std::int64_t err = std::ranges::fold_left(errs, std::int64_t{0}, std::plus<>{});
    return static_cast<double>(err) / static_cast<double>(total);
}

Ellenőrzés: üres vektorra 0.0, csupa ERROR-ra 1.0, és az int64_t összegek nem csordulnak túl; a static_cast<double> nélkül az err / total egész osztás lenne.

2. megoldás. A find_last_if subrange-et ad; a predikátumnak a limit-et is látnia kell, ezért lambdába zárjuk.

auto last_error_before_ts(const std::vector<Entry>& es, std::int64_t limit) {
    return std::ranges::find_last_if(es,
        [limit](const Entry& e) { return e.level == "ERROR" && e.ts < limit; });
}

void use(const std::vector<Entry>& es, std::int64_t limit) {
    auto r = last_error_before_ts(es, limit);
    if (!r.empty()) {
        const Entry& e = *r.begin();
        // e itt érvényes, amíg az es nem módosul.
    }
}

Ellenőrzés: üres bemenetre r.empty(), a limitnél nagyobb timestampű egyetlen ERROR esetén szintén r.empty(), és a visszaadott Entry& addig érvényes, amíg a vektor nem módosul.

3. megoldás. (Ez a megoldás nem lett lefordítva; a ranges::shift_left a g++ 15.2-ben nem érhető el, ott az iterátoros std::shift_left a fallback.) Rendezett vektoron az ismétlődések összefüggő blokkot alkotnak; a kanonikus megoldás az unique + erase; a shift_left gyakorlására külön példa az első k elem eltávolítása.

void dedup_in_place(std::vector<int>& v) {
    auto dups = std::ranges::unique(v);   // subrange {új_vég, régi_vég}
    v.erase(dups.begin(), dups.end());
}

// a shift_left gyakorlása: az első k elem eltávolítása
void drop_front(std::vector<int>& v, std::size_t k) {
    auto t = std::ranges::shift_left(v, static_cast<std::ptrdiff_t>(k));
    v.erase(t.end(), v.end());
}

A ranges::unique az egyedi elemeket előre mozgatja, és a subrange begin()-je az új logikai vég; a farkat töröljük. A shift_left-et ide fűzni felesleges (és az n = size miatt minden elemet kitörölne), ezért nem használjuk. A komplexitás O(n)O(n), egyetlen extra tárterület nélkül; üres bemenetre a vektor üres marad. Helyességi kapuk futtatható tesztként: {}, {1}, {1,1,1}, {1,2,3}, {1,1,2,2,3} → {1,2,3}.

4. megoldás. (a) A views::filter/views::transform lánc nem feltétlenül olvad össze a fold_left-tel, és a lambda-hívás költsége megjelenhet; ellenőrzés: assembly vagy -fopt-info összehasonlítása. (b) A fold_left std::plus<>-t használ, amely nem feltétlenül vektorizálódik, míg a kézi ciklus igen; ellenőrzés: -O3 -march=native melletti újramérés. (c) A mérés maga hibás: a volatile sink nem elegendő, vagy a bemenet mérete miatt a C++20-as változat a cache-ben marad; ellenőrzés: azonos bemenet, azonos flags, előmelegítés és több ismétlés, valamint az eredmények egyezésének ellenőrzése a mérés előtt.
