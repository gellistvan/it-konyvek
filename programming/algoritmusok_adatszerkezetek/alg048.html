13.3 Kiválasztás, order statistics és mediánok

A kiválasztási probléma (order statistics) a rendezés egyik legfontosabb rokona: nem a teljes rendezett sorozatot keressük, hanem annak egyetlen elemét, a kk-adik legkisebbet. Ha az A[1…n]A[1\ldots n] tömb elemeit növekvő sorrendbe rendeznénk, a kapott A′A' sorozat A′[k]A'[k] eleme lenne a válasz. A medián ennek speciális esete: páratlan nn-re a (n+1)/2(n+1)/2-edik, páros nn-re az alsó medián a n/2n/2-edik, a felső medián az n/2+1n/2+1-edik elem. A feladat tehát: bemenet az A[1…n]A[1\ldots n] tömb és egy k∈{1,2,…,n}k \in \{1,2,\ldots,n\} egész, kimenet a kk-adik legkisebb elem értéke. Előfeltétel, hogy a tömb legalább egy elemű és kk érvényes; utófeltétel, hogy a visszaadott érték a multihalmazban rendezés után a kk-adik helyen állna. A leállási feltétel minden rekurzív változatnál az, hogy a vizsgált résztömb mérete 1-re csökken, vagy a pivot pozíciója pontosan kk.

13.3.1 Particionálás mint alapművelet

A kiválasztó algoritmusok a particionálásra építenek, amelyet a gyorsrendezésből ismerünk. A particionálás egy pivot elem körül három részre osztja a tömböt: a pivotnál kisebb vagy egyenlő elemek, maga a pivot, majd a pivotnál nagyobb vagy egyenlő elemek. A klasszikus Lomuto-féle eljárás pszeudokódja (1-től indexelve, bal és jobb határokkal) a következő:

FUNCTION PARTITION(A, bal, jobb)
    // Előfeltétel: 1 ≤ bal < jobb ≤ n
    // Kimenet: p index, ahol A[p] = pivot, és
    //          minden i ∈ [bal..p-1] esetén A[i] ≤ pivot,
    //          minden j ∈ [p+1..jobb] esetén A[j] ≥ pivot.
    pivot := A[jobb]               // az utolsó elemet választjuk pivotnak
    i := bal - 1                   // i: az utolsó olyan index, ahol az elem ≤ pivot
    FOR j := bal TO jobb - 1 DO
        IF A[j] <= pivot THEN
            i := i + 1
            CSERE(A[i], A[j])
    CSERE(A[i+1], A[jobb])         // a pivot a helyére kerül
    RETURN i + 1

A ciklus invariánsa minden iteráció előtt: - az A[bal..i] résztömb minden eleme ≤ pivot; - az A[i+1..j-1] résztömb minden eleme > pivot; - az A[j..jobb-1] résztömb még feldolgozatlan.

A ciklus végén j = jobb lesz, így a feldolgozatlan rész üres. A CSERE(A[i+1], A[jobb]) lépés a pivotot a nála kisebb/egyenlő és nagyobb/egyenlő részek közé helyezi, tehát a pivot a rendezett sorrendben is az i+1 helyre kerül (a bal-tól számítva). A particionálás időbonyolultsága nyilvánvalóan O(n)O(n), ahol n=jobb−bal+1n = jobb - bal + 1, memóriaigénye pedig O(1)O(1) (ha cseréket in-place végezzük). A particionálás nem stabil, de a kiválasztási feladat nem igényel stabilitást. Fontos megjegyezni, hogy ha sok egyenlő elem van, a Lomuto-partíció kiegyensúlyozatlan lehet: például ha minden elem egyenlő, a pivot a jobb szélre kerül, és a bal oldali rész n−1n-1 méretű lesz. Ezt a gyakorlatban a Hoare-féle particionálás vagy a holland zászló particionálás (3-way partitioning) enyhíti.

A kiválasztó algoritmusokhoz a háromutas particionálást használjuk, amely a tömböt a pivot értéke körül három részre bontja: szigorúan kisebb, egyenlő és szigorúan nagyobb elemekre. Így az egyenlő elemek egyetlen blokkba kerülnek, és a kiválasztás az egyenlő blokkban azonnal leállhat; ez kulcsfontosságú az ismétlődő kulcsok esetén. A pszeudokód:

FUNCTION PARTITION3(A, bal, jobb, x)
    // Előfeltétel: 1 ≤ bal ≤ jobb ≤ n, és x előfordul A[bal..jobb]-ban
    // Kimenet: (lt, gt), ahol
    //   A[bal..lt-1] < x, A[lt..gt] = x, A[gt+1..jobb] > x.
    lt := bal
    i := bal
    gt := jobb
    WHILE i <= gt DO
        IF A[i] < x THEN
            CSERE(A[lt], A[i])
            lt := lt + 1
            i := i + 1
        ELSEIF A[i] > x THEN
            CSERE(A[i], A[gt])
            gt := gt - 1          // az i nem nő: az új A[i] még feldolgozatlan
        ELSE
            i := i + 1
    RETURN (lt, gt)

A particionálás O(n)O(n) idejű és O(1)O(1) memóriájú; az i és gt találkozásakor minden elem a helyes blokkban van. Az egyenlő blokk hossza E=gt−lt+1E = gt - lt + 1.

A PARTITION3 kimenete az egyenlő blokk lt…gtlt \ldots gt intervalluma. Ha ezt összehasonlítjuk a keresett kk indexszel, akkor eldönthető, hol kell tovább keresni: - ha lt≤k≤gtlt \le k \le gt, a válasz A[k]A[k] (az egyenlő blokk minden eleme ugyanaz az érték); - ha k<ltk < lt, a kk-adik elemet a bal oldali résztömbben kell keresni; - ha k>gtk > gt, akkor a jobb oldaliban.

Ez a megfigyelés vezet a quickselect algoritmushoz.

13.3.2 Quickselect: véletlen pivoton alapuló kiválasztás

A quickselect a gyorsrendezés kiválasztási változata: csak azt a résztömböt dolgozza fel rekurzívan, amelyik a keresett elemet tartalmazza, a másik oldalt eldobja. A pszeudokód (1-től indexelve, globális kk-val) a következő:

FUNCTION QUICKSELECT(A, bal, jobb, k)
    // Előfeltétel: 1 ≤ bal ≤ k ≤ jobb ≤ n
    // Kimenet: az A[bal..jobb] résztömbben a k-adik legkisebb elem értéke (globális k)
    // Utófeltétel: a függvény a megfelelő elemet adja vissza, a tömb átrendeződik.
    IF bal == jobb THEN
        RETURN A[bal]                // leállás: egyetlen elem
    // Véletlen pivotérték kiválasztása az egyenletes eloszlás szerint
    pivot_érték := A[VÉLETLEN(bal, jobb)]  // a résztömb egy véletlen elemének értéke
    (lt, gt) := PARTITION3(A, bal, jobb, pivot_érték)
    IF lt <= k ÉS k <= gt THEN
        RETURN A[k]                  // az egyenlő blokk minden eleme ugyanaz az érték
    ELSEIF k < lt THEN
        RETURN QUICKSELECT(A, bal, lt-1, k)
    ELSE
        RETURN QUICKSELECT(A, gt+1, jobb, k)

A függvény a kk paramétert globálisan kezeli: a bal és jobb határok változásával a kk értéke nem módosul. Ez fontos, mert a rekurzió során a résztömb elemeinek globális indexei ugyanazok maradnak. (Ha a kk a résztömbön belüli relatív rang volna, akkor a jobb oldali hívásnál k−(gt−bal+1)k - (gt - bal + 1)-et, a bal oldalinál változatlan kk-t kellene átadni.) A háromutas particionálás miatt az azonos kulcsok egy blokkba kerülnek: ha kk az egyenlő blokkba esik, a hívás azonnal visszatér, így az azonos elemekből álló tömb egyetlen particionálással lezárul, függetlenül a pivot választásától.

13.3.2.1 Korrektségi vázlat

A bizonyítást a résztömb méretére vonatkozó indukcióval végezhetjük. Az alapeset: ha bal == jobb, akkor a résztömb egyetlen eleméből a k-adik legkisebb nyilván az az elem. Tegyük fel, hogy a PARTITION3 helyes, azaz a particionálás után A[bal..lt-1] elemei < x, A[lt..gt] elemei = x, A[gt+1..jobb] elemei > x. Ekkor: - ha lt≤k≤gtlt \le k \le gt, a k-adik legkisebb elem értéke x, tehát a visszaadott A[k] helyes; - ha k<ltk < lt, a k-adik legkisebb elem a bal oldali résztömbben található: ott lt−ballt - bal darab, x-nél szigorúan kisebb elem van, és k<ltk < lt miatt a keresett elem éppen ezek közé esik; - ha k>gtk > gt, a k-adik elem a jobb oldalon van, mert a bal oldal és az egyenlő blokk összesen gt−bal+1gt - bal + 1 elemet tesz ki, ami <k< k.

Mivel a rekurzív hívás kisebb résztömbre vonatkozik, az indukciós feltevés miatt a visszaadott érték helyes. A leállási feltétel teljesül, mert minden rekurzív lépésben a résztömb mérete legalább eggyel csökken (rossz pivot esetén is), így a méret véges sok lépésben eléri az 1-et.

13.3.2.2 Példa

Legyen A=[8,4,2,5,1,9,7]A = [8, 4, 2, 5, 1, 9, 7] és k=4k = 4 (1-től indexelve). Tegyük fel, hogy a véletlen pivot a 77-es elem (index 7), azaz x=7x = 7. A PARTITION3 lépései, bal = 1, jobb = 7:

  • Kezdetben: [8, 4, 2, 5, 1, 9, 7], lt = 1, i = 1, gt = 7.
  • i = 1: 8 > 7, csere A[1] és A[7] → [7, 4, 2, 5, 1, 9, 8], gt = 6.
  • i = 1: 7 = 7, i = 2.
  • i = 2: 4 < 7, csere A[1] és A[2] → [4, 7, 2, 5, 1, 9, 8], lt = 2, i = 3.
  • i = 3: 2 < 7, csere A[2] és A[3] → [4, 2, 7, 5, 1, 9, 8], lt = 3, i = 4.
  • i = 4: 5 < 7, csere A[3] és A[4] → [4, 2, 5, 7, 1, 9, 8], lt = 4, i = 5.
  • i = 5: 1 < 7, csere A[4] és A[5] → [4, 2, 5, 1, 7, 9, 8], lt = 5, i = 6.
  • i = 6: 9 > 7, csere A[6] és A[6] (önmaga) → gt = 5.
  • i = 6 > gt = 5: leállás. Eredmény: lt = 5, gt = 5, azaz A[1..4] = [4, 2, 5, 1] < 7, A[5] = 7, A[6..7] = [9, 8] > 7.

A pivot pozíciója lt = gt = 5, a keresett k=4<5k = 4 < 5, tehát a bal oldali részben [4, 2, 5, 1] kell tovább keresni a globális 4. elemet. Ebben a résztömbben a 4. legkisebb elem (az eredeti tömb összes eleméhez viszonyítva) a keresett. A rekurzió folytatódik.

Vegyünk egy második lépést: a résztömb [4, 2, 5, 1], bal = 1, jobb = 4, k=4k = 4. Véletlen pivot mondjuk az 1-es indexű elem, értéke 4, tehát x=4x = 4. A PARTITION3 lépései:

  • lt = 1, i = 1, gt = 4: A[1] = 4 = x, i = 2.
  • i = 2: A[2] = 2 < 4, csere A[1] és A[2] → [2, 4, 5, 1], lt = 2, i = 3.
  • i = 3: A[3] = 5 > 4, csere A[3] és A[4] → [2, 4, 1, 5], gt = 3.
  • i = 3 ≤ gt = 3: A[3] = 1 < 4, csere A[2] és A[3] → [2, 1, 4, 5], lt = 3, i = 4.
  • i = 4 > gt = 3: leállás. Eredmény: lt = 3, gt = 3.

Most k=4>gt=3k = 4 > gt = 3, tehát a jobb oldalon keresünk: résztömb [5], egy elem, visszaad 5. A 4. legkisebb elem az 5, ami helyes.

13.3.2.3 Futásidő-elemzés

A quickselect várható futásideje O(n)O(n), legrosszabb esetben O(n2)O(n^2); az elemzés modellje a véletlen pivot fölötti várható érték tetszőleges rögzített bemenetre, a kulcsok multiplicitását is beleértve. Egy hívás a PARTITION3 miatt O(n)O(n) munkát végez, és vagy az egyenlő blokkban áll meg, vagy egy szigorú oldalra rekurzál. Nevezzünk egy pivotot sikeresnek, ha a rekurzióra kerülő szigorú oldal mérete legfeljebb 3n/43n/4. Ha LL, EE, illetve RR a pivotnál szigorúan kisebb, vele egyenlő, illetve nála szigorúan nagyobb elemek száma, akkor a sikertelenség azt jelenti, hogy L>3n/4L > 3n/4 vagy R>3n/4R > 3n/4 (a kettő egyszerre nem teljesülhet). Ha például R>3n/4R > 3n/4, akkor L+E<n/4L + E < n/4, tehát a pivotérték minden előfordulása a rendezett sorrend első ⌊n/4⌋\lfloor n/4 \rfloor helyének valamelyikén áll; a véletlen választás miatt ennek valószínűsége legfeljebb 1/41/4. Ugyanígy a másik eset valószínűsége is legfeljebb 1/41/4, ezért a pivot legalább 1/21/2 valószínűséggel sikeres — az ismétlődő kulcsok sem rontják ezt, mert a háromutas particionálás az összes egyenlő elemet egy blokkba teszi.

Egy sikeres pivotig várhatóan legfeljebb két particionálás kell, mert a sikeres lépés feltételes valószínűsége minden hívásban legalább 1/21/2, függetlenül az eddigi lépésektől. Bontsuk a hívások sorozatát fázisokra: egy fázis a következő sikeres pivotig tartó particionálásokból áll. A fázison belüli résztömbök mérete nem nő, ezért egy fázis várható munkája O(n0)O(n_0), ahol n0n_0 a fázis kezdetén a résztömb mérete; a sikeres lépés után a méret legfeljebb 3n0/43n_0/4. A fázisok méretei tehát mértani sorozatot alkotnak, és a teljes várható munka

O(n)+O(3n/4)+O((3/4)2n)+⋯=O(n⋅∑i=0∞(3/4)i)=O(n). O(n) + O(3n/4) + O((3/4)^2 n) + \cdots = O\left(n \cdot \sum_{i=0}^{\infty} (3/4)^i\right) = O(n).

Ez az elemzés a jelen fejezet háromutas particionálására vonatkozik; a kétutas Lomuto-partíciónál az azonos kulcsok esete ezt a becslést megkerülné (minden elem egy oldalra kerülne, és a rekurzió mérete csak eggyel csökkenne). A legrosszabb eset továbbra is O(n2)O(n^2): ha a véletlen választás mindig szélső értékű pivotot ad, a résztömb mérete csak eggyel csökken, így a költség O(n+(n−1)+…+1)=O(n2)O(n + (n-1) + \ldots + 1) = O(n^2); ennek valószínűsége a véletlen pivot mellett elhanyagolható, de a legrosszabb eset korlátja marad.

A véletlen pivot használata a gyakorlatban szinte mindig elfogadható, mert a várható futásidő kiváló, és a konstans tényező kicsi. Ráadásul a modern szabványos könyvtárak kiválasztó függvénye (például a C++ std::nth_element) is hasonló, introselect-alapú megoldást használ. Ha azonban determinisztikusan szeretnénk garantálni az O(n)O(n) legrosszabb futásidőt, a median-of-medians algoritmust kell alkalmazni.

13.3.3 Determinisztikus lineáris kiválasztás: median-of-medians

A median-of-medians (mediánok mediánja) algoritmust Blum, Floyd, Pratt, Rivest és Tarjan dolgozta ki (1973; doi:10.1016/S0022-0000(73)80033-9), és célja, hogy a kiválasztási problémát legrosszabb esetben is lineáris időben oldja meg. Az alapötlet: válasszunk egy olyan pivotot, amely garantáltan „jó”, azaz a tömbnek elég nagy részét teszi félre. Ezt úgy érjük el, hogy a tömböt 5 elemű csoportokra bontjuk, mindegyikben kiszámítjuk a mediánt, majd ezeknek a mediánoknak a mediánját választjuk pivotnak.

13.3.3.1 Az algoritmus lépései

  1. Ha a résztömb mérete kicsi (pl. ≤ 5), akkor egyszerűen rendezzük (például beszúró rendezéssel) és adjuk vissza a kk-adik elemet.
  2. Osszuk a tömböt 5 elemű csoportokra (az utolsó csoport lehet kevesebb). Minden csoportot rendezzünk, és vegyük a csoport mediánját (alsó medián).
  3. Gyűjtsük ezeket a mediánokat egy MM tömbbe. Az MM hossza ⌈n/5⌉\lceil n/5 \rceil, ahol nn a jelenlegi résztömb mérete.
  4. Rekurzívan keressük meg MM mediánját: hívjuk meg a kiválasztó algoritmust MM-re, k=⌈|M|/2⌉k = \lceil |M|/2 \rceil. A kapott érték legyen xx, a mediánok mediánja.
  5. Particionáljuk az eredeti tömböt xx körül háromutas PARTITION3-mal: a szigorúan kisebb, az egyenlő és a szigorúan nagyobb elemek blokkjára.
  6. Ha a particionálás után az egyenlő blokk az lt…gtlt \ldots gt indexeket foglalja el, és lt≤k≤gtlt \le k \le gt, akkor xx a válasz. Ha k<ltk < lt, akkor rekurzívan a bal oldali résztömbben keresünk; ha k>gtk > gt, akkor a jobb oldaliban. Az egyenlő blokkra soha nem hívunk rekurzívan.

A pszeudokód (1-től indexelve):

FUNCTION SELECT(A, bal, jobb, k)
    // Előfeltétel: 1 ≤ bal ≤ k ≤ jobb ≤ n
    // Kimenet: az A[bal..jobb] résztömbben a k-adik legkisebb elem (globális k)
    // Utófeltétel: a visszaadott elem a rendezett sorrendben a k-adik.
    n_rész := jobb - bal + 1
    IF n_rész <= 5 THEN
        RENDEZD az A[bal..jobb] résztömböt  // pl. beszúró rendezés
        RETURN A[k]                        // mert a k globális index
    // 1. Mediánok kinyerése 5 elemű csoportokból
    M := üres tömb
    i := bal
    WHILE i <= jobb DO
        csoport_vége := MIN(i + 4, jobb)
        RENDEZD az A[i..csoport_vége] résztömböt
        medián_index := i + (csoport_vége - i) // 2   // alsó medián
        ADD A[medián_index] AZ M-HEZ
        i := i + 5
    // 2. Mediánok mediánja rekurzívan
    m := HOSSZ(M)
    pivot_érték := SELECT(M, 1, m, CEILING(m / 2))  // itt a SELECT-et M-re hívjuk
    // 3. Háromutas particionálás pivot_érték körül
    (lt, gt) := PARTITION3(A, bal, jobb, pivot_érték)
    // 4. Rekurzív hívás csak a szigorú oldalra, ha k kívül esik az egyenlő blokkon
    IF lt <= k ÉS k <= gt THEN
        RETURN A[k]                   // az egyenlő blokk minden eleme = pivot_érték
    ELSEIF k < lt THEN
        RETURN SELECT(A, bal, lt-1, k)
    ELSE
        RETURN SELECT(A, gt+1, jobb, k)

A pszeudokódban a CEILING(m/2) az mm felső egészrészét jelenti, azaz ⌈m/2⌉\lceil m/2 \rceil-t. A mediánok kinyerésekor a csoportok rendezése összesen O(n)O(n) időt vesz igénybe, mert minden csoport mérete legfeljebb 5, így egy csoport rendezése konstans idő, és ⌈n/5⌉\lceil n/5 \rceil csoport van. A háromutas particionálás miatt az egyenlő kulcsok egyetlen blokkba kerülnek, ezért a rekurzió mindig szigorúan kisebb vagy szigorúan nagyobb elemekre hat.

13.3.3.2 Miért garantáltan jó a pivot?

A mediánok mediánja xx olyan tulajdonsággal rendelkezik, hogy legalább a tömb elemeinek körülbelül 3/103/10-e kisebb vagy egyenlő xx-nél, és legalább 3/103/10-e nagyobb vagy egyenlő. Ennek belátása:

  • Az MM tömb a csoportok mediánjait tartalmazza. xx az MM alsó mediánja, azaz a k=⌈|M|/2⌉k = \lceil |M|/2 \rceil-edik elem, ezért legalább ⌊m/2⌋+1\lfloor m/2 \rfloor + 1 MM-beli elem ≥ xx, ahol m=|M|=⌈n/5⌉m = |M| = \lceil n/5 \rceil.
  • Tekintsük azokat a csoportokat, amelyek mediánja ≥ xx. Közülük legfeljebb egy a hiányos (legfeljebb 4 elemű) utolsó csoport. Minden teljes ötelemű csoportban, mivel a csoport rendezett, a medián a 3. legkisebb elem, tehát legalább 3 elem ≥ a csoport mediánja ≥ xx; a hiányos csoport legalább 1 elemet ad (a saját mediánját).
  • Ezért az eredeti tömb legalább 3⌊m/2⌋+1≥3n/10−63\lfloor m/2 \rfloor + 1 \ge 3n/10 - 6 eleme ≥ xx: a 3⌊m/2⌋3\lfloor m/2 \rfloor tag a teljes csoportokból származik, az +1+1 pedig a hiányos csoportból (ha a hiányos csoport mediánja xx-nél kisebb, akkor még több teljes csoport számolható, tehát ez alsó becslés). Hasonlóan legalább 3n/10−63n/10 - 6 elem ≤ xx.

Mivel a pivot körüli háromutas particionálás után a szigorúan kisebb elemek a bal, az egyenlőek a középső, a szigorúan nagyobbak a jobb blokkba kerülnek, a rekurzió során a szigorú oldal mérete legfeljebb n−(3n/10−6)=7n/10+6n - (3n/10 - 6) = 7n/10 + 6 lehet. Ez a kulcs: a rekurziós hívás mérete lineárisan csökken, ellentétben a rossz pivot esetével.

13.3.3.3 Futásidő-elemzés

Jelölje T(n)T(n) a SELECT algoritmus legrosszabb futásidejét nn elemű bemeneten. Az algoritmus lépései: - A csoportok mediánjainak kiszámítása O(n)O(n) idő (minden csoport rendezése konstans, a csoportok száma n/5n/5). - A mediánok mediánjának rekurzív kiválasztása T(⌈n/5⌉)T(\lceil n/5 \rceil). - A háromutas particionálás O(n)O(n). - A pivot utáni rekurzív hívás csak a szigorú oldalra történik, amelynek mérete legfeljebb 7n/10+67n/10 + 6, így költsége T(7n/10+6)T(7n/10 + 6).

Ezért a rekurrencia:

T(n)≤T(⌈n/5⌉)+T(7n/10+6)+an, T(n) \le T(\lceil n/5 \rceil) + T(7n/10 + 6) + a n,

ahol ana n a O(n)O(n)-es rész felülbecslése valamely a>0a > 0 konstanssal.

Belátjuk, hogy T(n)=O(n)T(n) = O(n). Legyen C>10aC > 10a konstans, és tegyük fel indukciósan, hogy T(m)≤CmT(m) \le C m minden m<nm < n-re. (Az n<N(C)n < N(C) értékeket alapesetként kezeljük; N(C)N(C) definícióját lásd alább.) Helyettesítsünk be:

T(n)≤C⌈n/5⌉+C(7n/10+6)+an, T(n) \le C \lceil n/5 \rceil + C(7n/10 + 6) + a n,

ahol aa ugyanaz a konstans, mint a rekurrenciában. Mivel ⌈n/5⌉≤n/5+1\lceil n/5 \rceil \le n/5 + 1, kapjuk:

T(n)≤C(n/5+1)+C(7n/10+6)+an=(C/5+7C/10)n+(C+6C)+an=0,9Cn+(7C+an). T(n) \le C(n/5 + 1) + C(7n/10 + 6) + a n = (C/5 + 7C/10) n + (C + 6C) + a n = 0{,}9 C n + (7C + a n).

Ahhoz, hogy T(n)≤CnT(n) \le C n teljesüljön, elég, ha

0,9Cn+7C+an≤Cn. 0{,}9 C n + 7C + a n \le C n.

Átrendezve:

an+7C≤0,1Cn. a n + 7C \le 0{,}1 C n.

Legyen δ=0,1C−a>0\delta = 0{,}1C - a > 0 (ezt C>10aC > 10a biztosítja), és N(C)=⌈7C/δ⌉N(C) = \lceil 7C/\delta \rceil. Ekkor minden n≥N(C)n \ge N(C) esetén 7C≤δn7C \le \delta n, azaz 0,9Cn+7C+an≤Cn0{,}9 C n + 7C + a n \le C n, tehát az indukciós lépés működik, és T(n)≤CnT(n) \le Cn. Továbbá N(C)>70N(C) > 70, ezért 7n/10+6<n7n/10 + 6 < n, így az indukciós feltevés a második rekurzív hívásra is alkalmazható.

Az n<N(C)n < N(C) esetekre az indukciós lépés még nem érvényes, ezeket alapesetként kell lefedni. Ha C≥20aC \ge 20a, akkor δ≥0,05C\delta \ge 0{,}05C, ezért N(C)≤140N(C) \le 140, így az alapesetek halmaza legfeljebb az n<140n < 140 értékekből áll. Növeljük CC-t (ha szükséges) úgy, hogy C≥max⁡n<140T(n)/nC \ge \max_{n < 140} T(n)/n is teljesüljön; a C≥20aC \ge 20a feltétel megmarad, N(C)N(C) továbbra is legfeljebb 140, és az alapesetekre T(n)≤CnT(n) \le Cn. Ezzel az indukció minden nn-re működik, tehát T(n)=O(n)T(n) = O(n). (A CC növelése N(C)N(C)-t csak csökkenti, ezért nem keletkezik új, le nem fedett alapeset.)

Az alsó korlát Ω(n)\Omega(n): már a k=1k = 1 eset (a minimum megtalálása) is megköveteli, hogy minden más elem legalább egyszer veszítsen egy összehasonlítást, ami legalább n−1n - 1 összehasonlítás; így a legrosszabb eset legalább lineáris. Tehát a determinisztikus kiválasztás futásideje Θ(n)\Theta(n).

A median-of-medians algoritmus elméleti jelentőségű: garantálja a lineáris legrosszabb futásidőt, de a konstans tényezője viszonylag nagy (a mediánok kiválasztása és a csoportrendezés plusz munkát jelent; a pontos arány implementációfüggő, saját méréssel – lásd a labort – határozd meg), ezért a gyakorlatban ritkán használják; a könyvtári megoldások (pl. introselect) csak végső tartalékként alkalmazzák. A beépített rendezések és a quickselect szinte mindig elegendőek.

13.3.4 Mediánok és alkalmazások

A medián a statisztikában az adatok középpontját jellemzi, és ellenálló a kiugró értékekkel szemben, ellentétben az átlaggal. A kiválasztási algoritmusokkal a medián megtalálása lineáris időben lehetséges. Páratlan nn-re a medián a ((n+1)/2)((n+1)/2)-edik legkisebb elem. Páros nn-re az alsó medián az n/2n/2-edik, a felső medián az n/2+1n/2+1-edik elem. Ha numerikus adatokról van szó, a mediánt gyakran a két középső elem átlagaként definiálják; ehhez mindkét elemet meg kell találni. Ez két kiválasztási hívással O(n)O(n) időben megoldható.

Néhány alkalmazás: - Kvantilisek, percentilisek: a kk-adik legkisebb elem általánosítja a mediánt; a qq-kvantilis (0<q≤10 < q \le 1) a k=⌈qn⌉k = \lceil q n \rceil-edik legkisebb elem; q=0q = 0 esetén a minimum (k=1k = 1). - Kiegyensúlyozott quicksort: ha a gyorsrendezés pivotját mediánnak választjuk, a particionálás mindig kettéosztja a tömböt, garantálva az O(nlog⁡n)O(n \log n) futásidőt. A gyakorlatban a medián-of-3 trükk közelíti ezt. - Robusztus statisztikák: a medián használata a kiugró értékek kiszűrésére. - Online medián: adatfolyamok esetén a medián fenntartása két kupaccal (max-kupac a kisebb felére, min-kupac a nagyobb felére) O(log⁡n)O(\log n) műveletenkénti frissítéssel lehetséges. - Térbeli adatok: a medián alapú particionálás kiegyensúlyozott osztást ad, ami a kd-fák és hasonló struktúrák építésénél hasznos.

13.3.5 Tipikus hibák és gyakorlati tanácsok

  1. Indexelési hibák: A kk paraméter gyakran 1-től indexelt, míg sok programozási nyelvben a tömbök 0-tól. A kódban egyértelműen dokumentálni kell a konvenciót. Ha relatív kk-t használunk, a rekurzióban a jobb oldali híváskor k−(gt−bal+1)k - (gt - bal + 1) értéket kell átadni, ahol gtgt az egyenlő blokk utolsó (abszolút) indexe, nem kk-t.

  2. Csak rendezés használata: Bár a rendezés; return A[k] egyszerű, O(nlog⁡n)O(n \log n) időt vesz igénybe. Ha a kiválasztás gyakori művelet, a lineáris kiválasztás jobb választás. Ráadásul a rendezés módosítja a tömböt, ami nem mindig megengedett.

  3. Rossz pivotválasztás: Ha a quickselect mindig az első vagy utolsó elemet választja pivotnak, rendezett bemenet esetén O(n2)O(n^2) lesz. Véletlen pivot használata ezt elkerüli. A véletlen generátort seed-elni kell a reprodukálhatósághoz.

  4. Duplikátumok kezelése: A kétutas Lomuto-partíció sok egyenlő elem esetén kiegyensúlyozatlan: azonos kulcsok mellett a pivot a szélére kerül, és a rekurzió mérete csak eggyel csökken, ami Θ(n2)\Theta(n^2)-es futásidőt ad. Ezért a fejezet kiválasztó algoritmusai háromutas PARTITION3-at használnak, amely az egyenlő elemeket egy blokkba gyűjti, és ha kk ebbe esik, azonnal leáll. A PARTITION3-ban az összehasonlítások szigorúak (< és >), az egyenlőség a középső blokkba vezet; a < és <= összekeverése a blokkok helyességét rontja.

  5. Rekurzió mélység: A quickselect rekurziója a legrosszabb esetben nn mélységű lehet, ami verem túlcsordulást okoz. Mivel a quickselect farokrekurzív (csak egy részre hív), a rekurzió közvetlenül ciklussá alakítható (while bal < jobb: … bal, jobb = …), így a járulékos memória O(1)O(1). (A „kisebb részre rekurzálj” fogás a quicksortnál kell, ahol mindkét rész feldolgozandó.) A median-of-medians rekurziója két ágat tartalmaz, de mélysége O(log⁡n)O(\log n).

  6. Median-of-medians hibás csoportosítása: Az egykörös indukciós bizonyítás a csoportméret megválasztásán múlik. Ötelemű csoportoknál a mediánok rekurziója n/5n/5 méretű, a maradó szigorú oldal legfeljebb 7n/10+67n/10 + 6, és 1/5+7/10=9/10<11/5 + 7/10 = 9/10 < 1, ezért a T(n)≤T(n/5)+T(7n/10+6)+O(n)T(n) \le T(n/5) + T(7n/10 + 6) + O(n) rekurrenciából az O(n)O(n) korlát egykörös indukcióval kijön. Háromelemű csoportoknál a megfelelő arányok 1/31/3 és 2/32/3, összegük 11, így ebből az egykörös becslésből nem adódik 11-nél szigorúan kisebb tényező; a T(n)≤T(n/3)+T(2n/3+O(1))+O(n)T(n) \le T(n/3) + T(2n/3 + O(1)) + O(n) rekurrencia ezzel a közvetlen érveléssel csak O(nlog⁡n)O(n \log n) felső korlátot ad. A háromelemű csoport javított vagy ismételt változata külön elemzést igényel, ezért a fejezet az ötelemű csoportot használja. A maradék csoport méretét helyesen kell kezelni, és a mediánok tömbjének indexelése (1-től) a rekurzív hívásban fontos.

  7. Üres vagy érvénytelen kk: A függvénynek ellenőriznie kell, hogy 1≤k≤n1 \le k \le n. Ha kk kívül esik, hibát kell dobni. Az üres tömb esete is kezelendő.

13.3.6 Laborfeladat és mérési terv

A labor célja a quickselect és a median-of-medians implementálása, tesztelése és összehasonlítása. A feladatot reprodukálható jegyzetfüzetben vagy kódprojektben kell elkészíteni, rögzített inputokkal, tesztekkel és mérési naplóval.

13.3.6.1 Implementáció

  • Készítsük el a quickselect függvényt véletlen pivotválasztással. A véletlen generátor seed-jét paraméterként adjuk át.
  • Készítsük el a median_of_medians függvényt a fenti pszeudokód alapján. A particionálás háromutas PARTITION3 legyen, és az egyenlő blokkra ne hívjunk rekurzívan. A kódban a rekurzív hívás a mediánok tömbjére történik; figyeljünk az indexelésre.
  • Mindkét függvény kapja meg a tömböt, a bal-t, jobb-ot és a globális k-t. (Vagy implementálhatunk iteratív változatot is.)

13.3.6.2 Tesztesetek

A tesztek terjedjenek ki legalább az alábbiakra: - üres tömb: hibát dob; - egyelemű tömb: a k=1k=1-re visszaadja az egyetlen elemet; - kételemű tömb: mindkét kk-ra helyes; - rendezett tömb; - fordítva rendezett tömb; - véletlen tömb (seed rögzített); - minden elem egyenlő (sok duplikátum): a háromutas partíciónak egy lépésben le kell zárnia, k=1k=1 és k=nk=n mellett is; - kétféle kulcs: például n−1n-1 darab azonos és 1 eltérő elem, k=1k=1 és k=nk=n; - vegyes, sok duplikátummal; - szélső kk esetek: k=1k=1 (minimum) és k=nk=n (maximum).

Minden esetben ellenőrizzük, hogy a kapott eredmény megegyezik-e a rendezett tömb kk-adik elemével. A teszteket automatizáljuk: például 1000 véletlen teszt futtatása különböző méretekkel és kk-val. Az azonos és a kétféle kulcsú esetek külön ellenőrzik, hogy a háromutas particionálás nem esik vissza a kétutas viselkedésbe; a kétutas Lomuto-változat ezeken a bemeneteken Θ(n2)\Theta(n^2) lenne, ezért a teszt futásidejére is figyelni kell.

13.3.6.3 Mérési napló

  • Rögzítsük a környezetet: nyelv (pl. Python 3.12), operációs rendszer, CPU, memória, fordító/interpretátor verzió, optimalizációs szint (ha van).
  • A méréshez generáljunk bemeneteket különböző méretekkel: n=102,103,104,105,106n = 10^2, 10^3, 10^4, 10^5, 10^6 (a géptől függően).
  • Minden méretre és minden inputtípusra futtassuk le az algoritmust legalább 10-szer, rögzített seed-del, és számoljunk átlagot és szórást.
  • Hasonlítsuk össze a quickselect, a median-of-medians és a beépített sorted() + indexelés megoldását. A mért és az elméleti várt eredményt (lineáris vs. O(nlog⁡n)O(n \log n)) külön táblázatban közöljük.
  • A futásidőket log–log skálán ábrázoljuk. A várt kép: a quickselect és a median-of-medians görbéje közel 1 meredekségű egyenes, a median-of-medians a nagyobb konstans miatt feljebb tolva; a sorted() görbéjének meredeksége nagy nn-re 1-nél kissé nagyobb. A mért meredekséget illesztéssel határozzuk meg, és a várttól külön közöljük.
